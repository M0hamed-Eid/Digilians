SLIDES 1–3

1. From CNNs to Transformers in Vision

The Timeline: Why Would Anyone Try Putting a Text Model on Images?

📋 Original Slide Content

Slide 1 — Computer Vision's Dominating Architecture Timeline:

  • 1989 — Convolutional Neural Networks (CNNs) become the dominant architecture for vision.
  • 2017 — Transformers introduced (originally for NLP / sequence tasks).
  • 2020 — Vision Transformers (ViT) bring the Transformer architecture into computer vision.
  • Later — models such as CLIP and DINOv2 build on the Transformer-for-vision idea.

Slides 2–3 — The Paper: "An Image Is Worth 16×16 Words: Transformers For Image Recognition At Scale" — Alexey Dosovitskiy, Lucas Beyer, Alexander Kolesnikov, Dirk Weissenborn, Xiaohua Zhai, Thomas Unterthiner, Mostafa Dehghani, Matthias Minderer, Georg Heigold, Sylvain Gelly, Jakob Uszkoreit, Neil Houlsby — Google Research, Brain Team.

🇬🇧 English Explanation
ENGLISH EXPLANATION

This lecture opens with a timeline of "dominating architectures" in computer vision, because ViT is best understood as a challenger that dethroned a 30-year incumbent.


🟦 1989 — Convolutional Neural Networks (CNNs): LeCun's early CNNs (and later AlexNet in 2012, ResNet in 2015) became the default backbone for essentially every vision task — classification, detection, segmentation — for nearly three decades.

🟩 2017 — Transformers: Vaswani et al.'s "Attention Is All You Need" introduced the Transformer for language. It used self-attention instead of recurrence, and it exploded in popularity for NLP (this is exactly the encoder architecture covered in Lectures 18–19).

🟪 2020 — Vision Transformer (ViT): Dosovitskiy et al. asked: "Transformers work incredibly well for sequences of words — can we make an image look like a sequence of words?" The answer became ViT.

🟧 After ViT — CLIP, DINOv2, etc.: Once ViT proved Transformers could match/beat CNNs on images, an entire new generation of vision models built on top of the ViT backbone.

Why try this at all? By 2020, Transformers had already replaced RNNs/LSTMs across almost all of NLP because self-attention lets every token look directly at every other token, capturing long-range relationships that convolution (which only looks at a small local neighborhood at a time) struggles with. Researchers wanted that same global, flexible reasoning for images — but images are not naturally a sequence of discrete tokens the way sentences are. That mismatch is exactly the problem the next section digs into.


The paper title itself: "An Image Is Worth 16×16 Words" is a pun on the old idiom "a picture is worth a thousand words." The literal technical meaning is that the authors cut an image into small 16×16-pixel patches and treat each patch the way NLP treats a word — as one input token.

⚠️ Common Misconception

ViT did not throw away CNNs and "invent" attention. It reused the exact standard Transformer encoder from NLP almost unchanged — the innovation is entirely in how the image is turned into a sequence before it ever reaches that encoder.

💡 Analogy — Reusing a Toolbox in a New Room

Imagine the Transformer as a power tool built for carpentry (NLP / words). ViT's authors didn't redesign the tool — they figured out how to cut a completely different material (an image) into pieces shaped like the wood planks the tool was designed for (word-like tokens), so the same power tool could be reused as-is.

SLIDES 4–6

2. The Core Problem — Why You Can't Feed Raw Pixels to a Transformer

Quadratic Attention Cost: 512×512 Pixels Would Need a 262,144 × 262,144 Attention Matrix

📋 Original Slide Content
  • Using a Transformer as-is: In standard self-attention, each token attends to all other tokens.
  • Feeding an image to a Transformer directly: each pixel would attend to every other pixel.
  • A modest input sequence of pixels quickly becomes huge (slide shows an example around ~65K pixels producing a 65k × 65k attention matrix).
  • Concrete example: a 512×512 image = 262,144 pixels → a 262,144 × 262,144 attention matrix.
  • Quadratic dependency on sequence length — handling images as raw pixel sequences results in far too long sequence lengths to be computationally feasible.
🇬🇧 English Explanation
ENGLISH EXPLANATION

To understand why ViT needed a clever trick, you first need to understand why the "obvious" approach fails.


How Self-Attention Normally Works (Text)

In a standard Transformer, every token in the input sequence computes an attention score against every other token. For a sentence of length n (say, 50–500 words), this means computing an n × n attention matrix. For text, n is small — a paragraph might be a few hundred tokens — so this is cheap.

The "Obvious" (Broken) Idea for Images

What if we just treat every single pixel as one token, exactly like a word? Then self-attention would let every pixel attend to every other pixel — theoretically giving the model perfect, unrestricted global reasoning about the whole image.

The problem is the numbers. A modest 512×512 image has:

512 × 512 = 262,144 pixels (the sequence length n)

Self-attention cost scales quadratically with sequence length — it needs an n × n attention matrix, and the compute/memory cost of computing it scales as O(n²):

Attention matrix size = n × n = 262,144 × 262,144 ≈ 6.87 × 10¹⁰ entries

That's roughly 69 billion attention-score entries for just one 512×512 image, at just one attention layer. Real Transformers stack many attention layers and process batches of many images — this is computationally infeasible on any realistic hardware, and it only gets worse as image resolution grows (double the resolution → quadruple the pixels → the attention matrix grows by 16×).


Why does text avoid this? Language is naturally "chunked" into words/subwords — a whole paragraph might be only a few hundred tokens. Images have no such natural chunking: a raw image is just a dense grid of individual pixel values with no obvious way to group them into a short sequence — unless you invent one, which is exactly what ViT does in the next section.

🚫 Key Takeaway

The bottleneck is sequence length, not "images are hard" in some vague sense. If you can shrink the sequence length dramatically (fewer, larger tokens) while still covering the whole image, self-attention becomes tractable again — that's the entire motivation for patches.

لنفهم سبب حاجة ViT لحل ذكي، يجب أولًا أن نفهم لماذا تفشل الفكرة "المباشرة".


كيف يعمل self-attention عادةً في النصوص؟

في الـ Transformer العادي، كل token يحسب درجة attention مع كل token آخر في الجملة. بالنسبة للنص، طول الـ sequence عادةً صغير (فقرة قد تكون مئات الكلمات فقط)، فالتكلفة الحسابية معقولة.


الفكرة "البديهية" (والفاشلة) للصور:

ماذا لو عاملنا كل بكسل على أنه token واحد، تمامًا مثل الكلمة؟ نظريًا سيسمح ذلك لكل بكسل أن "ينظر" لكل بكسل آخر في الصورة.


المشكلة في الأرقام: صورة متواضعة بحجم 512×512 تحتوي على:

512 × 512 = 262,144 بكسل (طول الـ sequence)

تكلفة self-attention تتناسب تربيعيًا (quadratic) مع طول الـ sequence — تحتاج إلى مصفوفة attention بحجم n × n، أي حوالي 262,144 × 262,144 ≈ 69 مليار خلية! وهذا لصورة واحدة فقط ولطبقة attention واحدة فقط. هذا غير قابل للتنفيذ حسابيًا على أي جهاز حقيقي.


لماذا لا تواجه اللغة هذه المشكلة؟ اللغة مقسّمة طبيعيًا إلى كلمات — فقرة كاملة قد تكون بضع مئات من الـ tokens فقط. الصورة ليس لها تقسيم طبيعي مشابه — هي فقط شبكة كثيفة من قيم البكسلات، إلا إذا اخترعنا طريقة لتقسيمها لـ sequence قصيرة، وهذا بالضبط ما يفعله ViT في القسم التالي.


المصطلحات المهمة:

  • Self-Attention — كل token يحسب درجة ارتباطه بكل token آخر
  • Sequence Length (طول التسلسل) — عدد الـ tokens في الإدخال
  • Quadratic Dependency (اعتماد تربيعي) — التكلفة تتضاعف بمعدل n²
  • Attention Matrix (مصفوفة الانتباه) — مصفوفة بحجم n×n تخزّن درجات الاهتمام بين كل زوج tokens

⚠️ Common Misconception

This is not primarily a memory-storage problem you could just buy more GPUs for — it's a fundamental algorithmic scaling problem. Even with unlimited memory, computing and passing gradients through a matrix with tens of billions of entries per image, per layer, is far too slow to be practical for training at scale.

Standard self-attention costs O(n²) in sequence length n. Treating every pixel as a token makes n huge (a 512×512 image = 262,144 pixels), producing an infeasible 262,144×262,144 attention matrix (~69 billion entries). This quadratic blow-up is why Transformers cannot be fed raw pixels directly.

SLIDES 7–10

3. The ViT Solution — Patches as "Words"

Cutting the Image into 16×16 Chunks and Flattening Each into an Embedding Vector

📋 Original Slide Content
  • How Vision Transformer Works: split the image into fixed-size patches (example shown: 224×224 image, patch size = 16×16).
  • Number of patches = (224 / 16) × (224 / 16) = 14 × 14 = 196 patches.
  • Each 16×16×3 (RGB) patch is flattened from 2D into a 1D vector.
  • Each flattened 1D vector is passed through a linear projection (Wx + b) into a lower-dimensional embedding.
  • These are exactly analogous to word embeddings in NLP — "an image is worth 16×16 words."
🇬🇧 English Explanation
ENGLISH EXPLANATION

ViT's core trick is beautifully simple: instead of feeding the Transformer 262,144 individual pixels, chop the image into a small number of larger chunks (patches), and feed the Transformer a short sequence of patches instead of a long sequence of pixels.


Step-by-step, using the slide's own example (a 224×224 image):

  1. Choose a patch size — the paper's headline choice is 16×16 pixels
  2. Slide a 16×16 window across the image with stride 16 (non-overlapping) to cut it into a grid of patches
  3. Number of patches = (224 / 16) × (224 / 16) = 14 × 14 = 196 patches
  4. Each patch is a small 16×16×3 image (16 pixels tall, 16 wide, 3 RGB color channels)
  5. Flatten each 2D (16×16×3) patch into a single 1D vector of length 16×16×3 = 768 numbers
  6. Linearly project that 768-number vector down (or up) to a fixed embedding dimension D using a learned weight matrix: Wx + b
  7. The result: 196 embedding vectors — one per patch — exactly like 196 "word embeddings" in an NLP sentence

The Patch Embedding Formula: for a general image of height H, width W, and C channels, split into patches of size P × P:

Number of patches: N = (H × W) / (P × P)
Each patch flattened size: P² · C  →  Linearly projected to embedding dimension D

Plugging in the slide's numbers: H = W = 224, P = 16, C = 3 → N = (224×224)/(16×16) = 196 patches, each flattened to 16²×3 = 768 values, then linearly projected to D (e.g. D = 768 in the ViT-Base model).


Why "an image is worth 16×16 words"? In NLP, a sentence is a sequence of word tokens, each converted to an embedding vector via a lookup table or linear layer. In ViT, an image becomes a sequence of patch tokens, each converted to an embedding vector via that same kind of linear projection. A 16×16 patch plays exactly the structural role that one word plays in a sentence.

🇸🇦 الشرح بالعربي

فكرة ViT الأساسية بسيطة وعبقرية: بدل تغذية الـ Transformer بـ 262,144 بكسل منفرد، نقوم بتقطيع الصورة إلى عدد قليل من القطع الكبيرة (patches)، ونعطي الـ Transformer sequence قصيرة من الـ patches بدل sequence طويلة من البكسلات.


خطوة بخطوة (باستخدام مثال الشريحة: صورة 224×224):

  1. نختار حجم الـ patch — الاختيار الأساسي في الورقة البحثية هو 16×16 بكسل
  2. نقطع الصورة لشبكة (grid) من الـ patches بدون تداخل
  3. عدد الـ patches = (224 / 16) × (224 / 16) = 14 × 14 = 196 patch
  4. كل patch هو صورة صغيرة بحجم 16×16×3 (16 بكسل ارتفاع، 16 عرض، 3 قنوات ألوان RGB)
  5. Flatten: تحويل كل patch ثنائي الأبعاد إلى vector أحادي الأبعاد طوله 16×16×3 = 768 رقم
  6. Linear Projection: نمرر هذا الـ vector عبر مصفوفة أوزان متعلّمة (Wx + b) لتحويله إلى embedding بحجم ثابت D
  7. النتيجة: 196 embedding vector، واحد لكل patch — تمامًا مثل 196 "word embedding" في جملة NLP

معادلة Patch Embedding: لصورة بارتفاع H وعرض W وعدد قنوات C، مقسّمة إلى patches بحجم P×P:

N = (H × W) / (P × P)

كل patch بعد الـ flatten حجمه P²·C، ثم يتم projection له إلى بُعد D عبر طبقة خطية (linear layer).


لماذا "الصورة تساوي 16×16 كلمة"؟ في NLP، الجملة عبارة عن sequence من tokens (كلمات)، كل واحدة تتحول إلى embedding. في ViT، الصورة تتحول لـ sequence من "patch tokens"، كل واحد يتحول إلى embedding بنفس الطريقة. الـ patch بحجم 16×16 يلعب نفس الدور البنيوي الذي تلعبه كلمة واحدة في جملة.


المصطلحات المهمة:

  • Patch (قطعة) — جزء صغير مقطوع من الصورة
  • Flatten (تسطيح) — تحويل مصفوفة 2D إلى vector 1D
  • Linear Projection (إسقاط خطي) — تحويل vector إلى بُعد آخر باستخدام Wx+b
  • Patch Embedding (تضمين القطعة) — الـ vector النهائي الذي يمثل الـ patch
  • Sequence Length (طول التسلسل) — هنا أصبح 196 بدل 262,144!
💡 Worked Example — From 262,144 Down to 196

Compare the two approaches on the exact same 224×224 image:

Raw Pixels (Broken)

  • Sequence length n = 224 × 224 = 50,176 pixels
  • Attention matrix ≈ 2.5 billion entries
  • Computationally infeasible

16×16 Patches (ViT)

  • Sequence length n = 196 patches
  • Attention matrix = 196 × 196 ≈ 38,416 entries
  • Easily tractable on a GPU

Grouping pixels into 16×16 patches shrinks the sequence length by a factor of 256 (16×16) — turning an impossible ~2.5 billion-entry attention problem into a trivial ~38K-entry one.

🧠 Memory Trick — Patch Pipeline

"Slice, Squash, Shrink"

Slice the image into 16×16 patches → Squash (flatten) each patch into a 1D vector → Shrink (linearly project) into a fixed embedding dimension D.

  • 📌 Know the formula N = (H×W)/(P×P) and flattened patch size P²·C
  • 📌 Be able to explain "flatten then linearly project" as the patch embedding step
  • 📌 Understand the "16×16 Words" title pun — each patch is the image equivalent of one word/token

ViT splits an image into fixed-size (e.g. 16×16) patches, giving N = (H×W)/(P×P) patches (196 for a 224×224 image with 16×16 patches). Each patch is flattened (P²·C values) and linearly projected into an embedding vector, treated exactly like a "word" token in NLP.

SLIDES 8–13

4. The Full ViT Architecture

Patch + Position Embedding → [CLS] Token → Standard Transformer Encoder → MLP Head

📋 Original Slide Content
  • Patch + Position Embedding: patch embeddings get an added positional embedding so the model knows patch order/location.
  • Extra learnable [class] embedding ("*") prepended to the sequence of patch embeddings.
  • The resulting sequence ("Embedded Patches") is fed into a Transformer Encoder, applied Nx times (stacked layers).
  • Inside each encoder layer: Multi-Head (Self) Attention, Feed-forward layer, Norm (Layer Normalization), with Add & Normalize residual connections.
  • Final output is passed through an MLP Head to produce class predictions.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Once the image has been turned into a short sequence of patch embeddings, the rest of ViT is almost identical to the standard NLP Transformer encoder you already studied in Lectures 18–19. Here is the complete pipeline:

Step 1 — Patch EmbeddingSplit image into patches → flatten → linearly project each into a D-dimensional vector (Section 3).
↓
Step 2 — Prepend [CLS] TokenAn extra learnable "[class]" embedding vector is added to the front of the sequence, exactly like BERT's [CLS] token in NLP. It doesn't correspond to any real patch — it exists purely to accumulate global information.
↓
Step 3 — Add Positional EmbeddingsBecause the Transformer encoder has no innate sense of order (self-attention treats the sequence as an unordered set), a learnable positional embedding is added to every token (including [CLS]) so the model knows which patch came from which grid location.
↓
Step 4 — Transformer Encoder (× N layers)The combined sequence — [CLS] + 196 patch tokens, each carrying position info — is fed through N stacked standard Transformer encoder blocks. Each block contains: Multi-Head Self-Attention → residual Add & Norm → Feed-Forward (MLP) layer → residual Add & Norm. This is the exact same encoder architecture from Lectures 18–19 — ViT does not modify it at all.
↓
Step 5 — MLP Classification HeadAfter N encoder layers, take only the final output vector corresponding to the [CLS] token (it has now "attended to" and absorbed information from every patch). Feed that single vector through a small MLP (classification head) to output class probabilities.

Why prepend a [CLS] token instead of, say, averaging all patch outputs? This design choice comes straight from BERT-style NLP models. Because self-attention lets [CLS] attend to (and be attended to by) every patch across every layer, by the final layer its representation has aggregated a learned, weighted summary of the entire image — a single vector suitable for classification.


Why add positional embeddings? Without them, shuffling the patches would produce an identical output — the model would have no way to tell "top-left patch" from "bottom-right patch." The paper found simple learnable 1D positional embeddings work about as well as more complex 2D-aware schemes.


Direct cross-reference to Lectures 18–19: if you already understand the standard Transformer encoder — multi-head self-attention, feed-forward sublayers, layer normalization, and residual ("Add & Norm") connections — you already understand 90% of ViT's architecture. ViT's only real additions are (1) the patch embedding front-end, (2) the [CLS] token, and (3) the MLP head at the very end.

🇸🇦 الشرح بالعربي

بعد تحويل الصورة إلى sequence قصيرة من patch embeddings، باقي بنية ViT مطابقة تقريبًا لـ Transformer encoder القياسي الذي درسناه في المحاضرتين 18 و19. إليك الـ pipeline الكامل:

  1. الخطوة 1 — Patch Embedding: تقسيم الصورة لـ patches → flatten → linear projection لكل واحد إلى vector بُعده D
  2. الخطوة 2 — إضافة [CLS] token: يُضاف embedding متعلّم إضافي في بداية الـ sequence، تمامًا مثل [CLS] في BERT. لا يمثل أي patch حقيقي — وظيفته فقط تجميع المعلومات العامة عن الصورة
  3. الخطوة 3 — إضافة Positional Embeddings: بما أن الـ Transformer لا يعرف الترتيب طبيعيًا (self-attention يعامل الـ sequence كمجموعة غير مرتبة)، نضيف positional embedding متعلّم لكل token (بما فيهم [CLS]) ليعرف النموذج مكان كل patch
  4. الخطوة 4 — Transformer Encoder (×N مرات): الـ sequence الكاملة (CLS + 196 patch) تمر عبر N طبقة من الـ encoder القياسي: Multi-Head Self-Attention → Add & Norm → Feed-Forward layer → Add & Norm. هذه نفس بنية الـ encoder من المحاضرتين 18 و19 بدون أي تعديل
  5. الخطوة 5 — MLP Classification Head: نأخذ فقط الـ output النهائي المقابل لـ [CLS] token، ونمرره عبر MLP صغير لإخراج تصنيف الصورة (class probabilities)

لماذا [CLS] token وليس مثلًا average لكل الـ patches؟ هذا الاختيار مأخوذ من نماذج BERT في NLP. بفضل self-attention، الـ [CLS] token "ينتبه" لكل الـ patches عبر كل الطبقات، فيتجمّع فيه في النهاية ملخص متعلّم لكل الصورة — vector واحد جاهز للتصنيف.


لماذا نحتاج positional embeddings؟ بدونها، لو بدّلنا ترتيب الـ patches سيكون الناتج مطابقًا! النموذج لن يعرف الفرق بين patch في أعلى اليسار وpatch في أسفل اليمين.


ربط مباشر بالمحاضرتين 18 و19: إذا كنت تفهم بنية الـ Transformer encoder القياسية (multi-head self-attention + feed-forward + layer normalization + residual connections)، فأنت تفهم تقريبًا 90% من بنية ViT. الإضافات الحقيقية الوحيدة في ViT هي: (1) طبقة patch embedding في البداية، (2) الـ [CLS] token، و(3) الـ MLP head في النهاية.


المصطلحات المهمة:

  • [CLS] Token — token متعلّم إضافي يُستخدم للتصنيف النهائي
  • Positional Embedding (تضمين الموضع) — يعطي النموذج معلومة عن ترتيب/موقع كل patch
  • Multi-Head Self-Attention — عدة "رؤوس" attention تعمل بالتوازي
  • Feed-Forward Layer — طبقة كثيفة (dense) بعد الـ attention في كل طبقة encoder
  • Add & Norm (Residual + Layer Norm) — اتصال residual مع تطبيع الطبقة
  • MLP Head — الطبقة النهائية التي تُخرج التصنيف
💡 Practical Example — Classifying a Photo of a Dog
  1. Take a 224×224 photo of a dog → split into 196 patches of 16×16 pixels each
  2. Flatten and linearly project each patch → 196 patch embedding vectors
  3. Prepend one learnable [CLS] embedding → sequence length becomes 197
  4. Add learnable positional embeddings to all 197 tokens
  5. Pass the 197-token sequence through N Transformer encoder layers (self-attention lets patches showing "ear," "tail," "fur texture" inform each other)
  6. Take the final [CLS] output vector → feed into MLP head → output: "Dog" (98% confidence)
⚠️ Common Misconception

Students often think ViT has some special "vision attention" mechanism. It does not — the Multi-Head Self-Attention, Feed-Forward sublayers, and Add & Norm residual connections in ViT's encoder are the exact same mechanisms from the general-purpose Transformer encoder used for text. ViT is a demonstration that the encoder itself is modality-agnostic once the input is tokenized correctly.

  • 📌 The [CLS] token's final-layer output (not an average of patches) feeds the classification head
  • 📌 Positional embeddings are necessary because self-attention is permutation-invariant without them
  • 📌 ViT's Transformer encoder = the same encoder block from Lectures 18–19 (MHSA + FFN + LayerNorm + residuals), unmodified

ViT pipeline: patches → embeddings → prepend learnable [CLS] token → add learnable positional embeddings → feed through N stacked standard Transformer encoder layers (multi-head self-attention + feed-forward + Add & Norm, identical to Lectures 18–19) → take the final [CLS] output → MLP head produces the class prediction.

5. Why ViT Needs Big Data

Inductive Bias: What CNNs Get "for Free" and ViT Must Learn from Scratch

📋 Original Slide Content
  • Inductive Bias: "high inductive bias" gives the model built-in guidance about the structure of the data.
  • Transformer's self-attention: each token can attend to any token in every layer → "much less guidance" baked in — i.e. much lower / weaker inductive bias than a CNN.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Inductive bias refers to the built-in assumptions an architecture bakes into its design about the kind of patterns it expects to find in the data. More inductive bias = the model needs less data to learn well, because the architecture already "knows" some of the right structure; less inductive bias = the model is more flexible and general, but must learn everything — including basic structural patterns — purely from examples.


CNNs Have Strong, Built-In Inductive Biases
  • Locality: a convolution filter only looks at a small local neighborhood of pixels at a time — baking in the assumption "nearby pixels are related"
  • Translation equivariance: the same filter slides across the whole image, so a pattern (e.g. an edge or eye) is detected the same way no matter where it appears in the image
  • These priors match how natural images actually work — features are usually local and shift around the image — so CNNs learn efficiently even from modest-sized datasets
ViT Has Very Weak Inductive Bias

In self-attention, every patch token can attend to every other patch token in every layer, regardless of spatial distance. There is no built-in notion that nearby patches matter more than far-away ones, and no automatic sharing of "the same detector everywhere." The model has to discover locality- and translation-like patterns entirely from data if they turn out to be useful — "much less guidance" is baked in, exactly as the slide states.


The consequence — small data vs. big data:

CNN

  • Strong priors: locality + translation equivariance
  • Data-efficient — good even on small/medium datasets (e.g. ImageNet-1K ~1.3M images)
  • Performance plateaus at very large scale — priors that used to help can start to limit flexibility

ViT

  • Few built-in priors — must learn spatial structure purely from data
  • Underperforms CNNs when trained on small/medium datasets
  • Needs pretraining on massive datasets (e.g. ImageNet-21k ~14M images, or JFT-300M ~300M images) to learn what CNNs get "for free"
  • Once pretrained at that scale, matches or surpasses CNNs (e.g. ResNet) on downstream benchmarks, and scales further with more data/compute than CNNs typically do

This is the paper's central empirical finding: ViT trained on ImageNet alone (~1.3M images) underperforms comparable CNNs, but ViT pretrained on JFT-300M and then fine-tuned matches or beats state-of-the-art CNNs on tasks like ImageNet classification.

🇸🇦 الشرح بالعربي

الـ Inductive Bias تعني الافتراضات المدمجة داخل تصميم الـ architecture حول نوع الأنماط التي يتوقع إيجادها في البيانات. كلما زاد الـ inductive bias، احتاج النموذج بيانات أقل ليتعلم جيدًا لأن البنية "تعرف" مسبقًا بعض البنية الصحيحة. كلما قلّ، أصبح النموذج أكثر مرونة وعمومية، لكنه يحتاج تعلّم كل شيء — حتى الأنماط الأساسية — من الأمثلة فقط.


CNN لديها inductive bias قوي:

  • Locality (المحلية): الـ filter في الـ convolution ينظر فقط لمنطقة صغيرة مجاورة من البكسلات، أي أن البنية "تفترض" أن البكسلات القريبة مرتبطة
  • Translation Equivariance (ثبات الانتقال): نفس الـ filter ينزلق على كل الصورة، فيُكتشف نفس النمط (حافة، عين...) بنفس الطريقة أينما ظهر في الصورة

ViT لديه inductive bias ضعيف جدًا:

في self-attention، كل patch token يمكنه الانتباه لكل patch آخر في كل طبقة، بدون أي افتراض مسبق أن الـ patches القريبة أهم. النموذج يجب أن يتعلم أنماط شبيهة بالـ locality والـ translation equivariance بنفسه من البيانات — "توجيه أقل بكثير" كما تقول الشريحة.


النتيجة — بيانات قليلة vs. بيانات ضخمة:

  • CNN: كفاءة عالية مع بيانات محدودة، لكن أداءها قد "يتوقف عن التحسّن" مع بيانات ضخمة جدًا
  • ViT: أداء أضعف من CNN على بيانات صغيرة/متوسطة، لكنه يحتاج فقط pretraining على بيانات ضخمة جدًا (مثل JFT-300M بحجم 300 مليون صورة، أو ImageNet-21k) ليتفوّق على CNN أو يعادلها

المصطلحات المهمة:

  • Inductive Bias (الانحياز الاستقرائي) — افتراضات مدمجة في تصميم النموذج
  • Locality (المحلية) — التركيز على منطقة صغيرة مجاورة
  • Translation Equivariance (ثبات الانتقال) — اكتشاف النمط بنفس الطريقة في أي موضع
  • JFT-300M / ImageNet-21k — مجموعات بيانات ضخمة استُخدمت في pretraining ViT
💡 Analogy — The Tourist vs. The Local Guide

A CNN is like a local tour guide who already knows the city's layout (locality + translation equivariance) — they can navigate a small town efficiently with little extra information. ViT is like a brilliant but "blank slate" analyst dropped into a city with no map — given enough time and data exploring many different cities (massive pretraining datasets), they eventually build a deeper, more flexible, and ultimately more powerful mental model than the local guide, but they need a LOT of exploration first.

🚫 Common Mistakes
  • ❌ Thinking ViT is "always better" than CNNs — it only wins when pretrained on very large-scale data
  • ❌ Confusing "inductive bias" with "accuracy" — a strong inductive bias means data-efficiency, not necessarily a higher performance ceiling
  • ❌ Forgetting that on small datasets from scratch, ViT typically underperforms a comparable CNN like ResNet

  • 📌 Know why ViT's self-attention has weak inductive bias: every token attends to every token in every layer, with no spatial prior
  • 📌 Know the two large pretraining datasets named in ViT research: JFT-300M, ImageNet-21k
  • 📌 Common exam Q: "Why does ViT need more data than a CNN to reach good performance?" → it lacks built-in locality/translation priors, so it must learn spatial structure purely from data

CNNs have strong inductive bias (locality, translation equivariance) → data-efficient, strong on small/medium datasets. ViT has weak inductive bias — every patch attends to every other patch with no spatial prior — so it needs massive pretraining data (JFT-300M, ImageNet-21k) but then matches or surpasses CNNs and scales further.

SLIDE 15

6. What Came Next — CLIP & DINOv2

ViT as a Backbone for the Next Generation of Vision Models

📋 Original Slide Content
  • The timeline slide (Section 1) placed CLIP and DINOv2 after ViT (2020) on the computer vision architecture timeline, as the next dominant approaches building on the Transformer-for-vision idea.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Once ViT proved that a plain Transformer encoder could match/beat CNNs on images given enough pretraining data, it quickly became the new default backbone that later, more specialized vision models were built on top of.


CLIP — Contrastive Language-Image Pretraining (OpenAI)

Trains a ViT (or CNN) image encoder jointly with a text encoder on ~400 million image-text pairs scraped from the internet, pulling matching image/text embeddings close together in a shared embedding space and pushing non-matching pairs apart (contrastive learning). This is exactly the mechanism behind the Zero-Shot Learning concept introduced back in Lecture 10 — at inference time, you can classify an image against any set of text class-name descriptions it was never explicitly trained on, because the shared embedding space already generalizes.

DINOv2 — Self-Supervised Vision Transformer Features (Meta AI)

Trains a ViT backbone with no labels at all (self-supervised learning), using techniques where the model learns to produce consistent representations of the same image under different augmentations/views. The resulting patch and [CLS] embeddings turn out to be extremely strong general-purpose visual features, reusable for classification, segmentation, depth estimation, and more — without task-specific fine-tuning in many cases.


The big-picture takeaway: ViT's real legacy isn't just "a slightly better classifier" — it's that it unlocked a whole family of foundation-model-style vision architectures (CLIP, DINOv2, and many others) that reuse the same patch-embedding + Transformer-encoder recipe, changing only the training objective (contrastive text-image matching for CLIP, self-supervised consistency for DINOv2) rather than the underlying architecture.

🇸🇦 الشرح بالعربي

بعد أن أثبت ViT أن الـ Transformer encoder العادي يمكن أن يعادل أو يتفوّق على CNN في الصور (بشرط بيانات pretraining كافية)، أصبح سريعًا الـ backbone الافتراضي الذي بُنيت فوقه نماذج vision أحدث وأكثر تخصصًا.


CLIP — Contrastive Language-Image Pretraining (من OpenAI):

يدرّب ViT (أو CNN) كـ image encoder بالتوازي مع text encoder على حوالي 400 مليون زوج (صورة-نص) من الإنترنت، بحيث يقترب embedding الصورة من embedding النص المطابق له في فضاء مشترك، ويبتعد عن النصوص غير المطابقة (contrastive learning). هذه هي الآلية الحقيقية وراء Zero-Shot Learning التي درسناها في المحاضرة 10 — يمكن تصنيف صورة مقابل أي وصف نصي جديد لم يرَه النموذج أثناء التدريب.


DINOv2 — تعلّم ذاتي الإشراف لميزات ViT (من Meta AI):

يدرّب ViT بدون أي تسميات (labels) على الإطلاق (self-supervised learning)، عبر تعليم النموذج أن يُنتج تمثيلات متسقة لنفس الصورة تحت تحويلات/زوايا مختلفة. الـ embeddings الناتجة تكون ميزات بصرية قوية جدًا وعامة، قابلة لإعادة الاستخدام في التصنيف والتجزئة وتقدير العمق بدون الحاجة لتدريب إضافي في كثير من الحالات.


الخلاصة الكبرى: إرث ViT الحقيقي ليس فقط "مصنّف أفضل بقليل" — بل أنه فتح الباب لعائلة كاملة من نماذج vision الأساسية (foundation models) مثل CLIP وDINOv2، والتي تعيد استخدام نفس تركيبة patch-embedding + Transformer-encoder، وتغيّر فقط هدف التدريب.


المصطلحات المهمة:

  • CLIP — تدريب مشترك لنص وصورة باستخدام contrastive learning
  • DINOv2 — تدريب ViT ذاتي الإشراف بدون تسميات
  • Zero-Shot Learning — تصنيف فئات لم يرها النموذج أثناء التدريب (رُبطت بمحاضرة 10)
  • Foundation Model (نموذج أساسي) — نموذج ضخم مُدرّب مسبقًا يُعاد استخدامه لمهام متعددة
💡 Practical Example — Zero-Shot Classification with CLIP

Give CLIP a photo of a platypus and a list of text prompts it was never fine-tuned on: "a photo of a cat", "a photo of a platypus", "a photo of a car". CLIP's ViT image encoder embeds the photo, its text encoder embeds each prompt, and CLIP simply picks whichever text embedding is closest (highest cosine similarity) to the image embedding — correctly picking "a photo of a platypus" purely from the shared embedding space learned during contrastive pretraining, with zero platypus-specific training examples.

🎓 Exam Notes
  • 📌 CLIP = contrastive image-text pretraining, enables zero-shot classification (links back to Lecture 10)
  • 📌 DINOv2 = self-supervised ViT feature learning, no labels required
  • 📌 Both reuse the ViT patch-embedding + Transformer-encoder backbone, differing only in training objective
  • 📌 Know the timeline placement: CNN (1989) → Transformer (2017) → ViT (2020) → CLIP / DINOv2 (later)

ViT became the default backbone for later vision models. CLIP pairs a ViT image encoder with a text encoder via contrastive learning on ~400M image-text pairs, enabling zero-shot classification. DINOv2 trains a ViT backbone with self-supervised learning (no labels), producing strong general-purpose visual features.

Answer: Standard self-attention requires every token in a sequence to compute an attention score against every other token, producing an n × n attention matrix whose compute/memory cost scales as O(n²) in sequence length n. If each pixel is treated as one token, n equals the total pixel count. A modest 512×512 image already has n = 262,144 pixels, producing a 262,144 × 262,144 attention matrix (~69 billion entries) for a single image at a single attention layer. Real models stack many layers and process many images per batch, so this cost is far beyond what any realistic hardware can compute — unlike text, where a paragraph might be only a few hundred tokens, images have no natural short "tokenization," so raw-pixel attention is a non-starter.

Answer: An image of height H, width W, and C channels is split into non-overlapping patches of size P × P. The number of patches is N = (H × W) / (P × P) — e.g. for a 224×224 image with P=16, N = (224×224)/(16×16) = 196.
