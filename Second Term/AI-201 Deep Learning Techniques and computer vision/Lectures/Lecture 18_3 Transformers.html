1. Sequence-to-Sequence (Seq2Seq) Framing

The Generic Problem That Transformers Were Built to Solve

📋 Original Slide Content

Slide 1 — Title: "Transformers" — Abu Bakr Soliman.


Slide 2 — Sequence to Sequence (Seq2Seq):

  • Input: x1, x2, .. xn
  • Output: y1, y2, .. yn
  • A generic box/model transforms one sequence into another sequence.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Sequence-to-Sequence (Seq2Seq) is the general name for any machine learning task where the model reads in an ordered sequence of inputs (x1, x2, ..., xn) and produces an ordered sequence of outputs (y1, y2, ..., yn). The lengths of the input and output sequences don't have to match — that's exactly the point.


This is a deliberately abstract framing. It does not say how the transformation happens — only that "a sequence goes in, a sequence comes out." Every model we study in this lecture (RNN, and later the Transformer) is really just a different way of implementing this same Seq2Seq box.

Model( x₁, x₂, ..., xₙ ) → y₁, y₂, ..., yₘ

Classic Seq2Seq tasks:

  • 🌍 Machine Translation: English sentence in → Arabic sentence out (different lengths, different vocabularies)
  • 📝 Summarization: A long article in → a short summary out (n words in, m words out, m < n)
  • 🗣️ Speech Recognition: audio waveform sequence in → text transcript sequence out
  • 💬 Chatbots / Question Answering: a question sequence in → an answer sequence out

Why does this framing matter for Transformers? Because everything that follows in this lecture — RNNs, embeddings, self-attention — exists purely to answer one engineering question: "What is the best way to build the box in the middle of this diagram?"

أمثلة كلاسيكية على مهام Seq2Seq:

2. Recurrent Neural Networks (RNN) — Recap

The First Popular Answer to "How Do We Build the Seq2Seq Box?"

📋 Original Slide Content
  • Diagram: State 0 → RNN → RNN → ... → RNN (one RNN cell per time-step)
  • Inputs x1, x2, .. xn fed one at a time, in order (Time-Step axis)
  • Outputs y1, y2, .. yn produced alongside each time-step
  • Each RNN cell passes a "state" forward to the next time-step
🇬🇧 English Explanation
ENGLISH EXPLANATION

A Recurrent Neural Network (RNN) is one of the earliest and most natural ways to build a Seq2Seq box. Instead of looking at the whole input sequence at once, an RNN reads it one element at a time, in strict order, and carries forward a running memory called the hidden state.


How it works step by step:

  1. Start with an initial hidden state, State 0 (usually all zeros)
  2. At time-step 1: feed x1 and State 0 into the RNN cell → it produces output y1 and a new hidden state, State 1
  3. At time-step 2: feed x2 and State 1 into the (same) RNN cell → produces y2 and State 2
  4. Repeat for every time-step until xn is processed, carrying the hidden state forward each time

The crucial idea: it is the exact same RNN cell (same weights) reused at every time-step — only the hidden state changes. That hidden state is the RNN's only way of "remembering" everything it has seen so far in the sequence.

Each cell above takes (previous hidden state + current xᵢ) as input, and produces (yᵢ + next hidden state). This is called "unrolling" the RNN across time-steps.


Why RNNs made sense for language: language is inherently sequential — word order changes meaning ("dog bites man" ≠ "man bites dog"). Processing tokens one-by-one, carrying context forward, mirrors how we read a sentence left to right.

الشبكة العصبية التكرارية (Recurrent Neural Network - RNN) هي واحدة من أقدم الطرق وأكثرها منطقية لبناء صندوق Seq2Seq. بدلاً من النظر إلى كل الـ input sequence دفعة واحدة، تقرأ RNN عنصرًا واحدًا في كل مرة، بترتيب صارم، وتحمل معها ذاكرة مستمرة تُسمى الحالة الخفية (hidden state).


كيف تعمل خطوة بخطوة:

  1. نبدأ بحالة أولية State 0 (عادة كل قيمها أصفار)
  2. في الخطوة الزمنية الأولى: نُدخل x1 مع State 0 إلى خلية RNN → تُخرج y1 وحالة جديدة State 1
  3. في الخطوة الثانية: نُدخل x2 مع State 1 → تُخرج y2 وState 2
  4. نُكرر هذا لكل خطوة زمنية حتى نهاية الـ sequence، مع تمرير الحالة الخفية في كل مرة

الفكرة الأهم: نفس خلية RNN (نفس الـ weights) تُستخدم في كل خطوة زمنية — فقط الحالة الخفية تتغير. هذه الحالة هي الطريقة الوحيدة التي تتذكر بها الشبكة كل ما رأته من قبل في الـ sequence.


لماذا كانت RNN منطقية للغة؟ اللغة تسلسلية بطبيعتها — ترتيب الكلمات يُغيّر المعنى. معالجة الرموز واحدًا تلو الآخر، مع تمرير السياق، تُحاكي طريقة قراءتنا للجملة من اليسار لليمين.


المصطلحات:

  • Recurrent Neural Network (شبكة عصبية تكرارية) — model يعالج sequence خطوة بخطوة
  • Hidden State (الحالة الخفية) — الذاكرة التي تُمرَّر بين الخطوات الزمنية
  • Time-Step (الخطوة الزمنية) — لحظة معالجة عنصر واحد من الـ sequence
  • Unrolling (فَك الطي) — رسم نفس الخلية مُكررة عبر الزمن لتوضيح تسلسل العمليات
💡 Example — Reading "I can go alone" word by word
  1. State0=[0,0,0] , x1="I" → RNN → y1, State1
  2. State1 , x2="can" → RNN → y2, State2 (State2 now "remembers" that "I" came before "can")
  3. State2 , x3="go" → RNN → y3, State3
  4. State3 , x4="alone" → RNN → y4, State4 (final state theoretically summarizes the whole sentence)

"Same cell, moving memory."

One set of weights reused at every time-step; the hidden state is the only thing that carries information from the past into the future.

🎓 Exam Notes
  • 📌 RNN processes sequences one token at a time, in order — this is called sequential computation
  • 📌 The hidden state is passed from one time-step to the next and is the network's only memory of the past
  • 📌 The same weights (same RNN cell) are reused at every time-step — this is what "recurrent" means
  • 📌 Know how to draw the unrolled diagram: State0 → RNN(x1) → RNN(x2) → ... → RNN(xn)

An RNN solves Seq2Seq by processing tokens one at a time, carrying a hidden state forward across time-steps. The same cell (weights) is reused every step. This sequential design is elegant, but — as the next section shows — it creates serious problems at scale.

3. RNN Problems — Why We Needed Something Better

The Three Cracks in the RNN Foundation That "Attention Is All You Need" Was Written to Fix

📋 Original Slide Content
  • Long Sequences = Slow Computations
  • Vanishing and Exploding Gradients
  • Vanished Memory
🇬🇧 English Explanation
ENGLISH EXPLANATION

The unrolled, step-by-step nature of RNNs — the very thing that made them intuitive — turned out to be their biggest weakness. Three concrete problems motivated researchers to look for an alternative:


1. Long Sequences = Slow Computations

Because each time-step depends on the output of the previous time-step, an RNN cannot be parallelized across the sequence. To process token 500 in a 500-word document, you must first finish processing tokens 1 through 499, one after another. On modern GPUs — which are built to do thousands of computations simultaneously — this sequential bottleneck wastes almost all of the available parallel compute power. Longer sequences simply take proportionally longer to process, with no way to speed that up through parallel hardware.

2. Vanishing and Exploding Gradients

During training, backpropagation must flow the error signal backwards through every single time-step, all the way from the last token back to the first. Each backward step multiplies the gradient by a small factor. Multiply a number slightly less than 1 by itself hundreds of times → it vanishes toward 0 (the network stops learning about early tokens). Multiply a number slightly greater than 1 hundreds of times → it explodes toward infinity (the weights become unstable, NaN values appear). Either way, training long sequences reliably becomes very difficult.

3. Vanished Memory (Long-Range Dependencies)

Even when training succeeds, the hidden state is a fixed-size vector that must summarize everything seen so far. As the sequence grows, information about early tokens gets diluted and overwritten by newer information — practically "forgotten." A model that read a 200-word paragraph may have almost no usable memory of word #3 by the time it reaches word #200. This means RNNs struggle badly with long-range dependencies — connections between words that are far apart in the sequence.

⚠️ The Bridge to Attention

All three problems share one root cause: RNNs are forced to process information sequentially, one step at a time, through a single bottleneck (the hidden state). The paper "Attention Is All You Need" (Vaswani et al., 2017) solved all three at once with a radical idea: let the model look at every position in the sequence simultaneously, with no sequential dependency and no single fixed-size memory bottleneck.

🇸🇦 الشرح بالعربي

طبيعة RNN التسلسلية خطوة بخطوة — وهي ما جعلها سهلة الفهم — تحوّلت إلى أكبر نقطة ضعف فيها. ثلاث مشاكل حقيقية دفعت الباحثين للبحث عن بديل:


١. الـ sequences الطويلة = حسابات بطيئة (Slow Computations):

لأن كل time-step يعتمد على مُخرج الخطوة السابقة، لا يمكن معالجة RNN بالتوازي (parallelize) عبر الـ sequence. لمعالجة الكلمة رقم 500، يجب أولاً الانتهاء من معالجة الكلمات من 1 إلى 499 بالترتيب. هذا يهدر قدرة GPU الهائلة على التوازي.


٢. تلاشي وانفجار الـ Gradients (Vanishing/Exploding Gradients):

أثناء التدريب، يجب أن يتدفق الـ backpropagation عكسيًا عبر كل خطوة زمنية. ضرب عدد أصغر من 1 في نفسه مئات المرات → يتلاشى الـ gradient نحو الصفر (الشبكة تتوقف عن التعلم من الكلمات الأولى). ضرب عدد أكبر من 1 مئات المرات → ينفجر نحو ما لا نهاية (تصبح الأوزان غير مستقرة).


٣. الذاكرة المتلاشية (Vanished Memory):

حتى لو نجح التدريب، الحالة الخفية (hidden state) هي متجه بحجم ثابت يجب أن يُلخّص كل ما رآه الـ model حتى الآن. مع تزايد طول الـ sequence، تُطمس معلومات الكلمات الأولى بمعلومات أحدث — وكأنها "نُسيت" فعليًا. هذا يجعل RNN ضعيفة جدًا في التعامل مع الاعتماديات طويلة المدى (long-range dependencies).


الجسر إلى Attention: كل هذه المشاكل سببها واحد: RNN مُضطرة لمعالجة المعلومات بشكل تسلسلي عبر عنق زجاجة واحد (الحالة الخفية). ورقة "Attention Is All You Need" حلّت الثلاثة معًا بفكرة جذرية: اجعل الـ model يرى كل المواضع في الـ sequence في نفس الوقت، بدون اعتمادية تسلسلية وبدون عنق زجاجة ذاكرة واحد.


المصطلحات:

  • Vanishing Gradient (تلاشي الـ gradient) — الـ gradient يقترب من الصفر فيتوقف التعلم
  • Exploding Gradient (انفجار الـ gradient) — الـ gradient يتضخم لدرجة عدم الاستقرار
  • Long-Range Dependency (اعتمادية طويلة المدى) — علاقة بين كلمات بعيدة عن بعضها في الجملة
  • Parallelization (التوازي) — تنفيذ عمليات متعددة في نفس الوقت
💡 Example — Vanished Memory in Action

Sentence: "The trophy that the young athlete, who trained for six years despite countless setbacks and injuries, finally lifted above her head, was gold."

By the time an RNN reaches "was gold" it must still remember that "the trophy" (word #2) is the subject — but everything in between has been overwriting the hidden state. This long-range dependency (trophy ↔ was gold) is exactly the kind of connection RNNs lose.

🚫 Common Misconceptions
  • ❌ Thinking RNN problems are only about speed — vanishing gradients and lost memory are equally serious, independent of hardware
  • ❌ Thinking a bigger hidden state fully fixes vanished memory — it delays the problem but does not remove the sequential bottleneck
  • ❌ Confusing vanishing gradients (a training-time problem) with vanished memory (an inference-time information bottleneck) — they are related but distinct
🎓 Exam Notes
  • 📌 Name all three RNN problems: slow sequential computation, vanishing/exploding gradients, vanished long-range memory
  • 📌 All three trace back to one root cause: sequential, one-step-at-a-time processing through a fixed-size hidden state
  • 📌 This is the direct motivation for "Attention Is All You Need" (2017)

RNNs suffer from: (1) slow sequential computation on long sequences, (2) vanishing/exploding gradients during backpropagation, and (3) vanished long-range memory in the fixed-size hidden state. These three problems are why researchers proposed replacing recurrence with attention.

4. "Attention Is All You Need" — Motivation

The Recurring Banner Slide That Frames the Rest of This Lecture

📋 Original Slide Content

The deck repeats a single title banner — "Attention is All You Need" — as a section divider between each building-block topic (Vectors, Matrix Operations, Tokenizer, Embeddings, Self-Attention). It is used to keep reminding the audience that every topic covered is a stepping stone toward understanding this one paper.

🇬🇧 English Explanation
ENGLISH EXPLANATION

"Attention Is All You Need" is the title of the famous 2017 paper by Vaswani et al. that introduced the Transformer architecture. Its core idea directly answers the three RNN problems from the previous section:


  • ⚡ Instead of processing tokens one-by-one, attention lets the model look at all positions in the sequence at the same time — enabling massive parallelization on GPUs
  • 🧮 Instead of squeezing all history into one fixed-size hidden state, every token can directly "attend to" (reference) every other token, no matter how far apart they are — solving the long-range dependency / vanished memory problem
  • 📉 Because there's no long chain of sequential recurrent steps to backpropagate through, gradients flow much more directly, greatly reducing vanishing/exploding gradient issues

The rest of this lecture builds up, piece by piece, exactly what is needed to understand how attention works mathematically:

  1. Vectors — how any piece of data (including words) becomes a list of numbers
  2. Matrix Operations — the math that all attention computations are built from
  3. Tokenization — turning raw text into discrete units the model can index
  4. Embeddings + Positional Encoding — turning tokens into meaningful, order-aware vectors
  5. Self-Attention (Q, K, V) — the actual attention computation itself

Each repeated "Attention Is All You Need" banner slide in the original deck marks the transition to the next building block below.

🇸🇦 الشرح بالعربي

"Attention Is All You Need" هو عنوان الورقة البحثية الشهيرة لعام 2017 (Vaswani وآخرون) التي قدّمت بنية Transformer. فكرتها الأساسية تُجيب مباشرة على مشاكل RNN الثلاثة السابقة:


  • ⚡ بدلًا من معالجة الرموز واحدًا تلو الآخر، تسمح الـ attention للـ model برؤية كل المواضع في الـ sequence في نفس الوقت — مما يُمكّن التوازي الكامل على GPU
  • 🧮 بدلًا من ضغط كل التاريخ في حالة خفية واحدة ثابتة الحجم، كل token يمكنه الإشارة مباشرة (attend) إلى أي token آخر بغض النظر عن المسافة بينهما — يحل مشكلة الذاكرة المتلاشية
  • 📉 لعدم وجود سلسلة طويلة من الخطوات التكرارية المتتالية، تتدفق الـ gradients بشكل مباشر أكثر، مما يُقلل مشاكل التلاشي والانفجار

باقي هذه المحاضرة يبني، قطعة بقطعة، بالضبط ما نحتاجه لفهم كيف تعمل الـ attention رياضيًا: Vectors ← Matrix Operations ← Tokenization ← Embeddings + Positional Encoding ← Self-Attention (Q, K, V).


المصطلحات:

  • Transformer — البنية المعمارية التي قدمتها هذه الورقة، تعتمد بالكامل على الـ attention
  • Attention (الانتباه) — آلية تُمكّن الـ model من "التركيز" على أجزاء معينة من الـ input
  • Parallelization (التوازي) — معالجة كل الرموز في وقت واحد بدل التسلسل
💡 Analogy — A Study Group vs. a Relay Race

An RNN is like a relay race: each runner (time-step) must wait for the baton (hidden state) from the previous runner before starting, and if the baton gets a little "worn out" it may lose important information by the final runner.

Self-attention is like a study group: everyone reads the material at the same time, and any student can directly ask any other student a question, regardless of where they're sitting — no need to pass anything down a chain.

🎓 Exam Notes
  • 📌 "Attention Is All You Need" (Vaswani et al., 2017) introduced the Transformer architecture
  • 📌 Attention solves parallelization, long-range dependency, and gradient flow problems simultaneously
  • 📌 Know the 5 building blocks covered in this lecture, in order: Vectors → Matrix Operations → Tokenization → Embeddings/Positional Encoding → Self-Attention

"Attention Is All You Need" replaces RNN recurrence with a mechanism that lets every token look at every other token directly and in parallel — solving speed, gradient, and long-range memory problems at once. The rest of the lecture builds the math needed to understand this mechanism.

5. Representing Data as Vectors

The Foundation of All Deep Learning Math — Turning "Things" into Numbers

📋 Original Slide Content

🇬🇧 English Explanation
ENGLISH EXPLANATION

Before any deep learning model — RNN, CNN, or Transformer — can do a single computation, the input has to become numbers. A vector is simply an ordered list of numbers, and it is the universal way to represent "a thing" so that matrix math can be applied to it.


The slide's toy example uses patient medical records. Instead of a patient being a vague concept, each patient becomes a row of numeric features:

Patient 10200 → Vector
[ 165, 71, 120, 80 ]

Height=165cm, Weight=71kg, Systolic=120mmHg, Diastolic=80mmHg — four numbers, four dimensions.

Patient 3600 → Vector
[ 180, 92, 110, 85 ]

Once patients are vectors, we can do things that would be impossible with raw human-readable records: compute distances between patients, average groups of patients, feed them into a neural network layer, or compare similarity mathematically.

Why this matters for Transformers: exactly the same idea applies to words. A word like "go" means nothing to a matrix multiplication — but once it becomes a vector of numbers (its embedding, covered later in this lecture), it can be multiplied, compared, and combined mathematically just like the patient vectors above. This is the single most important mental bridge in the whole lecture: anything — patients, pixels, or words — becomes math the moment it becomes a vector.

🇸🇦 الشرح بالعربي

قبل أن يستطيع أي deep learning model — RNN أو CNN أو Transformer — تنفيذ عملية حسابية واحدة، يجب أن يتحول الـ input إلى أرقام. المتجه (Vector) هو ببساطة قائمة مُرتّبة من الأرقام، وهو الطريقة العامة لتمثيل "أي شيء" حتى تنطبق عليه رياضيات المصفوفات (matrix math).


مثال الشريحة يستخدم سجلات طبية للمرضى. بدلًا من أن يكون المريض مفهومًا عامًا، يتحول كل مريض إلى صف من الميزات (features) الرقمية:

  • Patient 10200 → [165, 71, 120, 80] (الطول، الوزن، الضغط الانقباضي، الضغط الانبساطي)
  • Patient 3600 → [180, 92, 110, 85]

بمجرد أن يصبح المرضى vectors، يمكننا فعل أشياء مستحيلة مع السجلات النصية الخام: حساب المسافة بين مريضين، حساب متوسط مجموعة من المرضى، تمريرها إلى طبقة neural network، أو مقارنة التشابه رياضيًا.

Once data is represented as vectors, those vectors get stacked into matrices (grids of numbers), and almost everything a neural network does — including every step of self-attention — boils down to matrix multiplication.


The rule for matrix multiplication: to multiply matrix A (shape m × k) by matrix B (shape k × n), the "inner" dimensions must match (both are k). The result is a new matrix of shape m × n. Each output value is computed as the dot product of a row from A with a column from B (multiply corresponding elements, then sum them).

A (m × k)  ·  B (k × n)  =  C (m × n)

The slide's generic example uses a 4×5 matrix multiplied by a 5×4 matrix, producing a 4×4 result:

4 × 4

Notice the matching inner dimension (both are 5) cancels out, leaving the outer dimensions (4 and 4) as the shape of the result — this "inner dimensions must match, outer dimensions survive" rule is the single most useful thing to memorize about matrix multiplication for this course.


Why this matters for attention: every operation you'll see in self-attention — computing Q, K, V from the input, computing Q·Kᵀ, multiplying attention weights by V — is exactly this same operation: take two matrices whose inner dimensions match, multiply them, get a new matrix. There is no new or exotic math in attention; it is entirely built from the matrix multiplication you just reviewed.

A Tokenizer is the very first step of turning text into something a model can compute with. It breaks raw text into small chunks called tokens, and maps every possible token to a unique whole number called a Token ID, using a fixed lookup table called the vocabulary.


Why not just use whole words? Using entire words as tokens would require a vocabulary large enough to contain every word in every form (walk, walks, walked, walking...) which is huge and can't handle new/unseen words. Modern tokenizers instead use subword tokenization: common whole words get their own token ("Hello", "Go"), while rarer or longer words get split into smaller reusable pieces (like the suffix "ed", as in the slide's example). This way a fixed vocabulary of about 32,000 tokens (the size shown in the slide) can represent effectively unlimited text, including words the tokenizer has never seen as whole units — by reassembling them from familiar pieces.

Text → Tokens → Input IDs → Embeddings → + Positional Embeddings → Encoder Input

📋 Original Slide Content

🇬🇧 English Explanation
ENGLISH EXPLANATION

This section chains together everything learned so far — vectors, matrices, and tokenization — into the complete pipeline that turns raw text into the actual numeric input a Transformer's encoder receives.


The full pipeline, step by step:

  1. Raw text: "I can go alone"
  2. Tokenization: split into tokens ["I", "can", "go", "alone"]
  3. Input IDs: look up each token in the vocabulary → [105, 255, 1001, 600]
  4. Embedding lookup: use each Input ID to look up a row in a learned embedding table (a big matrix with one row per vocabulary entry). Each row is a dense vector of size d_model = 512 (the dimensionality used in the original Transformer paper) — so "I" might become a 512-number vector like [103.65, 636.22, 639.22, ..., 152.06]
  5. Add Positional Embeddings: a second 512-dimensional vector, one per position (1st, 2nd, 3rd, 4th word), added element-wise to the token embedding
  6. Encoder Input: the final 4×512 matrix (4 tokens, 512 dimensions each) that actually enters the Transformer's encoder
Encoder Input = Token Embedding + Positional Embedding  (element-wise, same shape)

Embedding — what it actually is

An embedding is a dense vector representation of a token's meaning, learned during training. Words with similar meanings end up with similar vectors (close together in the 512-dimensional space). This is the same "represent anything as a vector" idea from Section 5 (patients → vectors), just applied to word tokens instead of patients.

Why we need Positional Embeddings — the key insight

An RNN naturally knows word order, because it reads tokens one at a time, in sequence (Section 2). But self-attention has no such built-in sense of order — mathematically, it treats the input as a set of tokens rather than an ordered sequence; swapping two input positions would otherwise produce the exact same attention computation. To give the model a way to distinguish "I can go alone" from "alone go can I", the Transformer adds a distinct positional embedding vector to each token embedding — one vector for "1st position", a different one for "2nd position", and so on. This injects order information directly into the numbers the model computes with, without needing any recurrence.

🇬🇧 English Explanation
ENGLISH EXPLANATION

Self-attention is the mechanism that finally answers the question raised back in Section 4: how can every token look at every other token directly, in parallel, without recurrence? The answer is built from exactly the vectors, matrices, and embeddings covered in the previous sections.


Step 1 — Three learned projections: Query (Q), Key (K), Value (V)

Starting from the Encoder Input (the 4×512 matrix from Section 8), the model creates three different views of the same input by multiplying it by three separate learned weight matrices:

Q = Input · WQ    K = Input · WK    V = Input · WV

In the original Transformer, d_k = d_model = 512, and the sequence length here is 4 ("I can go alone"), so Q and K are each 4×512 matrices.

What Q, K, and V intuitively represent
  • 🔍 Query (Q) — "What am I looking for?" A representation of the current token's question to the rest of the sequence
  • 🔑 Key (K) — "What do I contain?" A representation of what each token in the sequence has to offer, used to be matched against queries
  • 📦 Value (V) — "What do I actually give you once matched?" The actual content/information that gets passed forward once a query finds a relevant key

The slide's pantry analogy makes this concrete: imagine a set of Key → Value pairs — Food → Rice, Computers → Keyboard, Cleaning → Soap, Office → Papers. If your Query is "Pasta", it should match most strongly with the Key "Food" (since pasta is a food item), and so you'd retrieve the associated Value, "Rice" (something also filed under Food). Self-attention does exactly this kind of matching — but instead of exact string matches, it uses the dot product between Q and K vectors as a continuous, learnable notion of "how well does this query match this key."

Step 2 — Scaled Dot-Product Attention (the full formula)

For every token's Query, we compare it against every token's Key using a dot product (Q·Kᵀ), scale the result down, turn it into probabilities with softmax, and use those probabilities to take a weighted average of the Value vectors:

Attention(Q, K, V) = softmax( Q·KT / √dk ) · V

Shapes for our example (seq=4, d_k=d_model=512):

Q
4 × 512

512 × 4

4 × 4

This 4×4 "scores" matrix answers: for each of the 4 words, how much should it attend to each of the other 4 words (including itself)? After scaling by √d_k and applying softmax row-wise, each row sums to 1.0 and represents a probability distribution — the attention weights.

Attention weights (after softmax, one row per query word):
        I     can    go     alone
I     [0.7,  0.2,   0.1,   0.1 ]
can   [0.3,  0.5,   0.1,   0.1 ]
go    [0.1,  0.3,   0.4,   0.2 ]
alone [0.05, 0.05,  0.1,   0.8 ]

Reading row "I": when computing the new representation for the word "I", the model pays 70% attention to "I" itself, 20% to "can", 10% to "go", and 10% to "alone".

Step 3 — Why divide by √d_k? (the scaling factor)

As d_k (the embedding dimension, 512 here) grows, the raw dot products Q·Kᵀ tend to grow very large in magnitude, simply because they are sums of 512 multiplied terms. Feeding very large numbers into softmax makes it extremely "peaked" — one value gets a probability near 1 and all others collapse toward 0, which produces near-zero gradients and makes learning unstable. Dividing by √d_k rescales the dot products back down to a range where softmax behaves smoothly and gradients keep flowing normally. This single division is what makes the formula "scaled" dot-product attention.

Step 4 — Multiplying attention weights by V

The final step multiplies the 4×4 attention-weight matrix by the Value matrix V (4×512), producing the self-attention output (4×512) — the same shape as the input, but now every token's vector is a weighted blend of the Value vectors of every token it attends to.

Step 5 — Multi-Head Attention (the natural extension)

Instead of computing self-attention just once, the Transformer runs it h times in parallel ("heads"), each with its own separately learned WQ, WK, WV projection matrices, and each working in a smaller dimension d_k = d_v = d_model / h. In the original paper, h = 8 heads. Each head can learn to focus on a different kind of relationship (e.g., one head might specialize in subject-verb relationships, another in nearby-word patterns). The h outputs (each seq × d_v) are concatenated back together and passed through one more learned matrix WO to produce the final MultiHead attention output, the same overall shape as a single-head output would have been.

MultiHead(Q,K,V) = Concat(head₁, head₂, ..., headh) · WO

Intuition: rather than one attention mechanism trying to capture every kind of relationship at once, multiple smaller attention mechanisms each specialize, and their combined output is richer than any single head alone.

الخطوة ١ — ثلاثة تمثيلات مُتعلَّمة: Query (Q)، Key (K)، Value (V):

بدءًا من Encoder Input (المصفوفة 4×512 من القسم الثامن)، يُنشئ الـ model ثلاث "وجهات نظر" مختلفة للـ input نفسه بضربه في ثلاث مصفوفات أوزان مُتعلَّمة منفصلة: Q = Input·W^Q ، K = Input·W^K ، V = Input·W^V. في الـ Transformer الأصلي، d_k = d_model = 512، وطول الـ sequence هنا 4 ("I can go alone")، فتكون Q وK كل واحدة منهما بحجم 4×512.


ماذا تمثل Q، K، وV بشكل بديهي؟

  • 🔍 Query (الاستعلام) — "ماذا أبحث عنه؟" تمثيل لسؤال الـ token الحالي لباقي الـ sequence
  • 🔑 Key (المفتاح) — "ماذا أحتوي؟" تمثيل لما يُقدّمه كل token في الـ sequence، يُستخدم للمطابقة مع الاستعلامات
  • 📦 Value (القيمة) — "ماذا أُعطيك فعليًا بعد المطابقة؟" المحتوى الفعلي الذي يُمرَّر بعد أن يجد الاستعلام مفتاحًا مناسبًا

مثال المخزن في الشريحة يُوضّح الفكرة: لدينا زوج Key→Value مثل Food→Rice، Computers→Keyboard، Cleaning→Soap، Office→Papers. إذا كان الاستعلام (Query) هو "Pasta"، فيجب أن يتطابق بأقوى شكل مع المفتاح (Key) "Food" (لأن المعكرونة نوع طعام)، فنسترجع القيمة (Value) المرتبطة "Rice". Self-attention تفعل نفس نوع المطابقة، لكن بدلًا من التطابق الحرفي، تستخدم الضرب النقطي بين متجهات Q وK كمقياس مستمر ومُتعلَّم لـ "مدى تطابق هذا الاستعلام مع هذا المفتاح".


الخطوة ٢ — Scaled Dot-Product Attention (المعادلة الكاملة):

لكل Query لكل token، نُقارنه بكل Key لكل token باستخدام الضرب النقطي (Q·Kᵀ)، نُصغّر النتيجة (scaling)، نُحوّلها لاحتمالات باستخدام softmax، ثم نستخدم هذه الاحتمالات لأخذ متوسط مُوزَّن (weighted average) لمتجهات V:

Attention(Q, K, V) = softmax( Q·KT / √dk ) · V

مصفوفة النتائج (scores) بحجم 4×4 تُجيب: لكل كلمة من الأربعة، كم يجب أن تُركّز (attend) على كل كلمة أخرى (بما فيها نفسها)؟ بعد التصغير بـ√d_k وتطبيق softmax على كل صف، يصبح مجموع كل صف = 1.0 ويمثل توزيعًا احتماليًا — أوزان الـ attention.


الخطوة ٣ — لماذا نقسم على √d_k؟

مع زيادة d_k (بُعد الـ embedding، 512 هنا)، تميل نتائج الضرب النقطي Q·Kᵀ للنمو بشكل كبير جدًا، لأنها مجموع 512 حاصل ضرب. تغذية softmax بأرقام كبيرة جدًا تجعلها "حادة" للغاية — قيمة واحدة تحصل على احتمال قريب من 1 وكل القيم الأخرى تنهار قريبًا من 0، وهذا يُنتج gradients قريبة من الصفر ويجعل التعلم غير مستقر. القسمة على √d_k تُعيد تحجيم النتائج إلى مدى تعمل فيه softmax بسلاسة وتستمر الـ gradients بالتدفق بشكل طبيعي. هذه القسمة هي ما يجعل المعادلة "scaled" dot-product attention.


الخطوة ٤ — ضرب أوزان الـ attention في V:

الخطوة الأخيرة تضرب مصفوفة أوزان الـ attention (4×4) في مصفوفة القيم V (4×512)، فتُنتج مُخرج self-attention (4×512) — نفس حجم الـ input، لكن الآن كل متجه token هو خليط مُوزَّن من متجهات Value لكل الـ tokens التي يُركّز عليها.


الخطوة ٥ — Multi-Head Attention (الامتداد الطبيعي):

بدلًا من حساب self-attention مرة واحدة فقط، يُشغّل الـ Transformer العملية h مرة بالتوازي ("رؤوس" heads)، كل رأس له مصفوفات W^Q و W^K و W^V مُتعلَّمة بشكل منفصل، ويعمل في بُعد أصغر d_k = d_v = d_model/h. في الورقة الأصلية، h=8 رؤوس. كل رأس يمكنه التخصص في نوع مختلف من العلاقات. مخرجات الرؤوس الـ h تُدمج معًا (concatenate) وتُمرَّر عبر مصفوفة أخرى مُتعلَّمة W^O لإنتاج مُخرج Multi-Head النهائي.

💡 Full Worked Example — "I can go alone"

1. Inputs (from Section 8): Encoder Input matrix, shape 4×512 (rows: I, can, go, alone)

2. Project to Q, K, V using learned WQ, WK, WV (each 512×512) → Q, K, V each 4×512

3. Compute scores = Q·Kᵀ / √512 → 4×4 matrix

4. Softmax each row → attention weights (rows sum to 1):

       I     can   go    alone
I    [0.7,  0.2,  0.1,  0.1 ]
can  [0.3,  0.5,  0.1,  0.1 ]
go   [0.1,  0.3,  0.4,  0.2 ]
alone[0.05, 0.05, 0.1,  0.8 ]

5. Multiply weights · V (4×4 · 4×512) → final self-attention output, 4×512

Notice "alone" attends 80% to itself and little to the others — plausible, since "alone" doesn't depend heavily on the earlier words to be understood, while "can" splits attention fairly evenly between "I" and "can" itself, reflecting the subject-verb relationship.

🧠 Memory Trick — Q, K, V

"Query asks, Key advertises, Value delivers."

Query = what I'm looking for. Key = what I'm offering to be matched against. Value = what I actually hand over once matched.

🚫 Common Mistakes
  • ❌ Thinking Q, K, V are three separate inputs — in self-attention they are all computed FROM the same input matrix, just via three different learned projections
  • ❌ Forgetting the √d_k scaling — without it, softmax becomes too peaked and gradients vanish
  • ❌ Confusing multi-head attention with running the whole model multiple times — only the attention sub-step is split into heads; heads share the surrounding architecture
  • ❌ Assuming attention weights are symmetric — the weight from "I" to "can" is not necessarily the same as from "can" to "I", since Q and K come from different projections
🎓 Exam Notes
  • 📌 Memorize the full formula: Attention(Q,K,V) = softmax(QKᵀ/√d_k)·V
  • 📌 Q, K, V are all linear projections of the same input via separate learned weight matrices W^Q, W^K, W^V
  • 📌 Know why we scale by √d_k: prevents overly peaked softmax outputs and vanishing gradients as d_k grows
  • 📌 Multi-head attention: h parallel attention computations with d_k=d_v=d_model/h, concatenated and projected by W^O
  • 📌 In the original paper: d_model=512, h=8 heads, d_k=d_v=64
  • 📌 Self-attention has no inherent notion of token order — that's why positional embeddings (Section 8) are required

Self-attention projects the input into Query, Key, Value matrices, computes similarity scores via Q·Kᵀ, scales by √d_k to stabilize softmax, converts to probabilities with softmax, and takes a weighted sum of V. Multi-head attention runs several of these in parallel with smaller dimensions and concatenates the results. Lecture 19 continues with masked attention and the full Encoder-Decoder architecture.

  • A) The raw input token
  • B) The hidden state
  • C) The attention weights
  • D) The positional embedding
✅ Answer: B — The hidden state is the RNN's running memory, updated and passed forward at every time-step.

Q3. Which of these is NOT one of the three RNN problems discussed?

  • A) Slow computation on long sequences
  • B) Vanishing/exploding gradients
  • C) Vanished long-range memory
  • D) Inability to process numeric data
✅ Answer: D — The three real problems are slow sequential computation, vanishing/exploding gradients, and vanished memory. RNNs process numeric data fine — that's not a limitation.

Q4. Why can't self-attention be computed sequentially the way RNNs require?

  • A) It can only be computed sequentially — that's a myth
  • B) Every token's attention score can be computed independently and in parallel using matrix multiplication
  • C) Self-attention doesn't use matrices at all
  • D) Self-attention requires a GPU with no other software running
✅ Answer: B — Because Q·Kᵀ is a single matrix multiplication covering all token pairs at once, there is no step-by-step dependency, allowing full parallelization.

Q5. Multiplying a matrix of shape (4×5) by a matrix of shape (5×4) produces a matrix of shape:

  • A) 5×5
  • B) 4×4
  • C) 4×5
  • D) 20×20
✅ Answer: B — (m×k)·(k×n) = (m×n). Here m=4, k=5, n=4, so the result is 4×4. The inner dimensions (5) must match and cancel out.

Q6. What does a tokenizer's "vocabulary" contain?

  • A) A list of grammar rules
  • B) A fixed mapping of every possible token to a unique Token ID
  • C) The trained model's weights
  • D) The positional embeddings
✅ Answer: B — The vocabulary is a fixed lookup table mapping tokens (words/subwords) to integer Token IDs (e.g. ~32,000 entries in the slide example).

Q7. Why are positional embeddings added to token embeddings in a Transformer?

  • A) To reduce the vocabulary size
  • B) Because self-attention has no built-in notion of token order
  • C) To speed up tokenization
  • D) To replace the need for an embedding table
✅ Answer: B — Unlike RNNs, self-attention treats input as an unordered set unless positional information is explicitly injected via positional embeddings.

Q8. In scaled dot-product attention, what is the purpose of dividing by √d_k?

  • A) To make the matrix square
  • B) To prevent overly large dot products from making softmax too peaked, which would hurt gradient flow
  • C) To convert Q into K
  • D) To increase the vocabulary size
✅ Answer: B — Without scaling, large-magnitude dot products (which grow with d_k) push softmax toward near-one-hot outputs, causing vanishing gradients.

Answer: The raw dot product Q·Kᵀ is a sum of d_k multiplied terms, so its magnitude grows roughly with d_k. This causes vanishing gradients through the softmax and destabilizes training. Dividing by √d_k rescales the scores to a range where softmax stays smooth and gradients continue to flow.

Answer: RNNs process tokens one at a time, in strict sequential order, so the order of the sequence is naturally encoded in the very structure of the computation (token 1 is processed before token 2, etc.). Self-attention, by contrast, computes relationships between all token pairs simultaneously via matrix multiplication — mathematically, swapping two positions in the input would produce the same set of pairwise computations, so the model has no inherent way to know which token came first.
