1. R-CNN Overview — Object Detection with Region Proposals

The first deep-learning object detector: propose regions, then classify each one

📋 Original Slide Content

R-CNN for object detection

  • Scan the input image for possible objects using an algorithm called Selective Search, generating ~2000 region proposals.
  • Run a convolutional neural net (CNN) on top of each of these region proposals.
  • Take the output of each CNN and feed it into: an SVM to classify the region, and a Linear regressor to tighten the bounding box of the object if such an object exists.
🇬🇧 English Explanation
ENGLISH EXPLANATION

R-CNN (Regions with CNN features) was the first successful attempt to combine deep CNNs with object detection. Before R-CNN, object detectors either scanned the whole image with a sliding window (very slow) or used hand-crafted features. R-CNN's insight: don't look everywhere — first guess where objects probably are, then only run the expensive neural network on those guesses.


The R-CNN pipeline, step by step:

  1. Take the input image and run Selective Search — a classical (non-neural) algorithm — to generate roughly 2000 region proposals (candidate rectangles that might contain an object).
  2. For each of those ~2000 proposals, crop and warp the region to a fixed size, then run a full CNN forward pass on it to extract a feature vector.
  3. Feed that feature vector into an SVM (Support Vector Machine) classifier to decide what class of object is in the region (or "no object").
  4. Separately feed the same feature vector into a linear regressor that nudges the box coordinates so the bounding box fits the object more tightly.

Notice the two independent "decision-makers" at the end: the SVM answers "what is it?" and the linear regressor answers "where exactly is it?" — R-CNN needed both because a rough region proposal is rarely a perfect box around the object.

⚠️ The Catch

Running a full CNN forward pass ~2000 times per single image is extremely expensive. R-CNN gave good accuracy for its time but was painfully slow — this weakness is exactly what later models (Fast R-CNN, Faster R-CNN) were built to fix.

🇸🇦 الشرح بالعربي
شرح تفصيلي

R-CNN (Regions with CNN features) كانت أول محاولة ناجحة لدمج الشبكات العصبية الالتفافية (CNN) مع مهمة اكتشاف الأجسام (Object Detection). قبل R-CNN، كانت أنظمة الكشف تفحص الصورة كاملة بنافذة منزلقة (Sliding Window) وهذا كان بطيئًا جدًا. الفكرة الجديدة في R-CNN: لا تبحث في كل مكان، بل خمّن أولًا أين يُحتمل وجود الأجسام (باستخدام region proposals)، ثم شغّل الشبكة العصبية المكلفة فقط على هذه الأماكن المرشحة.


خطوات R-CNN:

  • تشغيل خوارزمية Selective Search (خوارزمية كلاسيكية بدون تعلم عميق) على الصورة لتوليد حوالي 2000 منطقة مرشحة (region proposals).
  • لكل منطقة من هذه المناطق، يتم تشغيل CNN كاملة لاستخراج vector من الميزات (features).
  • هذا الـ vector يُمرَّر إلى SVM لتصنيف نوع الجسم الموجود في المنطقة.
  • وفي نفس الوقت يُمرَّر إلى linear regressor لتعديل حدود صندوق الإحاطة (bounding box) ليصبح أدق وأكثر التصاقًا بالجسم.

المصطلحات المهمة:

  • Region Proposal (منطقة مرشحة) — مستطيل يُحتمل أن يحتوي على جسم
  • Selective Search — خوارزمية توليد المناطق المرشحة
  • CNN (شبكة عصبية التفافية) — تستخرج الميزات من كل منطقة
  • SVM (آلة المتجهات الداعمة) — تُصنّف نوع الجسم
  • Bounding Box (صندوق الإحاطة) — المستطيل الذي يحيط بالجسم
  • Linear Regressor (منحدر خطي) — يُعدّل موضع الصندوق ليصبح أدق

أهم النقاط:

  • ✅ R-CNN = Selective Search + CNN لكل منطقة + SVM للتصنيف + Regressor لتحسين الصندوق
  • ⚠️ العيب الأساسي: تشغيل CNN حوالي 2000 مرة لكل صورة — بطيء للغاية
💡 Simple Example — Spotting Cars in a Street Photo

Imagine a photo of a busy street. Selective Search first draws ~2000 candidate rectangles anywhere it thinks "something might be here" — around cars, people, even random patches of sidewalk. For each rectangle, R-CNN crops that patch, resizes it, and asks the CNN "what do you see here?" The SVM says "car" or "not a car," and the regressor slides/resizes the rectangle to hug the actual car shape more precisely.

🧠 Memory Trick — R-CNN Pipeline

"Search, See, Sort, Snap"

Search (Selective Search proposes regions) → See (CNN extracts features) → Sort (SVM classifies) → Snap (regressor tightens the box)

🎓 Exam / Interview Notes
  • 📌 R-CNN = Selective Search (proposals) → CNN per region (features) → SVM (classify) + Linear Regressor (box refinement)
  • 📌 ~2000 region proposals per image is the standard number to remember
  • 📌 R-CNN uses TWO separate learned components at the end: SVM and regressor — not a single unified network
  • 📌 Common exam Q: "Why is R-CNN slow?" → It runs a full CNN forward pass once per region proposal (~2000 times per image)

R-CNN: Selective Search generates ~2000 region proposals → each region is warped and passed through a full CNN → CNN features feed an SVM (classification) and a linear regressor (box refinement). Accurate but extremely slow because of running the CNN ~2000 times per image.

2. The Selective Search Algorithm

How R-CNN generates its ~2000 candidate regions — a bottom-up merging process

📋 Original Slide Content
  • Initial Segmentation: Over-segments the image into thousands of tiny, initial starter regions.
  • Similarity Calculation: Measures how alike adjacent regions are based on color, texture, size, and shape fit.
  • Iterative Merging: Continually merges the two most similar neighboring regions into a larger one.
  • Hierarchical Grouping: Repeats this merging process from the bottom up until the entire image is a single region.
  • Proposal Generation: Draws bounding boxes around every region created during the process, resulting in the ~2000 region proposals.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Selective Search is a classical (pre-deep-learning) computer vision algorithm — it uses no neural network at all. Its job is purely to guess "here are some rectangles that probably contain something interesting," without knowing what that something is yet.


The five exact steps:

  1. Initial Segmentation — Over-segment the image into thousands of tiny starter regions (like shattering the image into many small puzzle pieces based on low-level pixel similarity).
  2. Similarity Calculation — For every pair of adjacent (touching) regions, compute a similarity score based on color, texture, size, and shape fit (do the two regions combine into a nice compact shape?).
  3. Iterative Merging — Find the two most similar neighboring regions in the whole image and merge them into one larger region.
  4. Hierarchical Grouping — Repeat step 3 over and over, bottom-up, so regions keep merging into bigger regions, until eventually the entire image has merged into a single region.
  5. Proposal Generation — Every region that ever existed at any point during this whole merging process (tiny starter pieces, medium merged blobs, and the final whole-image region) gets a bounding box drawn around it. Collecting all of these boxes across every merge step is what produces the final ~2000 region proposals.

The key mental model: Selective Search doesn't decide "this is the region" once — it builds an entire hierarchy of regions from tiny to huge, and keeps a snapshot bounding box at every level of that hierarchy. That is why it naturally produces proposals at many different scales (small objects and large objects alike).

🇸🇦 الشرح بالعربي

Selective Search هي خوارزمية كلاسيكية (لا تستخدم أي شبكة عصبية) وظيفتها الوحيدة هي تخمين "هذه مستطيلات يُحتمل أن تحتوي على شيء مهم"، دون أن تعرف ما هو هذا الشيء بعد.


الخطوات الخمس بالتفصيل:

  1. التجزيء الابتدائي (Initial Segmentation) — تقسيم الصورة إلى آلاف المناطق الصغيرة جدًا في البداية.
  2. حساب التشابه (Similarity Calculation) — قياس مدى تشابه كل منطقتين متجاورتين بناءً على اللون (color) والنقشة (texture) والحجم (size) ومدى تناسب الشكل (shape fit).
  3. الدمج التكراري (Iterative Merging) — دمج أكثر منطقتين متجاورتين تشابهًا في منطقة واحدة أكبر.
  4. التجميع الهرمي (Hierarchical Grouping) — تكرار عملية الدمج من الأسفل إلى الأعلى حتى تتحول الصورة كاملة إلى منطقة واحدة فقط.
  5. توليد المقترحات (Proposal Generation) — رسم صندوق إحاطة (bounding box) حول كل منطقة ظهرت في أي خطوة من عملية الدمج، فتنتج في النهاية حوالي 2000 منطقة مرشحة.

الفكرة الأساسية: الخوارزمية لا تقرر منطقة واحدة نهائية، بل تبني هرمًا كاملًا من المناطق (من الصغيرة جدًا إلى الكبيرة جدًا)، وتحتفظ بصندوق إحاطة عند كل مستوى من هذا الهرم. هذا هو سبب حصولنا على مقترحات بمقاييس مختلفة (أجسام صغيرة وكبيرة).


المصطلحات:

  • Over-segmentation (التجزيء المفرط) — تقسيم الصورة لقطع صغيرة جدًا في البداية
  • Similarity (التشابه) — بناءً على اللون والنقشة والحجم والشكل
  • Hierarchical (هرمي) — من الأسفل إلى الأعلى (bottom-up)
  • Region Proposal (منطقة مرشحة) — صندوق إحاطة نهائي مُقترح
💡 Analogy — Merging Puzzle Pieces

Imagine shattering a photo into 5000 tiny jigsaw pieces (initial segmentation). You then repeatedly glue together the two pieces that look most alike — same color, same pattern (similarity calculation + merging). You keep gluing pairs together, over and over, level after level (hierarchical grouping), until finally the whole photo is one giant glued piece. At every single gluing step along the way, you took a photo of the current piece's outline (bounding box) — those thousands of snapshots are your region proposals.

⚠️ Common Misconception

Selective Search does NOT know what objects are in the image. It has zero semantic understanding — it is purely a bottom-up grouping algorithm based on low-level pixel statistics. All the "what is this object?" reasoning happens later, inside the CNN + SVM.

🎓 Exam Notes
  • 📌 Memorize the 5 steps in order: Initial Segmentation → Similarity Calculation → Iterative Merging → Hierarchical Grouping → Proposal Generation
  • 📌 Similarity is based on 4 cues: color, texture, size, shape fit
  • 📌 The process is bottom-up: small regions merge into progressively bigger ones
  • 📌 Every intermediate region (not just the final ones) contributes a bounding box proposal

Selective Search over-segments the image, then repeatedly merges the most similar adjacent regions (by color/texture/size/shape) bottom-up until one region remains, drawing a bounding box around every region ever created — producing ~2000 proposals.

Every proposal from Selective Search takes an independent trip through the entire warp → CNN → SVM/regressor pipeline. Nothing is shared or reused between proposals — even if two region proposals overlap by 90%, R-CNN still processes them as two completely separate CNN runs.


🚫 The Big Weakness — Speed

R-CNN is painfully slow because it runs a full CNN forward pass approximately 2000 times per image. On the hardware of its time, detecting objects in a single image could take on the order of tens of seconds. This makes R-CNN completely impractical for real-time applications (video, robotics, self-driving cars) and even slow for batch processing of large image datasets.

The root cause: R-CNN treats feature extraction as a per-region operation, when really most of those 2000 regions overlap and share huge portions of the same image pixels. Recomputing CNN features from scratch for every overlapping patch is massively redundant computation.

🇸🇦 الشرح بالعربي

هذه الشريحة رسم بياني (diagram)، فلنعيد بناءها كخط أنابيب (pipeline) من اليسار إلى اليمين:

الصورة الكاملة → Selective Search تُولّد ~2000 منطقة مرشحة → كل منطقة تُشوَّه (warp) لحجم ثابت وتُمرَّر عبر CNN كاملة (2000 مرة!) → متجه ميزات (feature vector) لكل منطقة → يُمرَّر إلى SVM لتحديد التصنيف، وإلى linear regressor لتحسين صندوق الإحاطة.


كل منطقة مرشحة من Selective Search تأخذ رحلة مستقلة تمامًا عبر كامل الـ pipeline (تشويه → CNN → SVM/regressor). لا يوجد أي مشاركة أو إعادة استخدام بين المناطق — حتى لو تداخلت منطقتان بنسبة 90%، فإن R-CNN يُعالجهما كتشغيلين منفصلين تمامًا للـ CNN.


🚫 نقطة الضعف الكبرى — السرعة

R-CNN بطيئة للغاية لأنها تُشغّل CNN كاملة حوالي 2000 مرة لكل صورة واحدة. هذا يجعلها غير عملية تمامًا للتطبيقات الفورية (الفيديو، الروبوتات، السيارات ذاتية القيادة).

السبب الجذري: معظم المناطق الـ 2000 تتداخل مع بعضها وتُغطي نفس بيكسلات الصورة، ومع ذلك تُعيد R-CNN حساب ميزات CNN من الصفر لكل منطقة متداخلة — وهذا حساب زائد ومُكرر بشكل ضخم.


المصطلحات:

  • Warp (تشويه/تحجيم) — تحويل المنطقة إلى حجم ثابت قبل إدخالها للـ CNN
  • Feature Vector (متجه الميزات) — تمثيل رقمي مستخرج من الـ CNN
  • Redundant Computation (حساب زائد) — إعادة حساب نفس الشيء بدون فائدة
💡 Practical Example — Why This Matters

If a single CNN forward pass takes ~10 milliseconds on old hardware, and you must run it 2000 times per image, that's already 20 seconds — just for feature extraction, before SVM/regression even happen. Processing a video at even 1 frame per second would be impossible. This single number (~2000 CNN passes) is the entire motivation for every model that came after R-CNN.

🎓 Exam Notes
  • 📌 Be able to draw the R-CNN pipeline: Image → Selective Search → warp each region → CNN per region → SVM + regressor
  • 📌 The critical bottleneck: ~2000 separate CNN forward passes per image
  • 📌 Root cause of the slowness: redundant computation on overlapping regions
  • 📌 This weakness directly motivates Fast R-CNN's "one CNN pass over the whole image" design

R-CNN's architecture runs the full warp→CNN→SVM/regressor pipeline independently for every one of ~2000 region proposals, with zero feature sharing between overlapping regions. This makes it accurate but extremely slow — the exact problem Fast R-CNN solves next.

SLIDE 5

4. Fast R-CNN — One CNN Pass Instead of 2000

Sharing computation across region proposals and unifying classification into the network

📋 Original Slide Content
  • The purpose of the Fast Region-based Convolutional Network (Fast R-CNN) is to reduce the time consumption related to the high number of models necessary to analyze all region proposals.
  • Performing feature extraction over the image before proposing regions, thus only running one CNN over the entire image instead of 2000 CNN's over 2000 overlapping regions.
  • Replacing the SVM with a softmax layer, thus extending the neural network for predictions instead of creating a new model.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Fast R-CNN keeps the idea of "propose regions, then classify them," but fixes the single biggest inefficiency in R-CNN: redundant CNN computation.


The key innovation: instead of running a CNN separately on each of the 2000 cropped/warped region images, Fast R-CNN runs the CNN exactly once, on the entire image, producing one shared convolutional feature map. Since region proposals are just rectangular areas of the original image, their corresponding areas can be located and cropped directly out of that single shared feature map — no need to re-run the CNN for each one.


Once each region's chunk of the feature map is located, a small operation called RoI Pooling (Region of Interest Pooling) resizes that variable-sized chunk into a fixed-size feature grid, so it can be fed into the following fully-connected layers regardless of the original region's shape.


Fast R-CNN also replaces the separate SVM classifier with a softmax layer that is part of the same neural network. This means classification is no longer a separate model trained afterwards — it is trained together with the feature extractor in one single end-to-end network, learned jointly via backpropagation.


R-CNN vs Fast R-CNN, side by side:

R-CNN

  • ~2000 separate CNN forward passes per image
  • Classifier: separate SVM (trained apart from the CNN)
  • Very slow — tens of seconds per image
  • Box refinement: separate linear regressor

Fast R-CNN

  • 1 shared CNN forward pass per image
  • Classifier: softmax layer inside the same network
  • Much faster — roughly 10x+ speed-up at test time
  • Box refinement: regression head inside the same network

Region proposals in Fast R-CNN still come from the same external Selective Search algorithm — that part has not changed yet. Selective Search is still a bottleneck, and that is exactly what Faster R-CNN solves next.

🇸🇦 الشرح بالعربي

Fast R-CNN يحافظ على فكرة "اقترح مناطق ثم صنّفها"، لكنه يُصلح أكبر مصدر بطء في R-CNN: الحساب المُكرر.


الابتكار الأساسي: بدلًا من تشغيل CNN بشكل منفصل على كل منطقة من الـ 2000 منطقة، يُشغّل Fast R-CNN الـ CNN مرة واحدة فقط على الصورة كاملة، لإنتاج خريطة ميزات مشتركة (shared feature map). وبما أن كل منطقة مرشحة هي مجرد جزء مستطيل من الصورة الأصلية، يمكن تحديد موقعها المقابل مباشرة داخل خريطة الميزات المشتركة تلك — بدون الحاجة لإعادة تشغيل CNN لكل منطقة.


بعد تحديد الجزء المقابل لكل منطقة داخل خريطة الميزات، تأتي عملية تُسمى RoI Pooling (تجميع منطقة الاهتمام) والتي تُحوّل هذا الجزء (ذو الحجم المتغير) إلى شبكة ميزات بحجم ثابت، بحيث يمكن تمريرها للطبقات الكاملة الاتصال بعدها بدون مشكلة.


كما يستبدل Fast R-CNN الـ SVM المنفصل بـ طبقة softmax جزء من نفس الشبكة العصبية. هذا يعني أن التصنيف لا يعود نموذجًا منفصلًا يتم تدريبه بعد ذلك، بل يتم تدريبه مع مستخرج الميزات معًا في شبكة واحدة متكاملة من البداية للنهاية (end-to-end)، عبر backpropagation.


المصطلحات:

  • Shared Feature Map (خريطة ميزات مشتركة) — نتيجة تشغيل CNN مرة واحدة على الصورة كاملة
  • RoI Pooling — تحويل جزء متغير الحجم من خريطة الميزات إلى حجم ثابت
  • Softmax Layer — طبقة داخل الشبكة تُخرج احتمالية كل تصنيف
  • End-to-End Training (تدريب من النهاية إلى النهاية) — تدريب كل الأجزاء معًا في نموذج واحد

مقارنة سريعة: R-CNN = 2000 تشغيل CNN + SVM منفصل + بطيء جدًا. Fast R-CNN = تشغيل CNN واحد فقط + softmax مدمجة + أسرع بكثير. لكن يبقى Selective Search (المُقترح الخارجي للمناطق) عائقًا لأنه لا يزال خوارزمية كلاسيكية بطيئة نسبيًا — وهذا ما تُصلحه Faster R-CNN بعد ذلك.

💡 Analogy — Photocopying vs. Cutting the Original

R-CNN is like photocopying the entire document 2000 times just so you can highlight 2000 different paragraphs separately. Fast R-CNN instead photocopies the document once, then simply looks at the relevant paragraph coordinates directly on that single copy — much less wasted work, same end result.

🎓 Exam Notes
  • 📌 Fast R-CNN's core fix: ONE shared CNN feature map for the whole image, not one CNN run per region
  • 📌 RoI Pooling extracts a fixed-size feature grid from a variable-sized region of the shared feature map
  • 📌 SVM is replaced by a softmax layer trained jointly with the network (end-to-end)
  • 📌 Fast R-CNN still relies on Selective Search for region proposals — this is still slow and is fixed in Faster R-CNN

Fast R-CNN runs the CNN once over the whole image to get a shared feature map, uses RoI Pooling to extract fixed-size features for each region proposal from that map, and replaces the SVM with an internal softmax layer for true end-to-end training. Selective Search is still used externally for proposals.

إعادة بناء هذا الرسم البياني كخط أنابيب:

الصورة كاملة → تشغيل CNN مرة واحدة فقط → خريطة ميزات مشتركة واحدة. وبالتوازي: Selective Search يُقترح مناطق على الصورة الأصلية. ثم: تُعرض (project) كل منطقة مرشحة على خريطة الميزات المشتركة → RoI Pooling يُنتج شبكة ميزات بحجم ثابت لكل منطقة → طبقات كاملة الاتصال → مخرجان: softmax للتصنيف، و regression لتحسين صندوق الإحاطة.


لاحظ أن مربع CNN يظهر مرة واحدة فقط في هذا الرسم — يُعاد استخدام هذا المربع الواحد لكل منطقة مرشحة، على عكس رسم R-CNN الذي كان يحتاج تكرار مربع CNN 2000 مرة. المناطق المرشحة تدخل الصورة فقط بعد انتهاء الحساب المكلف للـ CNN، وفقط لتقول للشبكة "انظر إلى هذا الجزء من خريطة الميزات المحسوبة مسبقًا".


المخرجان النهائيان (softmax للتصنيف + regression لصندوق الإحاطة) يخرجان من نفس الطبقات كاملة الاتصال، ولهذا يُوصف Fast R-CNN بأن له "دالة خسارة متعددة المهام" (multi-task loss) — خسارة واحدة للتصنيف وخسارة أخرى لتحسين الصندوق، تُدرَّبان معًا.


المصطلحات:

  • Project (عرض/إسقاط) — تحديد موقع المنطقة المرشحة داخل خريطة الميزات
  • Multi-task Loss (خسارة متعددة المهام) — دمج خسارتين مختلفتين في تدريب واحد
  • Fully-Connected Layers (طبقات كاملة الاتصال) — طبقات تربط كل عصبون بكل عصبون في الطبقة التالية
💡 Visual Intuition

Think of the shared feature map as a giant, already-computed "X-ray" of the whole image. Selective Search's rectangles are just coordinates saying "look here" on that X-ray. RoI Pooling then crops and resizes that specific patch of the X-ray to a standard size — like always printing photos at the same size no matter how big the original crop was.

  • 📌 The CNN box appears exactly once in the Fast R-CNN diagram — a key visual difference from R-CNN's diagram
  • 📌 Region proposals are projected onto the feature map, not re-computed from raw pixels
  • 📌 RoI Pooling standardizes variable-sized regions into a fixed-size grid for the FC layers
  • 📌 Fast R-CNN trains classification + box regression jointly (multi-task loss)

Fast R-CNN's architecture: one CNN pass produces a shared feature map; Selective Search proposals are projected onto that map; RoI Pooling extracts fixed-size features per region; fully-connected layers output softmax classification and box regression jointly.

SLIDE 7

6. Faster R-CNN — Region Proposals Become Learnable

The single most important idea in this lecture: replacing Selective Search with a tiny trainable neural network

📋 Original Slide Content

Faster R-CNN

  • Step 1: Feature Extraction — The input image is passed through a pre-trained CNN backbone (the original Faster R-CNN used VGG). The network extracts a convolutional feature map, which is then used for subsequent processing.
  • Step 2: Region Proposal Network (RPN) — The RPN takes the feature map and proposes a set of candidate regions (bounding boxes) that may contain objects. It does this by generating multiple region proposals using k anchor boxes of predefined scales and aspect ratios. k anchor boxes = the number of predefined bounding box shapes (scales + ratios) that the network uses at each feature map location to generate region proposals. Each anchor = one rectangle shape. You choose different scales (small, medium, large) and different aspect ratios (e.g., 1:1, 2:1, 1:2). This module significantly speeds up both training and inference compared to earlier methods.
  • Step 3: R-CNN Module — For each proposed region, the R-CNN head performs two tasks: Classification — determine what object (if any) is inside the region, including the "background" category; Bounding Box Regression — refine the bounding box coordinates to better align with the detected object.
🇬🇧 English Explanation
ENGLISH EXPLANATION

Fast R-CNN fixed the CNN redundancy problem, but it still relied on Selective Search — a slow, CPU-based, non-learnable classical algorithm — to generate region proposals. Faster R-CNN's single big idea: replace Selective Search entirely with a small neural network that proposes regions itself, learned end-to-end alongside everything else.


The 3 steps of Faster R-CNN:

  1. Feature Extraction — The image passes through a pre-trained CNN backbone (originally VGG) to produce a shared convolutional feature map, exactly like in Fast R-CNN.
  2. Region Proposal Network (RPN) — Instead of Selective Search, a small neural network called the RPN slides over the feature map and proposes candidate boxes directly, using k anchor boxes at every location.
  3. R-CNN Head — For every region the RPN proposed, classify what's inside (including a "background" option) and regress the box coordinates to fit tighter — same idea as before, just now fed by RPN proposals instead of Selective Search proposals.

What is an Anchor Box? (Simple Analogy)

Imagine you have a set of transparent stencils of different sizes and shapes — a small square, a medium square, a tall thin rectangle, a wide short rectangle — and at every single position on a grid over the image, you hold up all of these stencils and ask "does an object roughly this shape and size sit here?" Each stencil is an anchor box: a predefined rectangle shape (a combination of scale — small/medium/large — and aspect ratio — e.g. 1:1 square, 2:1 wide, 1:2 tall) placed at a fixed grid location on the feature map. k is simply how many different stencils (anchor shapes) you use at each location — a typical Faster R-CNN setup uses k=9 (3 scales × 3 aspect ratios).


Why this matters — Fast R-CNN vs Faster R-CNN:

Fast R-CNN

  • Region proposals from Selective Search
  • Selective Search runs on the CPU, is hand-designed, not learned
  • Proposal generation is a separate, slow pre-processing step
  • Cannot be improved by training — it's fixed, classical logic

Faster R-CNN

  • Region proposals from the RPN (a small neural network)
  • RPN runs on the GPU, shares the same backbone feature map, is fully learned
  • Proposal generation is baked into the same forward pass — nearly free
  • Trained end-to-end with the rest of the network, so it keeps getting better
⭐ The Single Most Important Idea Here

The real leap from Fast R-CNN to Faster R-CNN is NOT about the classifier or RoI Pooling — those stay basically the same. It's that region proposal generation moves from being an external, slow, CPU-bound, non-learnable classical algorithm (Selective Search) to being an internal, fast, GPU-bound, learnable tiny neural network (the RPN) that shares computation with the rest of the detector. This is why Faster R-CNN is dramatically faster and can even approach real-time speeds.

🇸🇦 الشرح بالعربي

حلّ Fast R-CNN مشكلة تكرار حساب CNN، لكنه كان لا يزال يعتمد على Selective Search — خوارزمية كلاسيكية بطيئة تعمل على المعالج (CPU) ولا تتعلم من البيانات. الفكرة الكبرى في Faster R-CNN: استبدال Selective Search بالكامل بشبكة عصبية صغيرة تُقترح المناطق بنفسها، وتتعلم مع باقي الشبكة من البداية للنهاية.


خطوات Faster R-CNN الثلاث:

  1. استخراج الميزات (Feature Extraction) — الصورة تمر عبر CNN مُدرَّب مسبقًا (كانت VGG في الأصل) لإنتاج خريطة ميزات مشتركة، تمامًا كما في Fast R-CNN.
  2. شبكة اقتراح المناطق (RPN) — بدلًا من Selective Search، شبكة عصبية صغيرة تُسمى RPN تتحرك فوق خريطة الميزات وتُقترح مناطق مباشرة، باستخدام k صندوق مرجعي (anchor boxes) عند كل موضع.
  3. رأس R-CNN (R-CNN Head) — لكل منطقة اقترحتها RPN، يُصنَّف ما بداخلها (بما فيها خيار "خلفية/background")، ويُحسَّن صندوق الإحاطة — نفس الفكرة السابقة، لكن الآن المُدخلات من RPN بدلًا من Selective Search.

ما هو Anchor Box؟ (تشبيه مبسّط)

تخيل أن لديك مجموعة من الأستنسل (استنسلات) الشفافة بأشكال وأحجام مختلفة — مربع صغير، مربع متوسط، مستطيل رفيع طويل، مستطيل عريض قصير — وعند كل نقطة على شبكة منتشرة فوق الصورة، تضع كل هذه الأستنسلات وتسأل "هل يوجد جسم بهذا الشكل والحجم هنا تقريبًا؟" كل استنسل هو anchor box: مستطيل محدد مسبقًا (مزيج من المقياس (scale) — صغير/متوسط/كبير — ونسبة الأبعاد (aspect ratio) — مثل 1:1 مربع، 2:1 عريض، 1:2 طويل) يُوضع في موضع ثابت على خريطة الميزات. k هو ببساطة عدد الأستنسلات (أشكال anchor) المستخدمة عند كل موضع — الإعداد النموذجي في Faster R-CNN هو k=9 (3 مقاييس × 3 نسب أبعاد).


أهم نقطة في الشريحة كلها: الفرق الحقيقي بين Fast R-CNN و Faster R-CNN ليس في المُصنِّف أو RoI Pooling — هذه تبقى تقريبًا كما هي. الفرق هو أن توليد المقترحات (region proposals) انتقل من خوارزمية خارجية بطيئة تعمل على CPU ولا تتعلم (Selective Search)، إلى شبكة عصبية صغيرة داخلية سريعة تعمل على GPU وتتعلم (RPN) وتُشارك الحساب مع باقي الشبكة. هذا هو سبب كون Faster R-CNN أسرع بشكل كبير وقادرة على الاقتراب من السرعة الفورية (real-time).


المصطلحات:

  • Backbone (العمود الفقري) — الشبكة الأساسية لاستخراج الميزات (مثل VGG)
  • RPN (شبكة اقتراح المناطق) — شبكة صغيرة تتعلم توليد المقترحات
  • Anchor Box (صندوق مرجعي) — شكل مستطيل محدد مسبقًا
  • Scale (المقياس) — حجم الصندوق: صغير/متوسط/كبير
  • Aspect Ratio (نسبة الأبعاد) — نسبة العرض للارتفاع
  • Learnable (قابل للتعلم) — يتحسن مع التدريب، على عكس Selective Search

SLIDES 8–9

7. How the RPN Labels Anchor Boxes (IoU Thresholds)

Teaching the RPN which anchors are "object" and which are "background"

📋 Original Slide Content

How RPN Detects Objects (Anchor Box Labeling)

  • Intersection over Union (IoU): Measures the overlap between the Anchor Box and the Ground Truth (true object box).
  • Positive Anchors (Object): Boxes with high IoU (e.g., > 0.7) are labeled as containing an object.
  • Negative Anchors (Background): Boxes with low IoU (e.g., < 0.3) are labeled as background.
  • RPN Classification Head: Outputs a probability score for each anchor box p_object vs. p_background to filter out empty regions.
  • Bounding Box Regression: Automatically adjusts the coordinates of the chosen anchor box to tightly fit the object.

(Slide 9 is a supporting illustration of anchors overlapping a ground-truth box — described conceptually below.)

🇬🇧 English Explanation
ENGLISH EXPLANATION

The RPN generates thousands of anchor boxes across the image, but during training it needs a rule to decide: "is this particular anchor a good match for a real object, or should it be ignored as background?" That rule is based on Intersection over Union (IoU).


IoU = (Area of Overlap between Anchor and Ground Truth) / (Area of Union of Anchor and Ground Truth)

IoU ranges from 0 (no overlap at all) to 1 (perfectly identical boxes).


IoU RangeLabelMeaning
IoU > 0.7Positive (Object)The anchor overlaps enough with a real ground-truth box to count as containing an object
0.3 ≤ IoU ≤ 0.7IgnoredAmbiguous overlap — excluded from training so the network isn't confused by borderline cases
IoU < 0.3Negative (Background)The anchor barely or never overlaps a ground-truth box — labeled as background

Worked numeric example — three anchors compared to one ground-truth box:

Ground-truth box GT = (100,100) to (300,300) → a 200×200 box, area = 40,000 px².

Anchor BoxOverlap AreaUnion AreaIoULabel
A1: (110,110)–(310,310)190×190 = 36,10040,000+40,000−36,100 = 43,90036,100/43,900 ≈ 0.82Positive (>0.7)
A2: (150,150)–(350,350)150×150 = 22,50040,000+40,000−22,500 = 57,50022,500/57,500 ≈ 0.39Ignored (0.3–0.7)
A3: (500,500)–(700,700)0 (no overlap)40,000+40,000−0 = 80,0000/80,000 = 0.00Negative (<0.3)

This is exactly why the thresholds matter: A1 is close enough to the ground truth to teach the RPN "an object looks like this here," A3 correctly teaches it "nothing is here," and A2 is deliberately thrown away during training because it's neither clearly right nor clearly wrong — including it would send a noisy, confusing signal to the network.


After labeling, two heads act on every anchor:

  • 🎯 RPN Classification Head — outputs p_object vs p_background (a simple two-class probability) for every anchor, filtering out the empty ones
  • 📐 Bounding Box Regression — for anchors labeled positive, adjusts the anchor's coordinates (x, y, width, height offsets) so the final box tightly hugs the actual object instead of just roughly overlapping it

تُولّد RPN آلاف صناديق anchor عبر الصورة، لكنها تحتاج أثناء التدريب إلى قاعدة لتحديد: "هل هذا الـ anchor مطابق بشكل جيد لجسم حقيقي، أم يجب اعتباره خلفية؟" هذه القاعدة تعتمد على Intersection over Union (IoU) — نسبة التقاطع على الاتحاد.


IoU = مساحة التقاطع بين Anchor و Ground Truth ÷ مساحة الاتحاد بينهما

تتراوح قيمة IoU بين 0 (لا يوجد تداخل) و 1 (الصندوقان متطابقان تمامًا).


  • IoU أكبر من 0.7 → إيجابي (Positive/Object) — يُعتبر الـ anchor يحتوي على جسم حقيقي
  • بين 0.3 و 0.7 → مُتجاهَل (Ignored) — تداخل غير واضح، يُستثنى من التدريب
  • IoU أقل من 0.3 → سلبي (Negative/Background) — يُعتبر خلفية بلا جسم

مثال رقمي محلول: صندوق حقيقي (Ground Truth) بحجم 200×200 = 40,000 بيكسل مربع. Anchor قريب جدًا منه يُعطي IoU ≈ 0.82 (إيجابي). Anchor متوسط التداخل يُعطي IoU ≈ 0.39 (مُتجاهَل). Anchor بعيد كليًا يُعطي IoU = 0.00 (سلبي). هذا يوضح سبب أهمية العتبات: الـ anchor القريب يُعلّم الشبكة شكل الجسم، والـ anchor البعيد يُعلّمها شكل الخلفية، والحالة الوسطى تُستبعد لأنها لا واضحة الصحة ولا واضحة الخطأ.


بعد التصنيف، يعمل رأسان على كل anchor:

  • رأس تصنيف RPN — يُخرج احتمالية p_object مقابل p_background لكل anchor
  • Bounding Box Regression — للـ anchors الإيجابية، يُعدّل الإحداثيات لتُصبح أكثر التصاقًا بالجسم الحقيقي

المصطلحات:

  • IoU (نسبة التقاطع على الاتحاد) — مقياس التداخل بين صندوقين
  • Ground Truth (الحقيقة الأرضية/الجسم الفعلي) — الصندوق الصحيح المُعلَّم يدويًا في بيانات التدريب
  • Positive/Negative Anchor (anchor إيجابي/سلبي)
  • p_object / p_background — احتمالية وجود جسم أو خلفية

SLIDES 10–12

8. Mask R-CNN — From Boxes to Pixel-Level Masks

Extending Faster R-CNN with instance segmentation

📋 Original Slide Content

Mask R-CNN (slide 10), Steps of Mask R-CNN (slide 11, diagram), and Mask R-CNN Architecture (slide 12, diagram) — these three slides together introduce Mask R-CNN as an extension of Faster R-CNN that adds a branch for predicting a pixel-level segmentation mask for each detected object, in addition to its class and bounding box.

🇬🇧 English Explanation
ENGLISH EXPLANATION

Mask R-CNN takes Faster R-CNN and adds one more capability: instead of just saying "there is a dog here, in this box," it also draws the exact pixel-level outline of the dog inside that box. This upgrades the task from object detection to instance segmentation — every individual object instance gets its own precise pixel mask, not just a rectangle.


Steps of Mask R-CNN (building on Faster R-CNN's 3 steps):

  1. Feature Extraction — same CNN backbone as Faster R-CNN produces a shared feature map.
  2. Region Proposal Network (RPN) — same as Faster R-CNN, proposes candidate object regions using anchor boxes.
  3. RoIAlign — extracts a fixed-size feature grid for each proposed region, similar in spirit to RoI Pooling but with an important precision fix (explained below).
  4. Classification + Box Regression head — identical to Faster R-CNN: what object is it, and where exactly is its box.
  5. Mask Head (the new branch) — a small convolutional network that runs in parallel with the classification/box head, outputting a small binary mask (e.g. 28×28) per class that marks exactly which pixels inside the box belong to the object.

RoIAlign vs. RoIPool — Why the Upgrade?

RoIPool (used in Fast/Faster R-CNN) snaps the region's boundaries to the nearest grid cell on the feature map — a process called quantization. For box classification this small misalignment barely matters. But for predicting a precise pixel mask, that same small misalignment causes visibly blurry, shifted masks.

RoIAlign avoids this by using bilinear interpolation to sample feature values at exact, non-quantized floating-point locations, instead of snapping to the nearest grid cell. This keeps spatial alignment between the input pixels and the extracted features precise — which matters enormously once you're trying to predict a mask at the individual-pixel level.


Mask R-CNN's architecture, visualized:

1CNN backbone → feature map
→
2RPN → region proposals
→
3RoIAlign (precision-preserving)
4aClassification + Box Regression head
+
4b (new!)Mask Head → per-pixel binary mask

The classification/box branch and the mask branch run in parallel, both fed from the same RoIAlign features — this is why Mask R-CNN is often described as adding "just one more head" to Faster R-CNN rather than being a completely new architecture.

🇸🇦 الشرح بالعربي

Mask R-CNN يأخذ Faster R-CNN ويُضيف قدرة جديدة: بدلًا من أن يقول فقط "يوجد كلب هنا داخل هذا الصندوق"، فإنه يرسم أيضًا الحدود الدقيقة على مستوى البيكسل لهذا الكلب داخل الصندوق. هذا يُرقّي المهمة من كشف الأجسام (object detection) إلى تجزئة الحالات (instance segmentation) — كل جسم فردي يحصل على قناع بيكسلي دقيق خاص به، وليس فقط مستطيلًا.


خطوات Mask R-CNN (بناءً على خطوات Faster R-CNN الثلاث):

  1. استخراج الميزات — نفس عمود CNN في Faster R-CNN يُنتج خريطة ميزات مشتركة.
  2. RPN — نفس الفكرة، تُقترح مناطق باستخدام anchor boxes.
  3. RoIAlign — يستخرج شبكة ميزات بحجم ثابت لكل منطقة، بشكل مشابه لـ RoI Pooling لكن مع إصلاح دقيق مهم (مُوضّح أدناه).
  4. رأس التصنيف + Box Regression — مطابق لـ Faster R-CNN: ما هو الجسم، وأين موقعه الدقيق.
  5. رأس القناع (الفرع الجديد) — شبكة التفافية صغيرة تعمل بالتوازي مع رأس التصنيف، تُخرج قناعًا ثنائيًا صغيرًا (مثل 28×28) لكل تصنيف يُحدد بالضبط أي بيكسلات داخل الصندوق تنتمي للجسم.

RoIAlign مقابل RoIPool — لماذا هذا التطوير؟

RoIPool (المستخدم في Fast/Faster R-CNN) يُقرِّب حدود المنطقة إلى أقرب خلية شبكية على خريطة الميزات — عملية تُسمى quantization (التكميم). بالنسبة لتصنيف الصندوق، هذا الخطأ الصغير في المحاذاة لا يُهم كثيرًا. لكن لتوقع قناع بيكسلي دقيق، يتسبب نفس الخطأ الصغير في أقنعة ضبابية ومُنزلقة بشكل واضح.

RoIAlign يتجنب هذه المشكلة باستخدام الاستيفاء الثنائي الخطي (bilinear interpolation) لأخذ قيم الميزات عند مواضع دقيقة (غير مُقرَّبة)، بدلًا من التقريب لأقرب خلية شبكية. هذا يحافظ على محاذاة مكانية دقيقة بين بيكسلات الصورة الأصلية والميزات المُستخرجة — وهو أمر بالغ الأهمية عند محاولة توقع قناع على مستوى البيكسل الفردي.


فرعا التصنيف/الصندوق وفرع القناع يعملان بالتوازي، وكلاهما يستمد من نفس ميزات RoIAlign — لهذا يُوصف Mask R-CNN غالبًا بأنه "إضافة رأس واحد فقط" فوق Faster R-CNN، لا بنية جديدة تمامًا.


المصطلحات:

  • Instance Segmentation (تجزئة الحالات) — قناع بيكسلي منفصل لكل جسم فردي
  • Mask Head (رأس القناع) — الفرع الجديد الذي يُنتج القناع
  • RoIAlign — نسخة محسّنة ودقيقة من RoI Pooling
  • Quantization (التكميم) — تقريب موقع إلى أقرب خلية شبكية، مصدر خطأ في RoIPool
  • Bilinear Interpolation (استيفاء ثنائي خطي) — طريقة حساب دقيقة تتجنب التقريب
💡 Example — Detection vs. Instance Segmentation

Faster R-CNN output: "Dog: box (120,80)–(340,290)" — a rectangle that includes some background (grass, sky) inside its corners.

Mask R-CNN output: the same box, PLUS a precise silhouette mask that colors exactly the dog-shaped pixels inside that box and leaves the background pixels (inside the same rectangle) uncolored — useful for things like removing the background behind the dog in a photo editor, or letting a robot know exactly which pixels it can safely grasp.

🎓 Exam Notes
  • 📌 Mask R-CNN = Faster R-CNN + a parallel mask-prediction branch = instance segmentation
  • 📌 RoIAlign replaces RoIPool specifically to fix pixel misalignment caused by quantization
  • 📌 The mask head, classification head, and box regression head all run in parallel from the same RoIAlign features
  • 📌 Common exam Q: "Why can't Mask R-CNN just use RoIPool?" → Quantization misalignment is tolerable for boxes but destroys mask precision

Mask R-CNN extends Faster R-CNN with a parallel mask-prediction branch fed by RoIAlign (instead of RoIPool, which loses precision to quantization). The result: for every detected object you get a class, a refined bounding box, AND a pixel-accurate segmentation mask — i.e. instance segmentation.

9. The Full Evolution: R-CNN → Fast R-CNN → Faster R-CNN → Mask R-CNN

Tying the whole family tree together — what changed at each step, and why

📋 Original Slide Content

This section is a capstone synthesis, not a single slide — it consolidates the four models covered across slides 2–12 into one comparison so the evolution is easy to hold in memory before moving on to Detectron2.

🇬🇧 English Explanation
ENGLISH EXPLANATION

Each model in this family fixed exactly one weakness of the model before it. Seeing them side by side makes the whole story click:

ModelRegion Proposals# CNN Passes / ImageClassifierOutputRelative Speed
R-CNNSelective Search (external, classical)~2000 (one per region)Separate SVMClass + boxVery slow
Fast R-CNNSelective Search (external, classical)1 shared pass + RoI PoolingSoftmax (in-network)Class + boxMuch faster (~10x+)

The two big turning points to remember:

Turning Point 1 — Fast R-CNN

  • Fixed: redundant CNN computation
  • How: 1 shared feature map instead of ~2000 CNN passes
  • Also folded SVM into the network as a softmax layer

Turning Point 2 — Faster R-CNN

  • Fixed: slow, non-learnable, external proposal generation
  • How: RPN — a tiny learnable network using anchor boxes
  • Region proposals now trained jointly with the whole network

And the third turning point — Mask R-CNN doesn't fix a weakness so much as extend the capability: it adds pixel-level output on top of an already-fast, already-learnable pipeline, made precise thanks to RoIAlign.

  • R-CNN: Selective Search خارجي + ~2000 تشغيل CNN + SVM منفصل → بطيء جدًا
  • Fast R-CNN: نفس Selective Search + تشغيل CNN واحد مشترك + softmax داخلية → أسرع بكثير
  • Faster R-CNN: RPN داخلية قابلة للتعلم (تعتمد على anchor boxes) بدلًا من Selective Search → قريب من الوقت الفعلي
  • Mask R-CNN: نفس RPN + RoIAlign بدلًا من RoI Pooling + رأس قناع جديد → يُخرج قناعًا بيكسليًا بالإضافة للصندوق والتصنيف

نقطتا التحول الكبيرتان:

التحول الأول (Fast R-CNN): حلّ مشكلة الحساب المُكرر — عبر خريطة ميزات مشتركة واحدة بدلًا من ~2000 تشغيل CNN، ودمج SVM كطبقة softmax داخل الشبكة.

التحول الثاني (Faster R-CNN): حلّ مشكلة توليد المقترحات البطيء غير القابل للتعلم — عبر RPN، شبكة صغيرة قابلة للتعلم تعتمد على anchor boxes، تُدرَّب مع باقي الشبكة معًا.

التحول الثالث (Mask R-CNN): لا يُصلح نقطة ضعف بقدر ما يُوسّع القدرة — يُضيف مخرجًا على مستوى البيكسل فوق خط أنابيب سريع وقابل للتعلم بالفعل، بدقة عالية بفضل RoIAlign.

  • 🎭 Mask R-CNN: "Also tell me exactly which pixels belong to the object."

11. Training Detectron2 on a Custom Dataset (COCO Format)

📋 Original Slide Content

Train Detectron2 On A Custom Dataset

The COCO dataset is formatted in JSON and has five annotation types: object detection, keypoint detection, stuff segmentation, panoptic segmentation, and image captioning. It is a collection of "info", "licenses", "images", "annotations", "categories" (in most cases), and "segment info" (in one case).

🇬🇧 English Explanation
ENGLISH EXPLANATION

Detectron2's built-in data loaders are designed around the COCO dataset format. So before you can train any Detectron2 model (Faster R-CNN, Mask R-CNN, etc.) on your own images, the very first practical step is: convert your custom dataset's annotations into COCO's JSON structure.


COCO supports five annotation types:

  • 📦 Object Detection — bounding boxes + class labels
  • 🕺 Keypoint Detection — labeled body/joint keypoints (e.g. for pose estimation)
  • 🌫️ Stuff Segmentation — pixel labels for background/texture regions (sky, grass, wall) rather than distinct countable objects
  • 🧩 Panoptic Segmentation — combines instance segmentation (countable objects, each with its own mask) with stuff segmentation (background regions) into one unified labeling
  • 📝 Image Captioning — natural-language text descriptions paired with images

Every COCO-format JSON file is built from these top-level sections:

  • ℹ️ info — metadata about the dataset itself (description, version, contributor)
  • 📜 licenses — license info for the images used
  • 🖼️ images — a list of image entries, each with an id, filename, width, height
  • 🏷️ annotations — the actual labels: for each object, its image_id, category_id, bounding box, and/or segmentation polygon/mask
  • 📂 categories — the list of class names and their ids (present in most annotation types)
  • 🧩 segment_info — extra per-segment metadata used specifically for panoptic segmentation (present in that one annotation type)

A simplified example of the COCO JSON structure:

{
  "info": {
    "description": "My Custom Dataset",
    "version": "1.0"
  },
  "licenses": [
    { "id": 1, "name": "CC-BY-4.0" }
  ],
  "images": [
    { "id": 1, "file_name": "img_001.jpg", "width": 640, "height": 480 }
  ],
  "annotations": [
    {
      "id": 1,
      "image_id": 1,
      "category_id": 2,
      "bbox": [x, y, width, height],
      "segmentation": [[x1, y1, x2, y2, x3, y3, ...]],
      "area": 15234,
      "iscrowd": 0
    }
  ],
  "categories": [
    { "id": 1, "name": "cat" },
    { "id": 2, "name": "dog" }
  ]
}

Once this JSON (plus the actual image files) exists, Detectron2's register_coco_instances() utility can load the dataset directly, and standard training configs (e.g. a Mask R-CNN config from the Model Zoo) can be pointed at it for fine-tuning with almost no extra code.

Q1. In R-CNN, roughly how many times is the CNN run per image?

  • A) Once

Q2. What is the main innovation that makes Fast R-CNN faster than R-CNN?

  • A) It uses fewer region proposals
  • B) It runs the CNN once on the whole image and shares the resulting feature map across all region proposals
  • C) It removes the bounding box regressor
  • D) It uses anchor boxes instead of Selective Search
✅ Answer: B — Fast R-CNN computes one shared convolutional feature map for the whole image, then uses RoI Pooling to extract per-region features from it, avoiding redundant CNN passes.

Q3. What does the Region Proposal Network (RPN) in Faster R-CNN replace?

  • A) The CNN backbone
  • B) RoI Pooling
  • C) Selective Search
  • D) The softmax classifier
✅ Answer: C — The RPN is a small learnable neural network that replaces the slow, external, classical Selective Search algorithm for generating region proposals.

Q4. An anchor box is best described as:

  • A) The final, fully-refined bounding box output by the model
  • B) A predefined rectangle shape (scale + aspect ratio) placed at a fixed location, used as a reference/starting point for proposals
  • C) A pixel-level segmentation mask
  • D) A region generated by Selective Search
✅ Answer: B — Anchor boxes are predefined shapes (combinations of scale and aspect ratio) placed at every location on the feature map; the RPN uses k of them per location.

  • B) Negative (background) anchor
  • C) Ignored anchor

Q6. What is the key reason Mask R-CNN uses RoIAlign instead of RoIPool?

  • A) RoIAlign is faster to compute
  • B) RoIAlign requires no ground-truth labels
  • C) RoIAlign avoids the quantization misalignment that would blur pixel-level mask predictions
  • D) RoIAlign replaces the need for a CNN backbone
✅ Answer: C — RoIPool snaps region boundaries to the nearest feature-map grid cell (quantization), which is tolerable for box classification but degrades pixel-precise mask prediction. RoIAlign uses bilinear interpolation to avoid this.

📖 Short Answer Questions

Answer: R-CNN uses Selective Search to generate ~2000 region proposals and runs a full CNN on each one separately, then classifies with an SVM and refines the box with a linear regressor — accurate but extremely slow due to ~2000 redundant CNN passes. Fast R-CNN fixes the redundancy by running the CNN once over the whole image to get a shared feature map, using RoI Pooling to extract per-region features, and replacing the SVM with an in-network softmax layer for end-to-end training — but it still depends on the slow, non-learnable Selective Search for proposals. Faster R-CNN fixes that remaining bottleneck by replacing Selective Search with a Region Proposal Network (RPN) — a small learnable neural network that proposes regions using k anchor boxes at each feature-map location, trained jointly with the rest of the model, making the whole pipeline learnable and near real-time. Mask R-CNN extends Faster R-CNN by adding a parallel mask-prediction branch (fed by RoIAlign instead of RoIPool for pixel-precision) so that, in addition to a class and a bounding box, each detected object also gets a precise pixel-level segmentation mask — upgrading the task to instance segmentation.

Answer: An anchor box is a predefined rectangle shape — a specific combination of scale (small/medium/large) and aspect ratio (e.g. 1:1, 2:1, 1:2) — placed at a fixed location on the feature map, used as a reference starting shape that the RPN tests against the underlying image content. "k anchor boxes" means the RPN uses k different predefined shapes at every single location on the feature map (a common setup is k=9, from 3 scales × 3 aspect ratios), so it can propose objects of many different sizes and shapes at once, all from the same location.

Answer: The RPN computes the Intersection over Union (IoU) between each anchor box and the nearest ground-truth object box: IoU = overlap area ÷ union area, ranging from 0 to 1. If IoU > 0.7, the anchor is labeled positive (it contains an object). If IoU < 0.3, the anchor is labeled negative (background). Anchors with IoU between 0.3 and 0.7 are ignored during training because their status is ambiguous and would introduce noisy training signal. The RPN's classification head then learns to output p_object vs p_background for every anchor, and bounding box regression further refines the coordinates of positive anchors to tightly fit the actual object.

Answer: RoI Pooling snaps a region's boundaries to the nearest cell on the discrete feature-map grid — a process called quantization. For classifying "what object is roughly in this box," that small misalignment barely matters. But predicting a pixel-accurate segmentation mask requires precise spatial correspondence between input pixels and extracted features; the same small misalignment that's harmless for classification produces visibly blurry, shifted masks. RoIAlign solves this by using bilinear interpolation to sample feature values at exact, non-quantized locations, preserving the spatial alignment needed for accurate per-pixel mask prediction.
