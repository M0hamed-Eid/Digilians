1. RNN Recap & Its Problems

Why the Transformer was invented — bridging from Lecture 18's self-attention introduction

📋 Original Slide Content

Slide 2 — Recurrent Neural Networks (RNN): A diagram shows a chain of RNN cells across Time Step 1, 2, 3 ... N. Each cell receives an input X_t and the hidden State from the previous cell, and produces an output Y_t. The state (labelled State<0> initially) is passed forward step by step.


Slide 3 — Problems with RNN (among others):

  • Slow computation for long sequences
  • Vanishing or exploding gradients
  • Difficulty in accessing information from long time ago

Slide 4 — Introducing the Transformer: Section-break slide announcing the architecture that solves these three problems.

🇬🇧 English Explanation
ENGLISH EXPLANATION

In Lecture 18 we introduced self-attention as the mechanism that lets a model relate every word to every other word directly. Before that mechanism existed, sequence models relied on Recurrent Neural Networks (RNNs): a chain of identical cells that process one token at a time, each cell passing a hidden state forward to the next time step.


Picture reading a sentence word by word, but you're only allowed to remember a single running summary in your head, and you must update that summary after every word before you're allowed to see the next one. That is exactly how an RNN works: State<0> feeds RNN cell 1 together with X1, producing Y1 and a new state; that new state feeds cell 2 together with X2, and so on until XN.


This design causes three concrete problems:

1. Slow computation for long sequences

Because each time step depends on the output of the previous one, the cells cannot be processed in parallel. A sentence of 1,000 tokens requires 1,000 sequential steps — there is no way to compute step 500 before step 499 finishes.

2. Vanishing or exploding gradients

During backpropagation, the gradient signal has to flow backward through every one of those time steps. Multiplying many numbers together repeatedly either shrinks the gradient toward zero (vanishing) or blows it up toward infinity (exploding), making the network very hard to train on long sequences.

3. Difficulty accessing information from long ago

Because everything the model "remembers" about earlier words has to be squeezed into one fixed-size hidden state, information from the start of a long sequence gets diluted or overwritten by the time the model reaches the end.

The Transformer architecture was introduced specifically to solve all three problems at once: it processes the whole sequence in parallel (no sequential dependency), it lets any word attend directly to any other word regardless of distance (no gradient has to travel through hundreds of intermediate steps), and it has no fixed-size bottleneck state. The rest of this lecture builds the machinery that makes this possible: input embeddings, positional encoding, self-attention, multi-head attention, layer normalization, and the masked attention used in the decoder.

المشاكل الثلاث في RNN:

  • 🐢 حساب بطيء (Slow computation) — لأن كل خطوة تعتمد على الخطوة السابقة، لا يمكن معالجة الخلايا بالتوازي (parallel)، فجملة من 1000 token تحتاج 1000 خطوة متتالية.
  • 📉 تلاشي أو انفجار المشتقات (Vanishing/Exploding Gradients) — عند التدريب backpropagation، يمر التدرج (gradient) عبر كل خطوة زمنية، وضربه المتكرر يجعله يقترب من الصفر أو يتضخم جدًا.
  • 🧩 صعوبة الوصول لمعلومات قديمة — كل ما يتذكره النموذج عن الكلمات الأولى مضغوط في حالة (state) واحدة ثابتة الحجم، فتضيع المعلومات القديمة مع تقدم الجملة.

جاء Transformer ليحل الثلاث مشاكل معًا: يعالج الجملة كاملة بالتوازي، ويسمح لأي كلمة بالانتباه (attend) لأي كلمة أخرى بدون قيود المسافة، وليس له "عنق زجاجة" (bottleneck) بحجم ثابت.

المصطلحات المهمة: RNN شبكة تكرارية، Hidden State حالة مخفية، Backpropagation الانتشار العكسي، Parallel Processing معالجة متوازية.

🐢 RNN Problem #1 — Speed

  • Sequential, one token at a time
  • Cannot parallelize training
  • Long sequences = very slow

📉 RNN Problem #2 — Gradients

  • Gradient flows through every time step
  • Repeated multiplication → vanish or explode
  • Hard to train on long text

🧩 RNN Problem #3 — Long-Range Memory

  • Fixed-size hidden state bottleneck
  • Old information gets overwritten
  • Poor for long documents

⚡ Transformer's Fix

  • Parallel processing of the whole sequence
  • Direct attention between any two words
  • No fixed-size bottleneck state

RNNs process sequences one token at a time via a chained hidden state, causing three problems: slow sequential computation, vanishing/exploding gradients, and difficulty accessing distant information. The Transformer was introduced to solve all three via parallel processing and direct attention between all word pairs.

2. Input Embeddings

Turning tokens into dense numeric vectors the model can compute with

📋 Original Slide Content

Slide 5 — Notations: Input matrix has shape (seq, d_model).


Slide 6/8 — Encoder: Section-break slides positioning embeddings inside the encoder block.


Slide 7 — What is an input embedding? Original sentence: YOUR CAT IS A LOVELY CAT. Each word is mapped to an Input ID (its position in the vocabulary), e.g. YOUR→105, CAT→6587, IS→5475, A→3578, LOVELY→65, CAT→6587 (repeated word gets the same ID). Each Input ID is then mapped to an Embedding — a vector of size 512 of numbers (example values shown like 952.207, 5450.840, 1853.448 ... 1.658, 2671.529). "We define d_model = 512, which represents the size of the embedding vector of each word."

🇬🇧 English Explanation
ENGLISH EXPLANATION

Neural networks cannot operate on raw text — they only understand numbers. The Input Embedding step is the very first step of the pipeline, and it happens in two stages:

  1. Tokenization → Input IDs: The sentence YOUR CAT IS A LOVELY CAT is split into tokens (here, whole words). Each token is looked up in a fixed vocabulary and replaced by its Input ID — simply the position of that word in the vocabulary list. Note that the word CAT appears twice and gets the exact same Input ID (6587) both times, because it's the same vocabulary entry.
  2. Input IDs → Embeddings: Each Input ID is then mapped, through a learned embedding table, to a dense vector of d_model = 512 numbers. This vector is the word's numeric "meaning fingerprint" — words with similar meaning end up with numerically similar vectors after training.
Input ID (integer)  →  Embedding lookup  →  vector of size d_model = 512

Important nuance: at this stage, the embedding for CAT is identical both times it appears in the sentence — the raw embedding only encodes the word's meaning, not its position or its relationship to neighboring words. That's exactly the gap that Positional Encoding (next section) and Self-Attention (Section 4) exist to fill.

⚠️ Common Misconception

Embeddings are not one-hot vectors. A one-hot vector for a 10,000-word vocabulary would be 10,000-dimensional and mostly zeros; the embedding is a dense, learned, 512-dimensional vector with meaningful numeric values throughout.

SLIDES 9–12

3. Positional Encoding

Injecting order information into position-blind embeddings using sine and cosine waves

📋 Original Slide Content

Slide 9 — What is positional encoding? Three requirements: (1) we want each word to carry information about its position in the sentence; (2) we want the model to treat words that appear close to each other as "close" and words that are distant as "distant"; (3) we want the positional encoding to represent a pattern that can be learned by the model.


Slide 10: The 512-d embedding of each word is added (+) element-wise to a 512-d Positional Encoding vector, giving the final Encoder Input (also 512-d). Note: "Position Embedding is only computed once and reused for every sentence during training and inference."


Slide 11 — Formulas:

PE(pos, 2i) = sin( pos / 10000(2i / d_model) )
PE(pos, 2i + 1) = cos( pos / 10000(2i / d_model) )

"We only need to compute the positional encodings once and then reuse them for every sentence, no matter if it is training or inference."


Slide 12 — Why trigonometric functions? "Trigonometric functions like cos and sin naturally represent a pattern that the model can recognize as continuous, so relative positions are easier to see for the model. By watching the plot of these functions, we can also see a regular pattern, so we can hypothesize that the model will see it too."

🇬🇧 English Explanation
ENGLISH EXPLANATION

The embedding from Section 2 tells the model what a word means, but not where it sits in the sentence. Since both occurrences of CAT get the same embedding, the model on its own cannot tell "first CAT" from "second CAT". Positional Encoding fixes this by adding a second, position-dependent vector to every word's embedding.


Why we need it — 3 requirements from the slide:

  • 📍 Each word must carry information about its own position in the sentence
  • 📏 The encoding should make the model treat nearby words as "close" and far-apart words as "distant" (a notion of relative distance)
  • 🔁 The pattern must be something the model can actually learn and generalize over

The exact formulas:

PE(pos, 2i) = sin( pos / 10000(2i / d_model) )
PE(pos, 2i + 1) = cos( pos / 10000(2i / d_model) )
Symbol meanings
  • pos — the position of the word in the sentence (0, 1, 2, 3, ...)
  • i — the index of the pair of dimensions inside the 512-length vector (each pair of dimensions gets one sine and one cosine value)
  • d_model — the embedding size, 512
  • Even dimensions (2i) use sin; odd dimensions (2i+1) use cos — so the 512-d positional vector alternates sin, cos, sin, cos, ...

The resulting 512-d Positional Encoding vector is added element-wise to the 512-d word embedding, producing the final Encoder Input (still 512-d): Encoder Input = Embedding + Positional Encoding.


Why sine and cosine specifically?

  • 📈 They are smooth and continuous functions — nearby positions produce nearby encoding values, which naturally gives the model a sense of relative closeness
  • 🔄 They produce a regular, repeating pattern — the model can recognize and generalize this pattern rather than memorizing arbitrary numbers
  • ♻️ Positional encodings are computed once (they don't depend on the actual words, only on position) and then reused for every sentence, during both training and inference — this is a fixed lookup table, not something the model learns from scratch each time

لماذا sin و cos بالتحديد؟

  • 🌊 دوال ملساء ومستمرة (continuous) — المواضع القريبة تعطي قيم قريبة، فيفهم النموذج القرب النسبي بشكل طبيعي
  • 🔄 تعطي نمطًا منتظمًا يتكرر — يسهل على النموذج تعلّمه والتعميم عليه
  • ♻️ تُحسب مرة واحدة فقط (لا تعتمد على الكلمات نفسها، بل على الموضع فقط) وتُعاد استخدامها لكل جملة أثناء training و inference

💡 Worked Example — Two Sentences Reusing the Same Table

Sentence 1: YOUR CAT IS uses PE(0,·), PE(1,·), PE(2,·) for its three positions.

Sentence 2: I LOVE YOU uses the exact same PE(0,·), PE(1,·), PE(2,·) — because Positional Encoding only depends on the position index, never on which word occupies that position. This is why the table is "computed once and reused for every sentence."

🧠 Memory Trick — Even/Odd Split

"Sine on the even seats, cosine on the odd seats."

Dimension index 0,2,4,... → sin. Dimension index 1,3,5,... → cos. Together they tile the whole 512-length vector.

🎓 Exam Notes
  • 📌 Memorize both formulas exactly, including which uses sin vs cos and the 10000^(2i/d_model) denominator
  • 📌 Positional encoding is added, not concatenated, to the embedding
  • 📌 It is fixed/precomputed — not a learnable parameter in the original design — and reused across all sentences
  • 📌 3 design requirements: carries position, encodes relative closeness, forms a learnable pattern

Positional Encoding adds position information to embeddings using fixed sin/cos formulas over even/odd dimensions of the 512-d vector. It is computed once, reused for every sentence, and gives the model a continuous, learnable sense of word order and relative distance.

4. Self-Attention Mechanics

The core formula — how words look at each other

📋 Original Slide Content

Slide 14 — What is Self-Attention? "Self-Attention allows the model to relate words to each other." Formula: Attention(Q,K,V) = softmax(QK^T/√d_k)·V. seq=6, d_model=d_k=512 in this simplified single-head example; Q, K, V are all just the input sentence. A 6×6 example matrix is shown for "YOUR CAT IS A LOVELY CAT" with each row summing to 1 (softmax rows), values are random for illustration.


Slide 15 — How to compute Self-Attention? The (6,6) softmax(QK^T/√d_k) matrix multiplies V (6,512) to give the final Attention output (6,512). "Each row in this matrix captures not only the meaning (given by the embedding) or the position in the sentence (represented by the positional encodings) but also each word's interaction with other words."


Slide 16 — Self-Attention in detail: (1) Self-Attention is permutation invariant. (2) Self-Attention requires no parameters — up to now the interaction between words has been driven only by their embedding and positional encodings; this will change later (with multi-head attention's learned projections). (3) We expect values along the diagonal to be the highest. (4) If we don't want some positions to interact, we can set their values to −∞ before applying softmax, and the model will not learn those interactions — used later in the decoder.

🇬🇧 English Explanation
ENGLISH EXPLANATION

Self-Attention lets every word "look at" every other word in the same sentence and decide how much attention to pay to each one. The formula is:

Attention(Q, K, V) = softmax( QKT / √dk ) · V

In this simplified example, sequence length seq = 6 and d_model = d_k = 512 (single head, so d_k = d_model). Crucially, Q, K, and V are all just the input sentence itself at this stage — there are no learned weight matrices yet.


Step by step:

  1. Multiply Q (6, 512) by KT (512, 6) → a (6, 6) matrix of raw similarity scores between every pair of words
  2. Divide by √d_k (a scaling factor that keeps numbers in a stable range for softmax)
  3. Apply softmax row-wise → each row now sums to 1, becoming an "attention-weight" distribution
  4. Multiply this (6, 6) attention-weight matrix by V (6, 512) → final Attention output (6, 512)

Reading the 6×6 matrix for "YOUR CAT IS A LOVELY CAT": the cell at row X, column Y represents "how much word X should attend to (borrow information from) word Y." For example the row for CAT has a value against every column including itself and every other word; the row values sum to 1.

Key properties (from Slide 16):

  • 🔁 Permutation invariant — if you shuffle the input word order, the attention computation itself doesn't inherently know about order (this is exactly why Positional Encoding from Section 3 is essential)

Self-Attention تسمح لكل كلمة بـ"النظر" إلى كل الكلمات الأخرى في الجملة وتحديد كم من الانتباه (attention) تعطيه لكل واحدة. الصيغة:

Attention(Q, K, V) = softmax( QKT / √dk ) · V

في هذا المثال المبسط: seq = 6 و d_model = d_k = 512 (رأس واحد فقط، لذلك d_k = d_model). المهم: Q و K و V هي جملة الدخل نفسها في هذه المرحلة، بدون أي مصفوفات أوزان متعلَّمة (weights).


الخطوات:

  1. ضرب Q (6, 512) في KT (512, 6) → مصفوفة (6, 6) من درجات التشابه الخام بين كل زوج كلمات
  2. القسمة على √d_k (عامل تقييس يحافظ على استقرار القيم قبل softmax)
  3. تطبيق softmax على كل صف → يصبح مجموع كل صف = 1 (توزيع أوزان انتباه)
  4. ضرب مصفوفة الأوزان (6, 6) في V (6, 512) → ناتج الـAttention النهائي (6, 512)

كل خلية في المصفوفة تمثّل "كم يجب أن تنتبه الكلمة X للكلمة Y". القيم على القطر (diagonal) هي الأعلى عادة لأن كل كلمة ترتبط بنفسها أكثر من غيرها.


الخصائص الأساسية:

  • 🔁 لا تتأثر بالترتيب (Permutation Invariant) — لو بدّلنا ترتيب الكلمات، الحساب نفسه لا يعرف الترتيب تلقائيًا، ولهذا نحتاج Positional Encoding
  • 🧮 لا تحتاج parameters بذاتها — في هذه المرحلة الخام، التفاعل بين الكلمات يعتمد فقط على الـembeddings والـpositional encodings، وليس على أوزان مُدرَّبة
  • 🎯 القطر (diagonal) هو الأعلى غالبًا — كل كلمة ترتبط بنفسها أكثر
  • 🚫 يمكن إخفاء (mask) بعض التفاعلات — بجعل قيمتها −∞ قبل softmax فتصبح صفرًا، وهذا يُستخدم لاحقًا في الـdecoder

5. Multi-Head Attention

Running several attention "views" in parallel and combining them

📋 Original Slide Content

🇬🇧 English Explanation
ENGLISH EXPLANATION

Plain self-attention (Section 4) has no learnable parameters and only produces one attention pattern per layer. Multi-Head Attention fixes both limitations: it introduces learned weight matrices and computes several different attention patterns in parallel, one per "head".

MultiHead(Q, K, V) = Concat(head1, ..., headh) · WO
headi = Attention(Q·WiQ, K·WiK, V·WiV)

Step by step:

  1. The input Q, K, V (each shape (seq, d_model)) are each multiplied by their own learned weight matrix W^Q, W^K, W^V (each (d_model, d_model)), giving Q', K', V'
  2. Each of Q', K', V' is split along the d_model dimension into h equal slices — one slice per head, each of shape (seq, d_k)
  3. Ordinary self-attention (from Section 4) is computed independently inside each head, producing an output of shape (seq, d_v) per head
  4. All h head outputs are concatenated back together into shape (seq, h·d_v)
  5. The concatenated result is multiplied by one more learned matrix W^O of shape (h·d_v, d_model), producing the final Multi-Head Attention output of shape (seq, d_model)

seqsequence length (number of tokens)
d_modelsize of the embedding vector (512 in the paper)
hnumber of attention heads
d_k = d_vd_model / h — the per-head dimensionality

Why multiple heads? A single attention pattern forces the model to compress every kind of relationship — grammar, meaning, coreference, position — into one shared view. Multiple heads let each head specialize: one head might learn to track subject-verb agreement, another might track which pronoun refers to which noun, another might focus on adjacent-word relationships. It's analogous to reading a sentence multiple times, each time focusing on a different aspect — once for grammar, once for overall meaning, once for who-refers-to-whom — and then combining all those readings into one richer understanding.

The names Query, Key, and Value come from database and dictionary terminology. Think of a Python dictionary or a lookup table where Keys and Values form pairs, similar to a movie recommendation table:

Now suppose someone issues the Query = "love". Even though "love" doesn't exactly match any Key literally, it is semantically closest to ROMANTIC — so the lookup returns TITANIC. The three roles

  • Key — a label each word advertises about itself, used to be matched against incoming queries
  • Value — the actual content/information that gets retrieved and passed forward when a Key matches well

In self-attention, every word simultaneously plays all three roles: it emits a Query (what it wants to know), a Key (what it offers to be matched against), and a Value (what it actually contributes if chosen).

7. Layer Normalization

Stabilizing activations, item by item, feature by feature

📋 Original Slide Content

Slide 22 — What is layer normalization? Diagram: a batch of 3 items, each item has its own mean μ and variance σ². Formula: x̂_j = (x_j − μ_j) / √(σ²_j + ε). "We also introduce two parameters, usually called gamma (multiplicative) and beta (additive) that introduce some fluctuations in the data, because maybe having all values between 0 and 1 may be too restrictive for the network. The network will learn to tune these two parameters to introduce fluctuations when necessary."

🇬🇧 English Explanation
ENGLISH EXPLANATION

Layer Normalization stabilizes training by re-scaling the numbers flowing through the network so they stay in a well-behaved range. Unlike Batch Normalization (which normalizes across a batch of examples for a given feature), Layer Norm normalizes each individual item across its own features — each of the 3 items in the batch gets its own mean μ and its own variance σ², computed only from that item's own values.

x̂j = ( xj − μ ) / √( σ² + ε )

Here x_j is one feature value of the item, μ and σ² are the mean and variance computed across all features of that same item, and ε (epsilon) is a tiny constant added to avoid dividing by zero.


Why it's needed: deep networks stack many layers; without normalization, the scale of activations can drift wildly from layer to layer, making training unstable and slow. Layer Norm keeps every item's features centered around 0 with unit variance, which stabilizes gradients and speeds up convergence.


The role of gamma (γ) and beta (β): after normalizing to mean 0 / variance 1, the network multiplies by a learnable γ (gamma, multiplicative) and adds a learnable β (beta, additive): y_j = γ·x̂_j + β. Why? Forcing every value into a strict [roughly -1, 1]-ish normalized range might be too restrictive for what the network actually needs downstream. Gamma and beta let the network learn to re-introduce useful fluctuations — effectively giving it permission to "undo" some of the normalization exactly where that helps performance, while still enjoying stable training.

8. Masked Multi-Head Attention (Decoder)

Making the decoder causal — no peeking at future words

📋 Original Slide Content

Slide 24 — What is Masked Multi-Head Attention? "Our goal is to make the model causal: it means the output at a certain position can only depend on the words on the previous positions. The model must not be able to see future words." A 6×6 attention matrix for "YOUR CAT IS A LOVELY CAT" is shown as the starting point.


Slide 25: The same Q·W^Q, K·W^K, V·W^V multi-head pipeline as Section 5, but with one addition: "All the values above the diagonal are replaced with −∞ before applying the softmax, which will replace them with zero."

🇬🇧 English Explanation
ENGLISH EXPLANATION

The decoder generates output one word at a time and must never be allowed to "cheat" by seeing words it hasn't generated yet. This requirement is called being causal: the output at position i can only depend on positions ≤ i, never on positions after it.


How masking implements this: we start from the same multi-head attention pipeline as Section 5 (Q·W^Q, K·W^K, V·W^V, split into heads, softmax(QK^T/√d_k), etc.), but right before applying softmax to the (seq, seq) score matrix, we set every value above the main diagonal to −∞.

scores[i][j] = −∞   for all j > i  (before softmax)

Since softmax(−∞) = 0, after softmax those upper-triangular positions become exactly 0 — meaning word i receives zero attention weight toward any word j that comes after it. Only positions on or below the diagonal (j ≤ i, i.e. the current word and everything before it) can contribute.


Why does the decoder need this but the encoder doesn't? The encoder sees the entire input sentence at once and is meant to build a rich, bidirectional representation — there is no "future" to hide because the whole sentence is already fully available (e.g. translating "I love you very much", the encoder can freely look at the whole English sentence). The decoder, however, is generating the output sequence step-by-step during inference, and even during training, we want it to learn to predict each word using only what came before — otherwise it would trivially "cheat" by peeking at the answer, and it would fail at real inference time when future words genuinely don't exist yet. Masking during training exactly simulates the information available during real autoregressive inference.

9. Training the Full Transformer

Teacher forcing, shifted-right inputs, and one-shot parallel loss computation

📋 Original Slide Content

Slide 27 — Training: Example machine translation task, English → Italian: I love you very much → Ti amo molto.


Slide 28: Encoder Input (seq, d_model) = <SOS> I love you very much <EOS>. Decoder Input (seq, d_model) = <SOS> Ti amo molto. "We prepend the <SOS> token at the beginning. "It all happens in one time step! The encoder outputs, for each word a vector that not only captures its meaning (the embedding) or the position, but also its interaction with other words by means of the multi-head attention."

🇬🇧 English Explanation
ENGLISH EXPLANATION

Now we assemble everything into the full encoder-decoder Transformer and train it on a machine translation task: English I love you very much → Italian Ti amo molto.


Encoder side: the source sentence, wrapped with <SOS> and <EOS> tokens, becomes the Encoder Input: <SOS> I love you very much <EOS>. It passes through embeddings, positional encoding, and (unmasked, bidirectional) multi-head self-attention layers, producing an Encoder Output where each position's vector captures meaning, position, and interaction with every other word in the source sentence.


Decoder side and teacher forcing: instead of feeding the decoder one word at a time and waiting for it to generate the next, during training we feed it the entire target sequence at once, prepended with <SOS>: <SOS> Ti amo molto. This technique is called teacher forcing — we "force" the correct previous words as decoder input rather than the model's own (possibly wrong) previous predictions.

Decoder Input = <SOS> + target sequence  (shifted right by one position)

Because the target sequence is prepended with <SOS>, every position in the decoder input is effectively the previous position of the true target — this is exactly why the original paper describes the decoder input as "shifted right".


Computing the loss: the decoder output (seq, d_model) passes through a Linear layer to project it to (seq, vocab_size), then a Softmax turns each position into a probability distribution over the vocabulary. This is compared against the true label Ti amo molto <EOS> using Cross-Entropy Loss.

⚡ Why training is fast

Thanks to the causal mask from Section 8, the decoder can process the entire target sequence in a single forward pass — one time step, computed fully in parallel — while still guaranteeing that the prediction at each position only used information from earlier positions. This is a major reason Transformer training is so much faster than RNN training, where each time step had to wait for the previous one to finish.

جهة الـDecoder وتقنية Teacher Forcing: بدلًا من تغذية الـdecoder كلمة كلمة وانتظار توليده للتالية، أثناء التدريب نُغذّيه بـالتسلسل الهدف كاملًا دفعة واحدة، مع إضافة <SOS> في البداية: <SOS> Ti amo molto. تسمى هذه التقنية Teacher Forcing — "نُجبر" الكلمات الصحيحة السابقة كمدخل للـdecoder بدلًا من تنبؤات النموذج نفسه (التي قد تكون خاطئة).

Decoder Input = <SOS> + التسلسل الهدف  (مُزاح لليمين بمقدار موضع واحد)

ولهذا يصف البحث الأصلي مدخل الـdecoder بأنه "shifted right" (مُزاح لليمين).


حساب الـLoss: ناتج الـdecoder (seq, d_model) يمر عبر طبقة Linear لإسقاطه إلى (seq, vocab_size)، ثم Softmax يحوّل كل موضع لتوزيع احتمالي على القاموس. يُقارَن هذا بالتسمية الحقيقية Ti amo molto <EOS> باستخدام Cross-Entropy Loss.

⚡ لماذا التدريب سريع

بفضل القناع السببي (القسم 8)، يمكن للـdecoder معالجة التسلسل الهدف كاملًا في تمريرة واحدة فقط (خطوة زمنية واحدة، بالتوازي الكامل)، مع ضمان أن التنبؤ في كل موضع استخدم فقط معلومات المواضع السابقة. هذا سبب رئيسي لكون تدريب Transformer أسرع بكثير من تدريب RNN.

10. Inference / Autoregressive Generation

Generating one token at a time, feeding each output back as the next input

📋 Original Slide Content

Slide 30 — Inference, Time Step 1: Decoder Input = <SOS> only. "We select a token from the vocabulary corresponding to the position of the token with the maximum value." "The output of the last layer is commonly known as logits." Output word: Ti.


Slide 31 — Time Step 2: Decoder Input = <SOS> ti. "Since decoder input now contains two tokens, we select the softmax corresponding to the second token." "Use the encoder output from the first timestep." "Append the previously output word to the decoder input." Output word: amo.


Slide 32 — Time Step 3: Decoder Input = <SOS> ti amo. Output word: molto.


Slide 33 — Time Step 4: Decoder Input = <SOS> ti amo molto. Output word: <EOS> — generation stops.

🇬🇧 English Explanation
ENGLISH EXPLANATION

At inference time we don't have the target sentence — we have to generate it. This makes decoding autoregressive: each newly generated word is fed back in as part of the input for generating the next word.

  1. Time Step 1: The decoder input is just <SOS>. The decoder (using the already-computed Encoder Output) produces logits over the vocabulary; softmax turns these into probabilities; we take the argmax (the vocabulary token with the maximum value) → the first output word, Ti.
  2. Time Step 2: We append Ti to the decoder input, giving <SOS> ti. We reuse the same Encoder Output computed once at the very start (no need to recompute it). We take the softmax corresponding to the second (newest) position → next word amo.
  3. Time Step 3: Decoder input becomes <SOS> ti amo; the softmax at the third position gives molto.
  4. Time Step 4: Decoder input becomes <SOS> ti amo molto; the softmax at the fourth position gives <EOS>, signaling that generation should stop.

"Logits": the raw, un-normalized output of the final Linear layer (before softmax) is commonly called the logits. Softmax turns logits into a probability distribution; argmax then picks the single highest-probability token.

⚡ Why inference is slower than training

Unlike training (one parallel pass over the whole target sequence), inference must run sequentially, one time step at a time — you cannot generate word 3 before word 2 exists, because word 2 has to be appended to the decoder input first. This mirrors one of the very RNN slowness problems from Section 1, except now it's confined only to the decoder's step-by-step loop, not the whole model. The one saving grace: the Encoder Output is computed exactly once, at Time Step 1, and reused unchanged across every subsequent decoder time step, since the encoder only depends on the fixed source sentence.

شرح تفصيلي

أثناء الـinference لا نملك الجملة الهدف — يجب أن نُولّدها. هذا يجعل عملية التوليد Autoregressive (توليد ذاتي التكرار): كل كلمة جديدة تُغذّى مرة أخرى كجزء من المدخل لتوليد الكلمة التالية.

  1. الخطوة الزمنية 1: مدخل الـdecoder هو <SOS> فقط. باستخدام Encoder Output المحسوب مسبقًا، يُنتج الـdecoder logits على القاموس، يحوّلها softmax لاحتمالات، ونأخذ argmax (أعلى قيمة) → أول كلمة ناتجة: Ti.
  2. الخطوة الزمنية 2: نُضيف Ti لمدخل الـdecoder ليصبح <SOS> ti. نُعيد استخدام نفس Encoder Output المحسوب مرة واحدة في البداية. نأخذ softmax الموضع الثاني → الكلمة التالية amo.
  3. الخطوة الزمنية 3: مدخل الـdecoder يصبح <SOS> ti amo؛ softmax الموضع الثالث يعطي molto.
  4. الخطوة الزمنية 4: مدخل الـdecoder يصبح <SOS> ti amo molto؛ softmax الموضع الرابع يعطي <EOS>، فيتوقف التوليد.

"Logits": ناتج طبقة Linear الأخيرة الخام (قبل softmax) يُسمى logits. الـsoftmax يحوّلها لتوزيع احتمالي، والـargmax يختار أعلى احتمال.

⚡ لماذا الـinference أبطأ من التدريب

بخلاف التدريب (تمريرة واحدة بالتوازي على كامل التسلسل الهدف)، يجب أن يعمل الـinference بالتتابع، خطوة زمنية واحدة في كل مرة — لا يمكن توليد الكلمة 3 قبل وجود الكلمة 2. هذا يُشبه مشكلة السرعة في RNN (القسم 1)، لكنه هنا محصور فقط في حلقة الـdecoder التتابعية. الميزة الوحيدة: Encoder Output يُحسب مرة واحدة فقط في الخطوة الزمنية 1، ويُعاد استخدامه دون تغيير في كل خطوة تالية، لأن الـencoder يعتمد فقط على الجملة المصدر الثابتة.

SLIDE 34

11. Inference Strategies — Greedy vs Beam Search

How to pick words during generation

📋 Original Slide Content

Slide 34 — Inference strategy: "We selected, at every step, the word with the maximum softmax value. This strategy is called greedy and usually does not perform very well." "A better strategy is to select at each step the top B words and evaluate all the possible next words for each of them and at each step, keeping the top B most probable sequences. This is the Beam Search strategy and generally performs better."

🇬🇧 English Explanation
ENGLISH EXPLANATION

Section 10 used the simplest possible decoding rule — always take the single highest-probability word (argmax) at each step. This is called Greedy decoding. It's fast and simple, but it can get stuck: an early word that looks slightly best right now might lead to a much worse overall sentence later, and greedy decoding has no way to reconsider a choice once it's made.


Beam Search fixes this by exploring multiple candidate sequences in parallel: at each step, instead of keeping only 1 sequence, it keeps the top B most probable partial sequences (B is the "beam width"). For each of those B sequences, it evaluates every possible next word, then again keeps only the overall top B resulting sequences before moving to the next step. This way, a word that's not the single best choice right now, but that leads to a much better full sentence, still has a chance to survive if it's part of one of the top-B beams.

شرح تفصيلي

القسم السابق استخدم أبسط قاعدة توليد ممكنة — أخذ الكلمة الأعلى احتمالًا فقط (argmax) في كل خطوة. تسمى هذه Greedy Decoding (التوليد الجشع). سريعة وبسيطة، لكنها قد "تعلق" في خيار سيء: كلمة تبدو الأفضل الآن قد تقود لجملة أسوأ بكثير لاحقًا، والـgreedy decoding لا تملك طريقة لإعادة النظر في خيار اتُّخذ من قبل.


Beam Search يحل هذه المشكلة باستكشاف عدة تسلسلات مرشحة بالتوازي: في كل خطوة، بدلًا من الاحتفاظ بتسلسل واحد فقط، يحتفظ بأفضل B تسلسلات جزئية (B تسمى "عرض الحزمة" beam width). لكل من هذه التسلسلات الـB، يُقيّم كل كلمة تالية ممكنة، ثم يحتفظ فقط بأفضل B تسلسلات ناتجة إجمالًا قبل الانتقال للخطوة التالية. بهذه الطريقة، كلمة ليست الأفضل حاليًا لكنها تقود لجملة كاملة أفضل بكثير، لا تزال لديها فرصة للنجاة إذا كانت جزءًا من إحدى أفضل B حزم.

المصطلحات: Greedy Decoding التوليد الجشع، Beam Search بحث الحزمة، Beam Width (B) عرض الحزمة.

🎯 Greedy Decoding

  • Always pick the single highest-probability word
  • Fast, simple, one candidate tracked at a time
  • Can get stuck in locally-good but globally-bad choices
  • Usually does not perform very well

🌳 Beam Search

  • Keeps top B most probable partial sequences at every step
  • Expands every beam with every possible next word, then re-prunes to top B
  • More compute, but explores more of the sentence-space
  • Generally performs better than greedy
💡 Practical Example — B = 2

With beam width B=2, after generating "Ti", the model might keep both "Ti amo" and "Ti ami" as candidates (instead of committing only to "amo"), evaluate their continuations, and only then decide which full path scores highest overall — something plain greedy decoding could never reconsider.

🎓 Exam Notes
  • 📌 Greedy = argmax at every step, one candidate, fast but suboptimal
  • 📌 Beam Search = keep top B sequences at every step, expand and re-prune, generally better quality
  • 📌 Trade-off: Beam Search costs more compute for better quality

Greedy decoding always takes the single best next word and can get stuck in suboptimal sentences. Beam Search keeps the top B partial sequences at each step, exploring more possibilities, and generally produces better final translations at the cost of more computation.

📝 Short-Answer Questions

Self-attention computes attention weights purely from the dot products between Q and K vectors — nothing in the formula itself encodes word order, so shuffling the input words would produce the same set of pairwise relationships just rearranged. Without an explicit signal for position, the model cannot tell "YOUR CAT" from "CAT YOUR." Positional encoding injects a position-dependent vector into each word's embedding before attention is computed, giving the model the order information the attention mechanism itself lacks.

Keys and Values form a lookup table (e.g. Key=ROMANTIC → Value=TITANIC). A Query (e.g. "love") is compared against every Key, and instead of requiring an exact match, the comparison produces a similarity score for each Key. Self-attention does the same numerically: the dot product QK^T scores how well each word's Query matches every other word's Key, softmax turns those scores into weights, and the output is a weighted blend of all the Values — mostly from the best-matching Keys, with smaller contributions from the rest.

Starting from the raw (seq, seq) score matrix QK^T/√d_k (before softmax), every entry at position [i][j] where j > i (i.e. above the main diagonal, referring to a "future" word relative to row i) is set to −∞. When softmax is then applied row-wise, exp(−∞) = 0, so all those upper-triangular entries become exactly 0 attention weight after normalization, while positions on or below the diagonal keep their normal (renormalized) weights. The result: word i's output can only be a weighted combination of words at positions ≤ i.

During training, the decoder receives the entire (shifted-right) target sequence at once. Because causal masking already guarantees position i cannot see positions after it, the model can compute predictions — and the Cross-Entropy loss — for every position simultaneously in a single parallel pass. During inference, the true future tokens don't exist yet: the model must generate one token, append it to the decoder input, and recompute before it can generate the next one, making inference an inherently sequential, multi-step process. The one part that isn't repeated is the Encoder Output, which is computed once and reused across every inference time step.

Greedy decoding commits irreversibly to the single highest-probability word at every step, which can lead to a locally-attractive but globally worse full sentence, with no way to reconsider. Beam Search instead tracks the top B most probable partial sequences at every step, expands each with every possible next word, and re-prunes back to the top B overall — allowing sequences that weren't the single best choice at one step to still survive if they lead to a better complete sentence. The trade-off is computational cost: Beam Search evaluates B times more candidate continuations at every step than greedy decoding.
