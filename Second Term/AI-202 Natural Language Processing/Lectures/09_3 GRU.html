1. What is a GRU? ▶

A GRU (Gated Recurrent Unit) is a type of neural network designed to handle sequences — things that come one after another, like words in a sentence, or frames in a video.

The big problem with plain sequence models is that they forget information quickly. GRUs solve this with gates — learned switches that decide what information to keep and what to throw away at each step.

Think of GRU like reading a long book. You don't memorize every word — you keep the important plot points and forget filler details. GRU does the same with sequential data.

Where GRU fits in the family tree

GRU is a recurrent neural network that uses gates to selectively remember or forget information across a sequence. It is simpler than LSTM but achieves comparable results on most tasks.

الـ GRU هو نوع من الشبكات العصبية المصممة للتعامل مع التسلسلات — يعني الأشياء اللي بتيجي واحدة ورا التانية، زي الكلام في جملة أو الإطارات في فيديو.

المشكلة الأساسية في الشبكات التكرارية العادية إنها بتنسى المعلومات بسرعة. الـ GRU حلّت المشكلة دي باستخدام Gates — يعني "بوابات" أو مفاتيح بتقرر إيه المعلومات اللي هتتذكرها وإيه اللي هترميها.

تخيل إنك بتقرأ رواية طويلة. مش بتحفظ كل كلمة — بتفضّل الأحداث المهمة وبتنسى التفاصيل الزيادة. الـ GRU بيعمل نفس الكلام مع البيانات.

الـ GRU هو نسخة أبسط وأسرع من الـ LSTM، وبيدي نتايج قريبة منه في معظم المهام.

الـ GRU شبكة عصبية تكرارية بتستخدم بوابات عشان تتحكم في إيه اللي يتذكر وإيه اللي يتنسى من المعلومات في التسلسل. أبسط من LSTM وأداؤه قريب منه.

2. The Two Gates ▶

GRU has exactly two gates. Each gate outputs a number between 0 and 1 — like a volume dial:

  • 0 = completely blocked (forget everything)
  • 1 = fully open (keep everything)

Gate 1 — Reset Gate r_t

Asks: "How much of the past should I use when computing the new candidate memory?"

When r_t ≈ 0, the past is mostly ignored — the model acts as if starting fresh. When r_t ≈ 1, the full past is used.

Imagine writing a sequel. The reset gate decides how much of the previous book's lore to consider when writing the new chapter.

Gate 2 — Update Gate z_t

Asks: "How much should I update my memory — how much old vs new?"

  • z_t → 1: keep the old memory, ignore the new input
  • z_t → 0: replace old memory with the new candidate
The update gate is like a DJ mixer — it decides how much of the old track (past) to fade out while fading in the new track (current input).
GRU has two gates: the Reset gate controls how much past context shapes the new candidate memory, and the Update gate controls how much to blend old vs new memory.

الـ GRU عنده بوابتين بس، وكل بوابة بتطلع رقم بين 0 و1 — زي مؤشر الصوت:

  • 0 = البوابة مسكّرة خالص (انسَ كل حاجة)
  • 1 = البوابة مفتوحة خالص (احتفظ بكل حاجة)

البوابة الأولى — Reset Gate r_t

بتسأل: "قد إيه من الماضي هستخدمه وأنا بحسب الـ candidate memory الجديدة؟"

لو r_t قريب من 0، الماضي بيتجاهل وكأن الـ model بيبدأ من أول. لو قريب من 1، الماضي بيتأخذ في الحسبان بالكامل.

تخيل إنك بتكتب الجزء التاني من رواية. الـ reset gate بيقرر قد إيه هتاخد من أحداث الجزء الأول وانت بتكتب الفصل الجديد.

البوابة التانية — Update Gate z_t

بتسأل: "قد إيه أحدّث الذاكرة — أخلط القديم بالجديد بأي نسبة؟"

  • z_t ← 1: احتفظ بالذاكرة القديمة، تجاهل الجديدة
  • z_t ← 0: استبدل القديمة بالـ candidate الجديدة
الـ update gate زي الـ DJ mixer — بيقرر نسبة خلط الأغنية القديمة (الماضي) مع الأغنية الجديدة (الـ input الحالي).
الـ GRU عنده بوابتين: الـ Reset Gate بتتحكم في قد إيه الماضي بيأثر في الذاكرة الجديدة، والـ Update Gate بتقرر بأي نسبة نحدّث الـ hidden state.

3. The Math — Step by Step ▶

GRU computes the new hidden state h_t in four steps:

Step 1 — Update Gate

z_t = σ( W_zh · h_(t-1) + W_zx · x_t + b_z ) -- σ = sigmoid, squashes output to [0, 1] -- W_zh = weight matrix for the past hidden state -- W_zx = weight matrix for the current input

Step 2 — Reset Gate

r_t = σ( W_rh · h_(t-1) + W_rx · x_t + b_r ) -- Same structure as z_t, but different learned weights

Step 3 — Candidate Hidden State h̃

h̃_t = tanh( W_hh · (r_t ⊙ h_(t-1)) + W_hx · x_t + b_h ) -- ⊙ = element-wise multiplication (Hadamard product) -- r_t "masks" how much of the past to include -- tanh squashes output to [-1, 1]

Step 4 — Final Hidden State (the blend)

h_t = (1 - z_t) ⊙ h_(t-1) + z_t ⊙ h̃_t -- z_t → 1 : h_t ≈ h̃_t (use mostly new candidate) -- z_t → 0 : h_t ≈ h_(t-1) (keep mostly old memory)
If z_t = 0.8: the new state is 80% new candidate + 20% old state. The model mostly updates its memory.
If z_t = 0.1: the new state is 10% new candidate + 90% old state. The model mostly preserves its memory.
The slide notes: "Reset acts directly on output state — no internal state and no output gate." Unlike LSTM, GRU has no separate cell state. The hidden state h_t is both the memory and the output.
Four equations: compute z_t → compute r_t → compute h̃_t → blend old and new into h_t. This whole process repeats at every time step in the sequence.

الـ GRU بيحسب الـ h_t الجديدة في أربع خطوات:

الخطوة الأولى — Update Gate

z_t = σ( W_zh · h_(t-1) + W_zx · x_t + b_z )

بنضرب الـ hidden state السابقة والـ input الحالي في مصفوفات أوزان، وبعدين بنعدّيها على دالة الـ sigmoid اللي بتحوّل النتيجة لرقم بين 0 و1.

الخطوة التانية — Reset Gate

r_t = σ( W_rh · h_(t-1) + W_rx · x_t + b_r )

نفس التركيب تماماً، بس بأوزان مختلفة متعلّمة لوحدها.

الخطوة التالتة — Candidate Hidden State

h̃_t = tanh( W_hh · (r_t ⊙ h_(t-1)) + W_hx · x_t + b_h )

هنا الـ r_t بيعمل "قناع" على الـ hidden state القديمة. لو r_t = 0 → الماضي اتنسى تقريباً. لو r_t = 1 → الماضي اتأخد بالكامل. الـ tanh بتحوّل النتيجة لقيمة بين -1 و1.

الخطوة الرابعة — الـ Hidden State النهائية

h_t = (1 - z_t) ⊙ h_(t-1) + z_t ⊙ h̃_t

ده خلط بين القديم والجديد. لو z_t = 0.8: 80% جديد + 20% قديم. لو z_t = 0.1: 10% جديد + 90% قديم.

أربع معادلات: احسب z_t ← احسب r_t ← احسب h̃_t ← اخلط القديم مع الجديد في h_t. وده بيتكرر في كل خطوة زمنية في التسلسل.

4. How Information Flows ▶

At each time step t, the GRU receives two inputs:

  • x_t — the current input (e.g. the current word embedding)
  • h_(t-1) — the hidden state from the previous step (the "memory")

And it produces h_t — the updated hidden state, which carries forward to the next step.

The same GRU cell is reused at every time step — its learned weights are fixed. Only the hidden state changes as it moves through the sequence.

Sentence: "The cat sat on the mat." At t=1, x_1 = "The". At t=2, x_2 = "cat". The GRU at t=2 remembers "The" because h_1 carries that memory forward.
GRU processes one token at a time and passes its hidden state (memory) forward. The same cell runs at every step — it just receives a different input and a different memory each time.

في كل خطوة زمنية t، الـ GRU بياخد مدخلين:

  • x_t — الـ input الحالي (مثلاً الكلمة الحالية)
  • h_(t-1) — الـ hidden state من الخطوة اللي قبلها (دي "الذاكرة")

وبيطلع منه h_t — الـ hidden state المحدّثة اللي بتتنقل للخطوة الجاية.

جملة: "القطة جلست على الحصيرة." في t=1: x_1 = "القطة". في t=2: x_2 = "جلست". الـ GRU في t=2 عارف معلومات عن "القطة" لأن h_1 نقلت الذاكرة دي.

نفس الـ GRU cell بيتكرر في كل خطوة زمنية. الأوزان ثابتة — اللي بيتغير هو الـ hidden state بس.

الـ GRU بيشتغل على token واحد في كل مرة، وبيمرر الـ hidden state للأمام. نفس الـ cell بيشتغل في كل خطوة — بس بياخد input مختلف وذاكرة مختلفة في كل مرة.

5. GRU vs LSTM ▶

The slide specifically notes: "Reset and update gates when coupled act as input and forget gates." GRU merges LSTM's three gates into two.

FeatureLSTMGRU
Number of gates3 (input, forget, output)2 (update, reset)
Separate cell stateYes — c_t alongside h_tNo — h_t only
Output gateYesNo
Parameter countMore (~4× hidden size)~25% fewer
Training speedSlowerFaster
Long-sequence performanceSlightly betterComparable, simpler
LSTM is a luxury car with three separate control systems. GRU is a sleek sports car — two controls, less maintenance, nearly the same capability.
GRU simplifies LSTM by merging the input and forget gates into one update gate and removing the separate cell state. Fewer parameters, faster training, similar results.

الـ GRU بيبسّط الـ LSTM بإنه بيدمج الـ input gate والـ forget gate في update gate واحدة، وبيشيل الـ cell state المنفصلة. النتيجة: parameters أقل، تدريب أسرع، أداء قريب.

6. Why GRU Matters — Applications ▶

GRU was introduced in the 2014 paper "Learning Phrase Representations using RNN Encoder–Decoder for Statistical Machine Translation" by Cho et al. It was designed for the encoder–decoder architecture used in machine translation.

Where GRUs are used

  • Machine translation — encoding source sentences, decoding to target language
  • Text generation — generating the next word or character
  • Sentiment analysis — reading a review and classifying positive/negative
  • Speech recognition — processing audio frames sequentially
  • Time-series forecasting — stock prices, sensor data, weather
Today, Transformers (BERT, GPT, etc.) have largely replaced RNNs/GRUs for NLP because they process sequences in parallel rather than one step at a time. But GRUs remain valuable in resource-constrained environments and are essential to understand for grasping the evolution of sequence modeling.
GRU was a landmark step in sequence modeling — simpler than LSTM, powerful enough for translation tasks. Understanding GRU is foundational for understanding the path that led to Transformers.

الـ GRU اتقدّم في ورقة بحثية سنة 2014 كتبها Cho وزملاؤه. كان مصمم أصلاً لمعمارية الـ encoder-decoder المستخدمة في الترجمة الآلية.

فين بيتستخدم الـ GRU

  • الترجمة الآلية — ترميز الجملة المصدر وفك ترميزها للغة الهدف
  • توليد النص — توقع الكلمة أو الحرف الجاي
  • تحليل المشاعر — قراءة تعليق وتوقع هل هو إيجابي أم سلبي
  • التعرف على الكلام — معالجة إطارات الصوت بالترتيب
  • التنبؤ بالسلاسل الزمنية — أسعار الأسهم، بيانات الحساسات، الطقس
في الوقت الحالي، الـ Transformers (زي BERT وGPT) استبدلت الـ RNNs والـ GRUs في معظم مهام الـ NLP لأنها بتعالج التسلسلات بالتوازي. لكن الـ GRU لسّه مهم في البيئات المحدودة الموارد وضروري لفهم تطور الـ deep learning.
الـ GRU كان خطوة مهمة في نمذجة التسلسلات — أبسط من الـ LSTM وقوي بما يكفي لمهام الترجمة. فهمه ضروري لفهم الرحلة اللي أدّت للـ Transformers.
