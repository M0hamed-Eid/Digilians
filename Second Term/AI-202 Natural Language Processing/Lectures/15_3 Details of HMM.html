01
HMM Basics — States, Transitions & the 3-Coins Example
▼

Quick recap: what is an HMM?

A Hidden Markov Model (HMM) is a statistical model for sequences where the thing you actually care about — the state at each time step — is hidden (not directly observable). What you DO observe is a sequence of observations that are probabilistically generated by those hidden states.

Formally, an HMM is defined by five components, often written as λ = (A, B, π) over a fixed set of states S and observation symbols V:

  • N states — the hidden state set, e.g. S = {S₁, S₂, ..., S_N}
  • M observation symbols — the visible alphabet, e.g. V = {v₁, v₂, ..., v_M}
  • State Transition Matrix (A) — A = {a_ij}, where a_ij = P(state j at t+1 | state i at t). Each row sums to 1.
  • Emission / Observation Matrix (B) — B = {b_j(k)}, where b_j(k) = P(observing symbol v_k | currently in state j).
  • Initial state distribution (π) — π_i = P(state i at t = 1).

State Transition Matrix (A) — the heart of the "Markov" part

The Markov assumption says: the next state depends ONLY on the current state, not on the whole history. This is what makes the matrix A so powerful — a single N×N table fully describes how the hidden process moves between states over time.

Example — a 2-state weather-like transition matrix
To State 1To State 2
From State 10.70.3
From State 20.40.6

Row 1 sums to 1 (0.7 + 0.3), row 2 sums to 1 (0.4 + 0.6) — this is mandatory for any valid transition matrix, because from any state you MUST go somewhere (including possibly staying in the same state).

The "Hidden Process" — 3 Coins example

This is the classic teaching example for HMMs. Imagine a person behind a curtain who has 3 coins: Coin 1, Coin 2, and Coin 3, each with a different (unknown to you) probability of landing Heads. At every time step, the person:

  1. Secretly picks one of the 3 coins according to some transition/selection rule (this choice is the hidden state).
  2. Flips that coin and tells you only the result: Heads (H) or Tails (T) — this is the observation.

You, the observer, never see WHICH coin was flipped — only the sequence of H/T outcomes, e.g. H T H H T .... Your job is to reason about the hidden coin sequence using only what you can observe. This is exactly the HMM setup: hidden states = which coin, observations = H/T, transition matrix A = probability of switching coins, emission matrix B = each coin's bias (P(H) and P(T) per coin).

State-transition diagram for the hidden 3-Coins process — nodes are hidden states (coins), arrows are transition probabilities a_ij. Observations (H/T) are emitted from each state but are not shown here.
Analogy
Think of the 3-coins example as a magician switching hidden cards behind a screen and only showing you the color of a light bulb (red/green) each round. You never see the card, only the bulb color. But because each card tends to produce a certain bulb color more often, and because the magician's card-switching follows a pattern, you can start making educated guesses about which card was used just from the sequence of bulb colors.
Summary
An HMM = hidden states + observable outputs, linked by a transition matrix A (how states change) and an emission matrix B (how each state produces observations). The 3-coins example shows exactly this: hidden = which coin, observed = H/T sequence.

مراجعة سريعة: ما هو HMM؟

Hidden Markov Model (HMM) هو model إحصائي للـ sequences، الشيء اللي فعلاً يهمنا — وهو الـ state في كل خطوة زمنية — يكون hidden (مخفي، ما نقدر نلاحظه مباشرة). اللي نلاحظه فعلاً هو سلسلة من الـ observations اللي تتولّد بشكل احتمالي من هذه الـ hidden states.

رسمياً، الـ HMM يتكوّن من خمسة عناصر، غالباً نكتبها λ = (A, B, π):

  • N من الـ states — مجموعة الـ hidden states
  • M من رموز الـ observations — الأبجدية المرئية
  • State Transition Matrix (A) — a_ij = P(الانتقال لـ state j في t+1 | كنا في state i في t). كل صف مجموعه 1.
  • Emission Matrix (B) — b_j(k) = P(ملاحظة الرمز v_k | نحن حالياً في state j).
  • Initial distribution (π) — احتمال البداية بكل state.

State Transition Matrix (A) — قلب فكرة Markov

Markov assumption بتقول: الـ state القادمة تعتمد فقط على الـ state الحالية، مش على كل التاريخ. هذا اللي يخلي مصفوفة A قوية جداً — جدول N×N واحد يوصف بالكامل كيف تنتقل العملية المخفية بين الـ states عبر الزمن.

كل صف مجموعه لازم يساوي 1، لأن من أي state لازم تنتقل لمكان ما (حتى لو بقيت في نفس الـ state).

الـ "Hidden Process" — مثال 3 Coins

هذا المثال الكلاسيكي لتدريس HMM. تخيّل شخص وراء ستارة معه 3 عملات: Coin 1 وCoin 2 وCoin 3، كل واحدة عندها احتمال مختلف (وأنت ما تعرفه) للحصول على صورة (Heads). في كل خطوة زمنية، الشخص:

  1. يختار سراً واحدة من العملات الثلاث حسب قاعدة انتقال معيّنة (هذا الاختيار هو الـ hidden state).
  2. يقلّب هذه العملة ويخبرك فقط بالنتيجة: صورة (H) أو كتابة (T) — هذه هي الـ observation.

أنت كمراقب لا ترى أبداً أي عملة استُخدمت — فقط سلسلة النتائج H/T. مهمتك هي الاستدلال على سلسلة العملات المخفية من خلال ما تلاحظه فقط. هذا بالضبط إعداد HMM: hidden states = أي عملة، observations = H/T، transition matrix A = احتمال تبديل العملة، emission matrix B = ميل كل عملة (P(H) وP(T) لكل عملة).

تشبيه
تخيّل مثال الـ 3 coins كساحر يبدّل بطاقات مخفية وراء شاشة، ويريك فقط لون لمبة (أحمر/أخضر) في كل جولة. أنت أبداً ما تشوف البطاقة، بس تشوف لون اللمبة. لكن لأن كل بطاقة تميل لتنتج لون معيّن أكثر، ولأن تبديل الساحر للبطاقات يتبع نمط معيّن، تقدر تبدأ تخمّن أي بطاقة استُخدمت فقط من سلسلة ألوان اللمبة.
ملخص
HMM = hidden states + observations مرئية، مرتبطين بمصفوفة انتقال A (كيف تتغيّر الـ states) ومصفوفة emission B (كيف تنتج كل state ملاحظات). مثال الـ 3 coins يوضّح هذا بالضبط: hidden = أي عملة، observed = سلسلة H/T.
02
Types of HMM
▼

Why does the "type" of HMM matter?

Not every hidden process can jump freely between every state. The structure of the transition matrix A (which entries a_ij are allowed to be non-zero) defines the topology of the HMM — and different real-world problems need different topologies.

TypeTransition structureTypical use
Ergodic HMMFully connected — every state can reach every other state directly (a_ij can be non-zero for any i, j)General sequence modeling, POS tagging, weather-style processes, the 3-coins example
Left-Right (Bakis) HMMStates are ordered; transitions only go forward (to the same state or a higher-indexed state), never backwardSpeech recognition — sounds/phonemes naturally progress in one direction over time
Left-Right Banded HMMEven more restricted left-right — you can only move to the immediate next state or stayStrictly sequential processes, e.g. isolated word models
Parallel path Left-Right HMMMultiple left-right chains running in parallel, merging at start/endModeling multiple pronunciation variants of the same word
Analogy
An ergodic HMM is like a board game where you can move your piece to any square from any square. A left-right HMM is like a one-way race track — you always move forward (or stay in place), you can never go back to an earlier checkpoint. Speech naturally flows one direction in time, which is exactly why left-right HMMs dominate speech recognition.
Example — Left-Right transition matrix (3 states, no going back)
S1S2S3
S10.60.40.0
S20.00.50.5
S30.00.01.0

Notice the zeros below the diagonal — the model can never move back to a previous state. This mirrors how a spoken phoneme naturally transitions into the next one.

Summary
HMM topology (which transitions are allowed) is chosen based on the problem. Ergodic HMMs allow any transition; Left-Right (Bakis) HMMs only allow forward movement — the standard choice for time-ordered signals like speech.

مو كل عملية مخفية تقدر تقفز بحرية بين كل الـ states. بنية مصفوفة الانتقال A (أي عناصر a_ij مسموح تكون غير صفرية) بتحدد topology الـ HMM — ومشاكل مختلفة في الواقع تحتاج topologies مختلفة.

The Three Fundamental Problems of HMM
▼

Once you accept that an HMM λ = (A, B, π) exists, every practical use of it boils down to answering exactly three questions. These are famously called the Three Fundamental Problems of HMM (Rabiner's formulation).

#ProblemQuestionAlgorithm(s)Complexity
1Evaluation / LikelihoodGiven λ and an observation sequence O, what is P(O | λ)?Forward Algorithm (or Backward Algorithm)O(N²T)
2DecodingGiven λ and O, what is the single BEST hidden state sequence Q that explains O?Viterbi AlgorithmO(N²T)
3Learning / TrainingGiven O (and maybe an initial guess of λ), how do we adjust λ = (A, B, π) to maximize P(O | λ)?Baum-Welch (Forward-Backward, an EM algorithm)O(N²T) per iteration
Analogy
Think of a detective investigating a case using only a security camera showing footprints on the floor (the observations), not the actual person (the hidden states). Problem 1 asks: "how likely is it that MY suspect could have produced exactly this footprint pattern?" Problem 2 asks: "given the footprints, what is the single most likely path the person walked?" Problem 3 asks: "I don't even know my suspect's walking style yet — can I learn it from many observed footprint patterns?"
Why order matters

Problem 1 (evaluation) is often used to score which of several candidate HMMs best explains a given observation sequence — e.g. "does this HMM match the word 'yes' or the word 'no' better?" (used inside speech recognition, see Section 7). Problem 2 (decoding) is used when you need to know the underlying path itself — e.g. tagging each observed frame with the most likely phoneme. Problem 3 (learning) must run first in practice, because you need a trained λ before you can meaningfully solve Problems 1 and 2.

Summary
The three problems are: (1) how likely is this observation sequence under my model — Forward Algorithm; (2) what is the best hidden path — Viterbi; (3) how do I train the model itself — Baum-Welch. All three rely on dynamic programming to avoid exponential brute-force search.

بمجرد ما نفترض وجود HMM باسم λ = (A, B, π)، كل استخدام عملي له بيرجع لثلاثة أسئلة بالضبط. تُعرف باسم Three Fundamental Problems of HMM (صياغة Rabiner).

04
Problem 1 — Evaluation: Exhaustive Search, Forward & Backward Algorithm
▼

The naive solution: Exhaustive Search

The most obvious way to compute P(O | λ) is: enumerate every possible hidden state sequence Q of length T, compute P(O, Q | λ) for each one, and sum them all up (since the sequences are mutually exclusive):

P(O|λ) = Σ_Q P(O|Q,λ) · P(Q|λ)

Why exhaustive search is infeasible
There are N^T possible hidden state sequences of length T (N choices at every one of T time steps). For each one, computing P(O,Q|λ) costs O(T) multiplications. Total cost: O(T · N^T). Even for a small HMM with N=5 states and T=20 observations, N^T = 5^20 ≈ 95 trillion — completely impossible to compute directly, even on fast hardware.

The smart solution: dynamic programming

The key insight: many of those N^T sequences share partial paths. Instead of recomputing shared work over and over, we can build up the answer incrementally, one time step at a time, reusing previously computed partial results. This is dynamic programming, and it is exactly what the Forward and Backward algorithms do.

Forward Algorithm

Define the forward variable: α_t(i) = P(o₁, o₂, ..., o_t, state=i at time t | λ) — the probability of the observation prefix up to time t AND being in state i at time t.

  1. Initialization (t=1): α₁(i) = π_i · b_i(o₁) for each state i
  2. Recursion (t=2..T): α_t(j) = [ Σ_i α_(t-1)(i) · a_ij ] · b_j(o_t)
  3. Termination: P(O|λ) = Σ_i α_T(i)

Each cell α_t(j) only needs the N values α_(t-1)(·) from the previous time step — that is the reuse that saves us from exponential blowup. The result is a trellis of size N×T, and filling every cell costs O(N) work, giving total cost O(N²T) instead of O(T·N^T).

Pseudocode — Forward Algorithm
# N states, T observations, A[i][j], B[j][k], pi[i] for i in range(N): alpha[1][i] = pi[i] * B[i][ obs[1] ] for t in range(2, T+1): for j in range(N): s = sum(alpha[t-1][i] * A[i][j] for i in range(N)) alpha[t][j] = s * B[j][ obs[t] ] P_O_given_lambda = sum(alpha[T][i] for i in range(N))

Backward Algorithm

The mirror-image idea: define β_t(i) = P(o_(t+1), ..., o_T | state=i at time t, λ) — the probability of the observation SUFFIX after time t, given we were in state i at time t.

  1. Initialization (t=T): β_T(i) = 1 for all i
  2. Recursion (t=T-1..1): β_t(i) = Σ_j a_ij · b_j(o_(t+1)) · β_(t+1)(j)
  3. Termination: P(O|λ) = Σ_i π_i · b_i(o₁) · β₁(i)

The Backward algorithm alone also solves Problem 1, but its real value shows up later: α_t(i) and β_t(i) together are exactly what the Baum-Welch training algorithm (Problem 3) needs to re-estimate A and B.

ApproachIdeaComplexity
Exhaustive searchEnumerate every hidden sequence explicitlyO(T · N^T) — infeasible
Forward AlgorithmDP, build up from t=1 to t=T, reusing partial sumsO(N²T)
Backward AlgorithmDP, build up from t=T back to t=1O(N²T)
Analogy
Exhaustive search is like re-solving an entire jigsaw puzzle from scratch for every possible way the last piece could be placed. Dynamic programming is like keeping a running photo of the assembled puzzle after each step and only figuring out where the NEXT piece goes — you never redo work you already finished. That is the entire trick that turns an exponential problem into a polynomial one.
Summary
Problem 1 asks "how likely is this observation sequence?" Exhaustive search is O(T·N^T) and infeasible. The Forward Algorithm (and equivalently the Backward Algorithm) uses dynamic programming to answer the same question in O(N²T) by reusing partial results across a trellis.

الحل الساذج: Exhaustive Search

أبسط طريقة لحساب P(O | λ) هي: تعدّد كل الـ hidden state sequences الممكنة بطول T، تحسب P(O,Q|λ) لكل واحدة، وتجمعهم كلهم:

P(O|λ) = Σ_Q P(O|Q,λ) · P(Q|λ)

ليش الـ Exhaustive Search غير عملي
يوجد N^T من الـ hidden state sequences الممكنة بطول T. لكل واحدة، حساب P(O,Q|λ) يكلّف O(T). التكلفة الكلية: O(T · N^T). حتى لـ HMM صغير بـ N=5 states وT=20 observation، N^T = 5^20 ≈ 95 تريليون — مستحيل حسابها مباشرة حتى على أسرع hardware.

الحل الذكي: Dynamic Programming

الفكرة الأساسية: كثير من هذه الـ N^T sequences تشترك في مسارات جزئية. بدل إعادة حساب العمل المشترك مرات ومرات، نقدر نبني الجواب تدريجياً، خطوة زمنية بخطوة، ونعيد استخدام النتائج الجزئية المحسوبة سابقاً. هذا اسمه dynamic programming، وهو بالضبط ما تفعله خوارزميتا Forward وBackward.

Forward Algorithm

نعرّف متغيّر forward: α_t(i) = P(o₁,...,o_t, state=i عند t | λ).

  1. Initialization (t=1): α₁(i) = π_i · b_i(o₁)
  2. Recursion (t=2..T): α_t(j) = [ Σ_i α_(t-1)(i) · a_ij ] · b_j(o_t)
  3. Termination: P(O|λ) = Σ_i α_T(i)

كل خلية α_t(j) تحتاج فقط القيم N من α_(t-1)(·) من الخطوة السابقة — هذا إعادة الاستخدام هو ما يوفّر علينا الانفجار الأسّي. الناتج trellis بحجم N×T، وملء كل خلية يكلّف O(N)، فالتكلفة الكلية O(N²T) بدل O(T·N^T).

Pseudocode — Forward Algorithm
# N states, T observations, A[i][j], B[j][k], pi[i] for i in range(N): alpha[1][i] = pi[i] * B[i][ obs[1] ] for t in range(2, T+1): for j in range(N): s = sum(alpha[t-1][i] * A[i][j] for i in range(N)) alpha[t][j] = s * B[j][ obs[t] ] P_O_given_lambda = sum(alpha[T][i] for i in range(N))

Backward Algorithm

نفس الفكرة بعكس الاتجاه: β_t(i) = P(o_(t+1),...,o_T | state=i عند t, λ).

  1. Initialization (t=T): β_T(i) = 1
  2. Recursion (t=T-1..1): β_t(i) = Σ_j a_ij · b_j(o_(t+1)) · β_(t+1)(j)
  3. Termination: P(O|λ) = Σ_i π_i · b_i(o₁) · β₁(i)

Backward وحدها كمان تحل المشكلة 1، لكن قيمتها الحقيقية تظهر لاحقاً: α_t(i) وβ_t(i) معاً هما بالضبط ما تحتاجه خوارزمية Baum-Welch (المشكلة 3) لإعادة تقدير A وB.

Problem 2 — Decoding: The Viterbi Algorithm
▼

What decoding means

Problem 1 tells us HOW LIKELY the observations are. Problem 2 asks a different question: given O, what is the single best hidden state SEQUENCE Q* = (q₁, q₂, ..., q_T) that most likely produced it? This is called decoding: Q* = argmax_Q P(Q | O, λ).

Why we can't just pick the best state at each t independently
A tempting shortcut is: at each time t, pick whichever state has the highest probability, independent of other time steps. This can produce an ILLEGAL sequence — e.g. picking two states at consecutive steps that have a_ij = 0 (no valid transition between them)! The Viterbi Algorithm avoids this by finding the single best sequence as a whole, respecting all transition constraints.

Viterbi Algorithm — DP over the trellis

Define δ_t(i) = max probability of any single path that ends in state i at time t, having produced o₁...o_t. We also keep a backpointer ψ_t(i) recording which previous state gave that max.

  1. Initialization (t=1): δ₁(i) = π_i · b_i(o₁), ψ₁(i) = 0
  2. Recursion (t=2..T): δ_t(j) = max_i [ δ_(t-1)(i) · a_ij ] · b_j(o_t), and ψ_t(j) = argmax_i [ δ_(t-1)(i) · a_ij ]
  3. Termination: P* = max_i δ_T(i), q_T* = argmax_i δ_T(i)
  4. Path backtracking: for t = T-1 down to 1, q_t* = ψ_(t+1)(q_(t+1)*)

Notice Viterbi is almost identical to the Forward Algorithm — the only difference is max replaces Σ, and we additionally store backpointers to reconstruct the winning path. This keeps the complexity at O(N²T), exactly like the Forward Algorithm — massively cheaper than checking all N^T paths explicitly.

Viterbi trellis: 3 states × 4 time steps. Grey lines are all legal transitions considered by δ_t(j) = max_i[...]. The highlighted red path is the single best (highest-probability) hidden state sequence Q* recovered by backtracking through ψ.
Mini worked example

Suppose N=2 states {S1,S2}, π=(0.6, 0.4), and observation o₁ with b₁(o₁)=0.5, b₂(o₁)=0.4. Then δ₁(S1) = 0.6×0.5 = 0.30 and δ₁(S2) = 0.4×0.4 = 0.16. For t=2, to compute δ₂(S1) we compare paths coming from S1 and S2 using a_11, a_21, take the max, then multiply by b₁(o₂). We keep doing this to t=T, then backtrack from the state with the highest δ_T(i) using the stored ψ pointers to recover the full best path — exactly like tracing back through a maze once you know the exit.

Summary
Viterbi finds the single most likely hidden state sequence using DP with max instead of sum, plus backpointers. It costs O(N²T), same order as Forward, and avoids the illegal-sequence trap of picking the best state independently at each time step.

معنى الـ Decoding

المشكلة 1 تخبرنا كم احتمال الـ observations. المشكلة 2 تسأل سؤال مختلف: بمعطى O، ما هو أفضل hidden state sequence واحد Q* = (q₁,...,q_T) أنتجها على الأرجح؟ هذا اسمه decoding: Q* = argmax_Q P(Q | O, λ).

ليش ما نقدر نختار أفضل state في كل t بشكل مستقل
طريقة مغرية: في كل t، تختار الـ state ذات أعلى احتمال بشكل مستقل عن باقي الخطوات. هذا ممكن ينتج sequence غير قانونية — مثلاً اختيار حالتين متتاليتين بينهما a_ij = 0 (لا يوجد انتقال صالح)! خوارزمية Viterbi تتجنب هذا بإيجاد أفضل sequence كوحدة واحدة، مع احترام كل قيود الانتقال.

Viterbi Algorithm — DP على الـ Trellis

نعرّف δ_t(i) = أعلى احتمال لأي مسار ينتهي بـ state i عند t. ونحتفظ بـ backpointer ψ_t(i) يسجّل أي state سابقة أعطت هذا الأعلى.

  1. Initialization (t=1): δ₁(i) = π_i · b_i(o₁)
  2. Recursion (t=2..T): δ_t(j) = max_i [ δ_(t-1)(i) · a_ij ] · b_j(o_t)
  3. Termination: P* = max_i δ_T(i)
  4. Backtracking: من t=T-1 إلى 1، q_t* = ψ_(t+1)(q_(t+1)*)

لاحظ أن Viterbi شبه مطابق للـ Forward Algorithm — الفرق الوحيد هو استبدال Σ بـ max، مع تخزين backpointers لإعادة بناء المسار الفائز. تبقى التكلفة O(N²T)، تماماً مثل Forward.

مثال مصغّر محلول

لنفترض N=2 states {S1,S2}، π=(0.6, 0.4)، وo₁ حيث b₁(o₁)=0.5، b₂(o₁)=0.4. إذن δ₁(S1) = 0.6×0.5 = 0.30 وδ₁(S2) = 0.4×0.4 = 0.16. عند t=2 نقارن المسارات القادمة من S1 وS2 ونأخذ الـ max ثم نضرب بـ b₁(o₂). نستمر لغاية t=T، ثم نرجع للخلف من أعلى δ_T(i) باستخدام ψ لاستعادة المسار الكامل الأفضل.

ملخص
Viterbi يجد أفضل hidden state sequence واحد باستخدام DP مع max بدل sum، مع backpointers. تكلفته O(N²T)، نفس رتبة Forward، ويتجنب مصيدة السلسلة غير القانونية.
06
Problem 3 — Learning: Re-estimating HMM Parameters (Baum-Welch)
▼

Why training is the hardest of the three problems

Problems 1 and 2 assume λ = (A, B, π) is already known. Problem 3 asks the opposite: given only observed data O (and NO labeled hidden states — remember, they're hidden!), how do we find the λ that best explains O? There is no closed-form solution; we must use an iterative algorithm.

Baum-Welch = Forward-Backward, an instance of EM

The Baum-Welch Algorithm is a special case of Expectation-Maximization (EM). It alternates between two steps until convergence:

  1. E-step (Expectation) — using the CURRENT λ, run the Forward Algorithm (to get α_t(i)) and the Backward Algorithm (to get β_t(i)). Combine them to compute two quantities: γ_t(i) = probability of being in state i at time t, and ξ_t(i,j) = probability of being in state i at time t AND state j at time t+1, both given O and the current λ.
  2. M-step (Maximization) — use γ and ξ, averaged (expected counts) over the whole observation sequence, to re-estimate new parameters: π̂_i = γ₁(i); â_ij = (expected # transitions i→j) / (expected # transitions out of i) = Σ_t ξ_t(i,j) / Σ_t γ_t(i); b̂_j(k) = (expected # times in state j while observing symbol k) / (expected # times in state j).

Replace λ with the newly re-estimated λ̂, and repeat. Each iteration is guaranteed to never DECREASE P(O|λ) — this is the core EM guarantee. The algorithm stops when the improvement becomes negligible (convergence) or after a fixed number of iterations.

Analogy
Baum-Welch is like a detective refining a theory of the crime with no eyewitness to the crime itself, only its aftermath. First (E-step), given the current theory, the detective estimates how likely each possible sequence of events was. Then (M-step), the detective updates the theory to better match those weighted possibilities. Repeat this cycle — each round of "guess, then refine" gets the theory closer to the truth, even without ever directly observing the hidden events.
Pseudocode — Baum-Welch outline
# initialize A, B, pi randomly (or with reasonable priors) repeat until convergence: # E-step alpha = forward(A, B, pi, O) beta = backward(A, B, pi, O) gamma = compute_gamma(alpha, beta) xi = compute_xi(alpha, beta, A, B, O) # M-step pi_new = gamma[1] A_new = sum(xi, axis=t) / sum(gamma[1:T-1], axis=t) B_new = sum(gamma where obs==k, axis=t) / sum(gamma, axis=t) A, B, pi = A_new, B_new, pi_new
Important
Baum-Welch only finds a LOCAL optimum, not the global best λ — the result depends on the initial values of A, B, π. In practice you re-run training from several random initializations and keep the model with the highest likelihood.
Summary
Training an HMM = Baum-Welch = EM applied to HMMs. E-step uses Forward + Backward to compute expected state occupancies (γ) and expected transitions (ξ); M-step re-estimates A, B, π from those expectations. Repeats until convergence, guaranteed to never decrease likelihood, but only guarantees a local optimum.

ليش الـ Training هي أصعب المشاكل الثلاث

المشكلتان 1 و2 تفترضان إن λ = (A, B, π) معروفة مسبقاً. المشكلة 3 تسأل العكس: بمعطى فقط بيانات ملاحظة O (وبدون أي hidden states معروفة — تذكّر، هي مخفية!)، كيف نجد λ التي تفسّر O بأفضل شكل؟ لا يوجد حل مغلق (closed-form)؛ يجب استخدام خوارزمية تكرارية.

Baum-Welch = Forward-Backward، نسخة من EM

خوارزمية Baum-Welch هي حالة خاصة من Expectation-Maximization (EM). تتناوب بين خطوتين حتى التقارب (convergence):

  1. E-step (Expectation) — باستخدام λ الحالية، شغّل Forward Algorithm (للحصول على α_t(i)) وBackward Algorithm (للحصول على β_t(i)). ادمجهما لحساب γ_t(i) = احتمال أن نكون في state i عند t، وξ_t(i,j) = احتمال الانتقال من i إلى j بين t وt+1.
  2. M-step (Maximization) — استخدم γ وξ لإعادة تقدير المعاملات الجديدة: π̂_i = γ₁(i)؛ â_ij = عدد الانتقالات المتوقعة i→j / عدد الانتقالات المتوقعة الخارجة من i؛ b̂_j(k) = عدد المرات المتوقعة في state j مع ملاحظة الرمز k / عدد المرات المتوقعة في state j.

استبدل λ بـ λ̂ الجديدة، وكرّر. كل iteration مضمون أنها لا تُنقص P(O|λ) أبداً — هذا ضمان EM الأساسي. تتوقف الخوارزمية عند التقارب أو بعد عدد ثابت من الـ iterations.

تشبيه
Baum-Welch مثل محقق يحسّن نظرية عن جريمة بدون شاهد عيان للجريمة نفسها، فقط آثارها. أولاً (E-step)، بمعطى النظرية الحالية، يقدّر المحقق احتمال كل تسلسل ممكن للأحداث. ثم (M-step)، يحدّث المحقق النظرية لتتوافق أكثر مع تلك الاحتمالات الموزونة. كرّر هذه الدورة — كل جولة "خمّن ثم حسّن" تقرّب النظرية من الحقيقة، حتى بدون ملاحظة الأحداث المخفية مباشرة.
مهم
Baum-Welch يجد فقط local optimum، مش أفضل λ عالمياً — النتيجة تعتمد على القيم الابتدائية لـ A وB وπ. عملياً نعيد الـ training من عدة نقاط بداية عشوائية ونحتفظ بالـ model ذي أعلى likelihood.
ملخص
تدريب HMM = Baum-Welch = تطبيق EM على HMM. الـ E-step يستخدم Forward + Backward لحساب γ وξ؛ الـ M-step يعيد تقدير A وB وπ من هذه التوقعات. يتكرر حتى التقارب، ومضمون عدم إنقاص الـ likelihood، لكن يضمن فقط local optimum.
07
Application: Testing of a Speech Recognition System
▼

How the three problems come together in speech recognition

A classic HMM-based speech recognizer models each word (or phoneme) as its own left-right HMM. The observations are short frames of acoustic features (e.g. MFCC vectors) extracted every ~10ms from the audio signal. All three fundamental problems are used together:

ProblemRole in speech recognition
Learning (Problem 3)During TRAINING: for every word in the vocabulary, run Baum-Welch on many recorded audio examples of that word to learn its own HMM λ_word = (A, B, π).
Evaluation (Problem 1)During TESTING: given a new, unseen audio clip (as an observation sequence O), run the Forward Algorithm against EVERY candidate word-HMM to get P(O | λ_word) for each word.
Decoding (Problem 2)Used to find the most likely internal phoneme/state alignment within a word-HMM, useful for further refinement, keyword spotting, and forced alignment.

Testing procedure

  1. Record a test utterance and extract its acoustic feature sequence O.
  2. For each word-HMM λ_w in the vocabulary, compute P(O | λ_w) using the Forward Algorithm.
  3. Predict the word: ŵ = argmax_w P(O | λ_w) — the model whose HMM assigns the highest likelihood to the observed audio.
  4. Compare the predicted word ŵ against the true (ground-truth) label to score the system.
Example

Suppose the vocabulary has two word-HMMs: λ_yes and λ_no, both already trained via Baum-Welch. A new audio clip produces the observation sequence O. The Forward Algorithm computes P(O | λ_yes) = 0.0021 and P(O | λ_no) = 0.00004. Since P(O | λ_yes) is much higher, the system predicts the spoken word was "yes".

Evaluation metrics

  • Word Error Rate (WER) — the standard metric: (Substitutions + Insertions + Deletions) / Total reference words.
  • Accuracy — fraction of correctly recognized words/utterances, especially for isolated-word tasks.
  • Confusion matrix — which words are commonly mistaken for which others, useful for diagnosing weak or acoustically similar HMMs.
Analogy
Testing a speech recognizer is like presenting a mystery sound clip to a panel of expert judges, one judge per candidate word ("yes", "no", "stop", ...). Each judge (a trained HMM) gives a score for "how likely is it that THIS clip is really the word I specialize in?" The judge with the highest score wins, and their word becomes the system's answer.
Important
Testing performance heavily depends on training data quality and quantity. If a word-HMM was trained on too few or too noisy examples, its emission probabilities B will not generalize well, and the Forward Algorithm will assign it unreliable likelihoods on new test audio.
Summary
In HMM-based speech recognition, training (Problem 3 / Baum-Welch) builds one HMM per word from example recordings; testing (Problem 1 / Forward Algorithm) scores a new audio clip against every candidate word-HMM and picks the one with the highest likelihood. Viterbi (Problem 2) supports finer-grained alignment within each word-HMM.

كيف تجتمع المشاكل الثلاث في Speech Recognition

نظام speech recognition كلاسيكي مبني على HMM يمثّل كل كلمة (أو phoneme) بـ HMM خاص بها من نوع left-right. الـ observations هي إطارات (frames) قصيرة من acoustic features (مثل MFCC vectors) تُستخرج كل ~10ms من إشارة الصوت. المشاكل الثلاث تُستخدم معاً:

المشكلةالدور في Speech Recognition
Learning (المشكلة 3)أثناء الـ TRAINING: لكل كلمة في المفردات، شغّل Baum-Welch على عدة تسجيلات صوتية لتلك الكلمة لتعلّم HMM خاص بها λ_word.
Evaluation (المشكلة 1)أثناء الـ TESTING: بمعطى مقطع صوتي جديد O، شغّل Forward Algorithm على كل HMM كلمة مرشحة للحصول على P(O | λ_word) لكل كلمة.
Decoding (المشكلة 2)يُستخدم لإيجاد أفضل محاذاة داخلية للـ phonemes/states ضمن HMM الكلمة، مفيد للتحسين ولـ forced alignment.

إجراء الاختبار

  1. سجّل نطقاً اختبارياً واستخرج سلسلة الـ acoustic features O.
  2. لكل word-HMM λ_w في المفردات، احسب P(O | λ_w) باستخدام Forward Algorithm.
  3. تنبّأ بالكلمة: ŵ = argmax_w P(O | λ_w).
  4. قارن الكلمة المتنبأ بها ŵ مع التصنيف الحقيقي لتقييم النظام.
مثال

لنفترض المفردات فيها كلمتين: λ_yes وλ_no، تم تدريبهما بـ Baum-Welch. مقطع صوتي جديد ينتج O. Forward Algorithm يحسب P(O | λ_yes) = 0.0021 وP(O | λ_no) = 0.00004. بما أن P(O | λ_yes) أعلى بكثير، النظام يتنبأ بأن الكلمة المنطوقة كانت "yes".

مقاييس التقييم

  • Word Error Rate (WER) — المقياس المعياري: (Substitutions + Insertions + Deletions) / إجمالي كلمات المرجع.
  • Accuracy — نسبة الكلمات/النطق المتعرَّف عليها بشكل صحيح.
  • Confusion matrix — أي كلمات يُخطأ بها عادة لصالح كلمات أخرى، مفيد لتشخيص الـ HMMs الضعيفة.
تشبيه
اختبار نظام speech recognition مثل عرض مقطع صوتي غامض على لجنة حكّام خبراء، كل حكم مختص بكلمة مرشحة ("yes"، "no"، "stop"...). كل حكم (HMM مدرَّب) يعطي درجة لـ "كم احتمال أن هذا المقطع فعلاً الكلمة التي أتخصص بها؟" الحكم صاحب أعلى درجة يفوز، وكلمته تصبح إجابة النظام.
مهم
أداء الاختبار يعتمد بشدة على جودة وكمية بيانات الـ training. إذا تم تدريب word-HMM على أمثلة قليلة أو صاخبة جداً، احتمالات الـ emission B ما راح تعمم جيداً، وForward Algorithm راح يعطيها likelihoods غير موثوقة على صوت اختبار جديد.
ملخص
في speech recognition المبني على HMM، الـ training (المشكلة 3 / Baum-Welch) يبني HMM لكل كلمة من تسجيلات أمثلة؛ الـ testing (المشكلة 1 / Forward Algorithm) يقيّم مقطعاً صوتياً جديداً مقابل كل word-HMM مرشح ويختار الأعلى likelihood. Viterbi (المشكلة 2) يدعم محاذاة أدق داخل كل word-HMM.
