Q3 True / False Medium

Typically, in a network that uses sigmoid, the gradient decreases to 0 within five layers, making the network difficult to train.

  • True
  • ❌ False (My Answer)
❌ Incorrect — Correct Answer: True
Why TRUE is correct (you answered False — WRONG)
This is a classic vanishing gradient problem fact. The sigmoid function squashes values into [0,1], and its gradient (derivative) is at most 0.25. When you chain 5 layers, the gradient becomes: 0.25 × 0.25 × 0.25 × 0.25 × 0.25 = 0.00098 ≈ 0. This is essentially zero, making early layers unable to learn.

Why False is wrong: The math clearly shows that sigmoid-based deep networks lose gradients within just 5 layers — this is a documented fact in deep learning research (Hochreiter 1991, Bengio 1994).
Vanishing Gradient Problem — Deep Explanation
The Problem: During backpropagation, gradients are multiplied through each layer. If each gradient is less than 1 (like sigmoid's max 0.25), repeated multiplication drives the gradient toward zero.

Sigmoid: f(x) = 1/(1+e^-x) | Range: (0,1) | Max Gradient: 0.25
After 5 layers: 0.25^5 = 0.000977 ≈ 0
Solutions to vanishing gradient:
  • ReLU: Gradient is 1 for positive inputs (no vanishing)
  • Batch Normalization: Normalizes activations
  • Residual Connections: Skip connections in ResNet
  • LSTM/GRU: For recurrent networks

Key exam trap: Tanh also suffers from vanishing gradient (range -1 to 1, max derivative = 1, but still compresses to near-zero with depth). The question says sigmoid causes this in ~5 layers — this is TRUE!
Memory Trick
"Sigmoid SQUISHES gradients like a SPONGE — squeeze 5 times and nothing is left!"
0.25^5 = basically zero. Sigmoid = vanishing gradient = TRUE.
⚠️ YOU GOT THIS WRONG. Sigmoid max gradient = 0.25. After 5 layers: 0.25^5 ≈ 0. This causes vanishing gradient. The statement is TRUE. Remember: sigmoid and tanh BOTH suffer vanishing gradient. ReLU solves it. This will DEFINITELY appear on the real exam.
Q4 True / False Hard

When you train a deep neural network with the softsign function, if the network is very deep, an increasing number of back-propagated gradients fall into the saturation area, making the gradient module smaller and finally close to 0, and the weight cannot be updated.

  • ✅ True
  • False
✅ Correct — 16 Points
Why TRUE is correct
Softsign is defined as: f(x) = x / (1 + |x|). Like sigmoid and tanh, softsign is a saturating function — for very large or very small x, the output approaches ±1 and the gradient approaches 0. In deep networks, as signals propagate backward, more neurons enter saturation, the chain-rule multiplication of near-zero gradients → vanishing gradient → weights can't update.

Sigmoid (0,1) Yes Yes
Tanh (-1,1) Yes Yes
Softsign (-1,1) Yes (slower) Yes (in deep nets)
ReLU [0,+∞) No (positive) No (but dying ReLU)
Leaky ReLU (-∞,+∞) No No

Saturation area: Region where the function's derivative is near zero. Softsign saturates more slowly than sigmoid, but still does in deep networks.
Softsign = saturating function = vanishing gradient in deep networks = TRUE. Any bounded activation function (sigmoid, tanh, softsign) can cause vanishing gradient. Only non-saturating functions like ReLU avoid this.

Q6 True / False Medium

If the hyperparameter search space is large, random search is better than grid search.

  • ✅ True
  • False
✅ Correct — 16 Points
Why TRUE is correct
Grid Search exhaustively tries every combination. With a large search space, this becomes computationally impossible (curse of dimensionality). For 10 parameters each with 10 values = 10^10 combinations!

Random Search samples random combinations — proven by Bergstra & Bengio (2012) to find equally good or better hyperparameters in less time when only a few hyperparameters actually matter. Random search explores the space more efficiently.
Hyperparameter Search Methods
Method How it Works Best For Downside
Grid Search Try all combinations Small search spaces Exponential cost
Random Search Sample random combos Large spaces, fewer important params May miss optimal
Bayesian Search Use past results to guide next Expensive evaluations Complex setup

Key hyperparameters (Q40): Batch size, learning rate, optimizer type (NOT loss value — that's a parameter)
Large search space → Random Search wins. Small search space → Grid Search is fine. Random search samples from the parameter distribution — each trial is independent. Grid search has exponential complexity. Remember Q7: in random search, each setting is sampled from possible values.

Q10 True / False Medium

Batch normalization is a technique used in deep learning to optimize training. It reduces the dependence on initial weights and learning rates, resulting in improved model performance.

  • ✅ True
  • False
✅ Correct — 16 Points
Why TRUE is correct
Batch Normalization (BN) normalizes the inputs of each layer to have zero mean and unit variance within each mini-batch. This: (1) reduces internal covariate shift, (2) allows higher learning rates, (3) reduces sensitivity to initial weights, (4) acts as a regularizer (sometimes replacing dropout). Result: faster training, more stable convergence, better performance.
Batch Normalization — Complete Guide
How BN works:
1. For each mini-batch: compute mean (μ) and variance (σ²)
2. Normalize: x̂ = (x - μ) / √(σ² + ε)
3. Scale and shift: y = γ·x̂ + β (learnable parameters)

Benefits:
  • Faster training (allows larger learning rates)
  • Less sensitive to weight initialization
  • Regularization effect (reduces overfitting)
  • Enables deeper networks
Note from Q47: Batch normalization is NOT a data augmentation method — it's a training technique!
Batch Normalization = normalize layer inputs per mini-batch. Benefits: faster training, less weight-sensitivity, regularization. NOT a data augmentation technique (Q47 trap). Applied between layers during training.

Cross-entropy is used for classification tasks. For regression, the standard loss functions are:

Cross-entropy measures probability distribution differences — only meaningful when output is a probability (classification).

Regression → MSE/MAE. Classification → Cross-Entropy. Cross-entropy for regression = FALSE. MSE = Mean Squared Error. Softmax + Cross-Entropy = standard multi-class setup (Q48 confirms this).

Q16 Single Choice Medium

Without considering any regularization terms, the support vectors of a support vector machine (SVM) are composed of ( ).

  • ❌ A. Points on the separating hyperplane (My Answer)
  • B. The points farthest from the separating hyperplane
  • ✅ C. The points closest to the separating hyperplane
  • D. Points of a certain type
❌ Incorrect — Correct Answer: C
Why C is correct (you answered A — WRONG)
Support vectors are the data points from each class that are closest to the decision boundary (separating hyperplane). These are the critical points that define the margin. The SVM algorithm maximizes the margin between the two nearest points of each class.

Support Vector Machines — Complete Guide

  • Support Vectors: Points CLOSEST to the hyperplane from each class
  • Margin: Distance between support vectors of different classes (SVM maximizes this)
  • Kernel Trick: Maps data to higher dimensions for non-linear classification
  • Hard Margin SVM: No regularization, perfect separation (Q16 context)
  • Soft Margin SVM: Allows some misclassification (regularization C)

From Q28: SVMs can do non-linear classification via kernel trick — NOT only linear!
⚠️ YOU GOT THIS WRONG. Support vectors = points CLOSEST to the hyperplane (margin boundary). NOT points on the hyperplane. SVM maximizes the margin between support vectors of different classes. Kernel trick enables non-linear SVM.

In k-fold cross-validation, the existing data is divided into ____ groups.

  • ✅ k
✅ Correct — 16 Points
K-Fold Cross-Validation
Data is split into k equal groups (folds). In each iteration, k-1 folds are used for training and 1 fold for validation. This repeats k times, with each fold used as validation once. Final metric = average of k evaluations. Common values: k=5 or k=10.

⚠️ My Weak Areas

1. Activation Functions & Vanishing Gradient (3 wrong: Q3, Q5, Q20)

You consistently confuse which functions solve vs cause vanishing gradient. Remember: ONLY ReLU solves it. Sigmoid, tanh, softsign all suffer it. Tanh is BETTER than sigmoid but does NOT solve the problem.

2. Distributed Training Parallelism (2 wrong: Q12, Q13)

You confused data parallelism (aggregates gradients, not loss) and pipeline parallelism (splits model stages, not layer parameters). Tensor parallelism splits weight matrices. These are highly specific distinctions.

3. Parameters vs Hyperparameters (2 wrong: Q17, Q46)

Gradient descent updates PARAMETERS (weights/biases). Hyperparameters are manually set by humans. You selected "hyperparameters" as what gradient descent updates — classic trap!

4. Large Model Evaluation & Fine-Tuning (2 wrong: Q55, Q14)

Evaluation measures, it does not improve or align. Fine-tuning doesn't change model structure. You selected too many options in Q55 and incorrectly identified fine-tuning definition in Q14.

5. Attention Mechanism (Q38) & Transformer (Q37)

Attention SCORE uses Query × Key (not Value). Value is used after the score. Transformer captures dependencies via self-attention + positional encoding (not FFN or residual layers).

6. Foundation Models = Weak AI (Q9)

Foundation models are NOT General AI. They're powerful but still Narrow/Weak AI. AGI does not exist. This is a critical conceptual distinction.

7. SVM Support Vectors (Q16)

Support vectors = points CLOSEST to the hyperplane (margin boundary), not ON the hyperplane. Points on the hyperplane have no discriminative value.
